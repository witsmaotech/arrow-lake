# Arrow Lake v1.6.0 规划方案

> 状态: DRAFT | 日期: 2026-06-05 | 前序版本: v1.5.3
>
> 注: 架构修复（Tag API 4 methods、KG 管理 API 2 methods、server 废弃警告）
> 已在 v1.5.3 后完成，不纳入 v1.6.0。

## 一、版本定位

**主题: 搜索智能升级 + 实时能力补位**

v1.5.x 完成了安全加固、Gravitino 治理、平台系统化、公开 API 补齐。v1.6.0 聚焦：
1. **搜索能力升级** — 补齐业界主流的高级检索特性
2. **引入实时数据通道** — 从纯批处理走向批流一体

## 二、搜索智能升级

### 3.1 SPLADE 学习稀疏表示（P1）

**现状**: FTS 仅 BM25 (Tantivy)
**业界**: Milvus 2.5、Weaviate 已内置 SPLADE/uniCOIL
**方案**: 在 `embed/` 新增 `SparseEncoder` 接口

```
用户查询 → SPLADE 编码 → 稀疏向量 → 与 BM25 分数融合
```

**收益**: 中文/多语言搜索质量显著提升，兼具可解释性

### 3.2 Corrective RAG / CRAG（P1）

**现状**: RAG 有 HyDE、MultiQuery、rerank，但无检索质量自评
**业界**: CRAG 已成 2025 生产标配
**方案**: 在 `rag/` 新增 `RetrievalEvaluator`

```
用户查询 → 检索 → 质量评估(置信度阈值) →
  高置信: 直接生成
  低置信: 触发查询改写 / 回退到 FTS / 放弃回答
```

### 3.3 语义缓存（P2）

**现状**: Redis 用于分布式协调，无查询缓存
**业界**: GPTCache、Semantic Cache 成为 RAG 降本标配
**方案**: 在 `rag/` 新增 `SemanticCache`，基于向量相似度命中

```python
# API 示例
cache = SemanticCache(similarity_threshold=0.95, ttl=3600)
response = cache.get_or_compute(query, lambda: rag_pipeline.query(query))
```

**收益**: 重复/相似查询 LLM 调用减少 30-50%

## 四、实时能力补位

### 4.1 流式向量摄入（P1）

**现状**: 数据摄入为纯批处理（Metaflow flow）
**业界**: Qdrant、Milvus 已支持 streaming ingestion
**方案**: 新增 `StreamingIngestor` 接口

```python
# 核心接口
class StreamingIngestor:
    async def ingest_stream(
        self, source, dataset_name: str, ...
    ) -> AsyncIterator[IngestBatch]:
        """从数据源持续摄入，按 batch_size 提交"""

# 使用方式
async for batch in ingestor.ingest_stream(kafka_source, "products"):
    lake.append_dataset("products", batch.table)
    if batch.count % 1000 == 0:
        lake.rebuild_vector_index("products", ...)
```

**支持的 source**: Kafka topic、文件目录 watch、HTTP webhook

### 4.2 嵌入模型版本管理（P2）

**现状**: 硬编码 Qwen3-Embedding-0.6B，无版本/A/B 测试
**业界**: 模型注册中心 (MLflow, Gravitino Model) 已成标配
**方案**: 利用已有 Gravitino Model Catalog 扩展

```python
config = ArrowLakeConfig(
    embedding=EmbeddingConfig(
        models={
            "default": "Qwen3-Embedding-0.6B",
            "multilingual": "BGE-M3",
        },
        active_model="default",  # 支持热切换
    ),
)
```

## 五、不纳入 v1.6.0 的特性（延后评估）

| 特性 | 原因 | 建议 |
|------|------|------|
| ColBERT Late Interaction | 计算成本高，需 GPU 推理基础设施 | v1.7.0 |
| OpenLineage 标准 | 现有 lineage 满足需求，迁移 ROI 不明确 | v1.7.0 |
| CDC 集成 (Debezium) | 依赖外部基础设施，与部署模式不匹配 | v2.0 |
| Data Contract Testing | 需要产品设计，非纯技术特性 | v2.0 |
| Auto-Schema Detection | LLM 调用成本高，准确性待验证 | v1.7.0 |
| Lambda 架构 (流批一体) | 架构变更过大 | v2.0 |

## 七、验收标准

| 维度 | 标准 |
|------|------|
| API 成熟度 | examples/ 零 `_get_storage()` / `_get_kg_client()` 直接调用 |
| 搜索质量 | SPLADE + BM25 混合 NDCG@10 提升 >= 10% (中文测试集) |
| RAG 可靠性 | CRAG 低置信度拒绝率 <= 5%，幻觉率降低 >= 15% |
| 缓存效率 | 语义缓存命中率 >= 30% (重复查询场景) |
| 实时性 | 流式摄入端到端延迟 < 5s (Kafka -> 可搜索) |
| 测试覆盖 | 新增代码覆盖率 >= 80%，全局 >= 78% |
| 文档 | 所有新 API 有 cookbook + REST API 文档 |

## 八、风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| SPLADE 中文效果不佳 | 中 | 先用 BGE-M3 sparse 验证，备选 BM25 增强 |
| CRAG 阈值难调 | 中 | 可配置阈值，默认保守策略 |
| 流式摄入与批处理冲突 | 低 | 共享 append_dataset() 路径 |
| Tag API 迁移遗漏 | 低 | CI 门禁检查 `_get_storage()` 调用 |
