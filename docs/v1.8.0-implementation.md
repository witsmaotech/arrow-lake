## 1. 第一批 🟥(高价值低成本)—— 详细实现

### #13 Daft AI 函数替代自建嵌入调度  ✅ 已实施 (v1.8.0)

**实施结果**（2026-06-26）：`DaftBatchEncoder` 实际**已存在**于 `arrow_lake/embed/daft_encoder.py`（非初版文档写的 `embedding/` 目录），已接入主 ingest dispatch。本项聚焦**端到端补全 + PoC 验证**。

**实际改动**:
- `arrow_lake/embed/encoder.py` — `LocalEmbeddingEncoder` 加 `encode_to_vectors`（对称 Daft，返回 `(ndarray, dim)` 向量矩阵，null 行零填充）
- `arrow_lake/_lake_ingest.py` — 修 `embed_and_add` LOCAL 分支 bug（原 `result.embeddings` AttributeError，`EmbeddingResult` 无此字段）+ DAFT 分支传 `expected_dim`
- `arrow_lake/api/routers/embedding.py` — `/embed/text` 端点补 DAFT 分支
- `arrow_lake/embed/daft_encoder.py` — 加 `expected_dim` 维度校验 + L2 归一化 + `encode(list[str])` 满足 `EmbeddingEncoderProtocol`
- `examples/benchmark_embed_daft_vs_local.py` — 新建 PoC benchmark

**PoC 实测结果**（`Qwen/Qwen3-Embedding-0.6B`，n=50）:
- **cosine(mean) = 1.0000**（Daft `embed_text(provider="transformers")` vs Local `SentenceTransformer`，同模型同输入，向量完全等价）
- dim ✓ 1024/1024，**speedup 1.14x**
- 代码足迹：Daft 调度 ~30 行 vs Local 手写 ~150 行（删减 ~120 行 lazy-load/GPU/batch/normalize/retry）
- ✓ **roadmap #13 假设验证通过**：Daft 内置 AI 函数可完全替代自建嵌入调度，语义等价 + 性能略优 + 代码大幅删减

**范围修正（vs 初版）**:
1. ❌ **排除 `he_extractor.py`**：初版「LLM 抽取改 Daft prompt」是**误判** —— he_extractor 是 v1.7.0 hyper-extract Template（领域模板 + AutoGraph 结构化抽取），非「LLM 调度」。Daft `prompt()` 是 DataFrame 列表达式，无法注入 Template 的 `llm_client`；强行替换会推翻 v1.7.0。
2. provider 用 `transformers`（非 ollama —— Daft 0.7.8 `PROVIDERS` 不含 ollama；transformers 对齐本地 SentenceTransformer）。

**Daft prompt KG 抽取**（拆为独立后续项）: Daft `prompt(return_format=Pydantic)` 的批量调度 + 强制结构化价值，改为新建 `DaftExtractor` 作 `extractor_backend="daft"` 第三选项，与 hyper-extract 并列对比。需自建领域 prompt 模板，不在 #13 范围。

**风险已解除**: Daft 0.7.8 `embed_text`/`prompt`/`classify_*` 全可用；`transformers` provider 端到端验证可跑（PoC cosine=1.0）。
**回滚**: Daft 作可选 backend（`config.embedding.backend="local"` 默认），bug 修复（LOCAL 分支）即使回滚 PoC 也应保留。

### #5 Reranker 接入(混合搜索精排)

**现状**: `HybridSearchConfig` 有 RAG reranker 配置,未接 lancedb reranker
**目标**: 混合搜索 RRF 粗排后接 cross-encoder 精排(Cohere/Voyage/Jina/AnswerDotAI)

**改动文件**:
- `arrow_lake/config/search.py` —— `HybridSearchConfig` 加 `reranker_type` / `reranker_model`
- `arrow_lake/query/hybrid.py` —— search 后加 `reranker.rerank(results)` step
- `arrow_lake/_lake_search.py` —— facade 暴露 rerank 选项

**实施步骤**:
1. config 加 reranker 字段(type/model/provider)
2. `hybrid.py` 加 reranker step(可选,none=跳过)
3. 测试:mock reranker(验证调用 + 重排)
4. 端到端:`20_rag_qa_system` 验证精度(对比有/无 reranker)

**测试**: `tests/unit/query/test_hybrid_rerank.py`
**风险**: reranker 依赖(Cohere/Jina 需 API key;本地 cross-encoder 需模型下载)
**回滚**: `reranker_type=none` 默认(向后兼容)
