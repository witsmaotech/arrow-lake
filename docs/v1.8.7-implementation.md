## 1. 第一批 🟥 — Docling 文档解析(替代 kreuzberg)

### 基线 #20aeda2 — 替代 kreuzberg:Python SDK 库内嵌

**背景**: kreuzberg 容器镜像层依赖重、中文 OCR 弱、表格还原差;镜像里**根本没有 kreuzberg**,导致 PDF 解析走 `prepare_pdf` 降级。

**改动文件**:
- `arrow_lake/ingest/document.py` — Docling `DocumentConverter` 配置入口
- `arrow_lake/ingest/ingestor.py` — 解析编排(分发到 Docling backend)
- `arrow_lake/ingest/_ingest_files.py` — 多格式分发
- `arrow_lake/config/document.py` — Docling 配置项 enum

**实施要点**:
- Docling 作 Python SDK **库内嵌**(非独立 service),`DocumentConverter` 直接在 ingest 进程内调用
- 多 OCR 后端可切:RapidOCR(中文优) / EasyOCR(多语言) / Tesseract
- 统一输出 `DoclingDocument` → Markdown/JSON,与 RAG 分块衔接

**测试**: `tests/unit/ingest/test_docling_p2.py`(后扩展至 390 行)
**风险**: Docling 依赖链重(torch/transformers/PDF 后端);纯 CPU >200s/页
**回滚**: 保留 `prepare_pdf` 降级路径(Docling 失败时回退)

## 7. 范围修正 / 实施纠错(仿 v1.8.0-implementation 纠错段)

> 实施中发现的与初版设想不符之处,记录以防重蹈。

1. **Docling 镜像预取**(P0.2 回退): 初版设想 build 时预取模型入镜像 → 实际镜像膨胀 + build 网络不稳 → **回退为运行时 `HF_HOME` 持久卷**(`37733c2`)。
2. **apache-arrow CDN**: 初版用 CDN 加载 → 安全审查否决 → **方案 A 完全自托管,移除 stream**(`7a62f0d`)。
3. **`/console` mount 路径**: `parent.parent` 只回退两级不够 → `parents[2]`(`2c296a3`)。
4. **Console auth**: 单 header 不够(OLAP 要 API key + 用户态要 JWT)→ **BOTH 双 header**(`a9a50a8`)。
5. **dataset 名含 `-`**: DuckDB 当减号 → 默认双引号包裹(`7841f01`)。
6. **he_extractor 范围**(继承 v1.8.0 教训): he 是 hyper-extract Template,非「LLM 调度」;Docling/Daft 不混入 he 抽取链。
7. **HugeGraph auth**: 非可选 —— per-dataset KG 1.7+ 动态建图**强制开 auth**(`64e5366`)。
