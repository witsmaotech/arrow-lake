# v1.8.6 — 按 lake 路径分图隔离（per-dataset HugeGraph isolation）方案

> 状态：设计已 Review 通过，待实施
> 关联：`issue_hugegraph_hstore_init.md`（gremlin `hugegraph` 绑定修复）、v1.7.x PD 多图模式、`v1.7.0-hyper-extract-kg-extraction-plan.md`

---

## 1. 背景与目标

当前所有知识图谱数据写入**单个** HugeGraph 图（`hugegraph`）。每个 Lance dataset 的实体/关系/chunk 都落进同一个图，仅靠 `document_name` 属性标签区分来源。这导致：

- **无逻辑隔离**：不同 dataset 数据混存，互相污染。
- **管理困难**：删除一个 Lance dataset 不会清理它在图里的数据，残留累积。
- **稳定性耦合**：一个 dataset 的坏查询/脏数据可能拖慢整图（共享索引、共享后端分区）。
- **性能退化**：单图索引随数据量线性膨胀，全图扫描代价随 dataset 数增长。

**目标**：按 lake 路径（= Lance `dataset_name`，现有 `kg_build` 的单位）映射到**独立 HugeGraph 图**（`kg_{dataset}`），纯图内查询（不做跨 dataset 检索）。

---

## 2. 主要优化点

| # | 优化点 | 收益 |
|---|--------|------|
| 1 | **数据逻辑隔离** | 每 dataset 独立图，实体/关系/索引完全隔离，杜绝跨库污染 |
| 2 | **生命周期可管理** | 删 dataset = 删图（drop-on-delete），无残留；重建即全新图 |
| 3 | **生产稳定性** | 故障隔离：单 dataset 的脏数据/慢查询不波及其它图；PD 多图互不影响 |
| 4 | **查询性能** | 每图索引规模 = 单 dataset 量级，索引/扫描代价恒定，不随 dataset 数增长 |
| 5 | **运维清晰** | 图名即 dataset 名，可按图独立备份/导出/统计/限流 |
| 6 | **schema 独立** | 每图独立 schema 实例，未来按 dataset 定制 schema（如 doc_type 专属标签）零冲突 |

---

## 3. 设计基石（实测事实，2026-06-30 针对 live `hg-server` 验证）

这些实测约束决定架构走向：

1. **REST 路径天然按 URL 隔离**。写入（`POST /graphs/{name}/graph/vertices/batch`）和 8 个 REST traverser（`/graphs/{name}/traversers/*`）都把图名放在 URL，换图名即隔离。
2. **`ensure_graph` 已支持创建任意命名图**（`POST /graphspaces/DEFAULT/graphs/{name}`）。现场已有 4 个图：`hugegraph` + 3 个 `v17_*` 测试图，PD 多图模式活经验证。
3. **gremlin 只能解析启动时绑定的图全局**。动态创建的图**无法**被 gremlin 按名查询：`v17_pdf_e2e.traversal().V().count()` → `MissingPropertyException: No such property: v17_pdf_e2e`。`graphs["name"]`（TinkerPop Map）同样不可用（`No such property: graphs`）。仅 `hugegraph`（由 `entrypoint-hugegraph.sh` 显式绑定）可解析。
4. **REST 按属性查顶点成立**（替代 gremlin find_entity）：`GET /graphs/hugegraph/graph/vertices?label=entity&properties={"name":"Python"}` 实测返回顶点 `3:Python`。
5. **retriever 是缓存单例**（`_lake_kg.py` `_get_component("kg_retriever", ...)`），不能在构造器焊死 dataset_name。

**推论**：分图后 REST 路径自动隔离；gremlin 路径需特殊处理（动态图不可 gremlin 按名查）。

---

## 4. 核心架构：REST-first 分图

```
  dataset_A ──▶ graph kg_dataset_a ──┐
  dataset_B ──▶ graph kg_dataset_b ──┼─▶ HugeGraph PD (1.7)
  dataset_C ──▶ graph kg_dataset_c ──┘
                                     │
  legacy hugegraph ──────────────────┘  默认/绑定图：仅任意 gremlin kg_query 用

  build:     REST POST /graphs/kg_X/graph/vertices/batch      ✅
  retrieve:  REST GET  /graphs/kg_X/graph/vertices?properties  ✅ (find_entity 迁 REST)
  traverser: REST /graphs/kg_X/traversers/kneighbor            ✅
  kg_query:  gremlin —— 仅默认绑定图 hugegraph                 ⚠️ 任意 gremlin 受限
```

图名由 `dataset_name` **按操作派生**，不再是 config 里的单一固定值。所有结构化操作（build/retrieve/traverse/stats/schema）走 REST，按 per-dataset 图名隔离。任意 gremlin 仍作用于遗留绑定的 `hugegraph` 图。

## 5. Phase 1：分图核心（命名 + client + facade + builder）

### 5.1 图名派生 `arrow_lake/knowledge_graph/_naming.py`（新增）

```python
import re
_MAX = 48  # HugeGraph 图名长度安全上限
_RE = re.compile(r"[^a-z0-9_]")

def graph_name_for(dataset_name: str) -> str:
    """Lance dataset 名 → 稳定、HugeGraph 安全的图名。

    规则：小写 → 非 [a-z0-9_] 转 _ → 去首尾 _ → 截断 → 前缀 kg_。幂等。
    """
    sanitized = _RE.sub("_", dataset_name.lower()).strip("_")[: _MAX - 3] or "default"
    return f"kg_{sanitized}"
```

冲突策略：图名 dataset 作用域；若两个 dataset sanitize 后重名，会共享同一图（罕见，build 时 WARN 日志）。

### 5.2 client 重构 `arrow_lake/knowledge_graph/client.py`

- 凡按 URL 定位图的方法加可选 `graph_name: str | None = None`，缺省回退 `self._config.graph_name`（向后兼容）：`add_vertices` / `add_edges` / `get_vertex` / `get_schema` / `ensure_schema` / `get_stats` / `clear` 以及 `_TraverserMixin` 全部 8 个 traverser。统一通过 `name = graph_name or self._config.graph_name` + `_graph_base_for(name) -> f"/graphs/{name}"`。
- `ensure_schema(graph_name=...)` 必须把 `graph_name` 透传给它内部调用的 `ensure_graph()`，保证图与 schema 落在同一 per-dataset 图。
- 新增 `find_vertices_by_property(label, properties, graph_name)`：`GET /graphs/{name}/graph/vertices?label={label}&properties={json}`，返回 `vertices` 列表（替代 gremlin find_entity）。
- 新增 `drop_graph(name)`：`DELETE /graphspaces/DEFAULT/graphs/{name}`（HugeGraph 1.7 PD）—— 真正删除图，区别于 `clear()`（只清数据留图壳）。
- `gremlin(query)` **不变**，始终 POST `/gremlin`，解析启动时绑定全局（默认 `hugegraph`）。

### 5.3 facade 透传 `arrow_lake/_lake_kg.py`

- `_dataset_graph(dataset_name) -> str` = `graph_name_for(dataset_name)`。
- `kg_build(dataset_name)`：build 前先 `client.ensure_graph(g)` + `client.ensure_schema(schema, graph_name=g)`，再给 builder 的每次 `add_vertices`/`add_edges` 传 `graph_name=g`。
- 图作用域查询方法加**必选** `dataset_name` 参数并透传派生图名：`kg_get_neighbors` / `kg_stats` / 8 个 `kg_*_path|rays|rings|crosspoints|customized_paths` / `kg_export_graph` / `kg_import_graph`。遍历必须知道在哪个图跑，故 `dataset_name` 必选；所有调用方（`api/routers/knowledge_graph.py`、`cli/kg.py`）同步改。`kg_query(gremlin)` 是唯一例外（默认图）。
- 新增 `kg_drop_graph(dataset_name)`：幂等 `client.drop_graph(g)`，try/except 包裹（图已不在不报错）。

### 5.4 builder 注入 `arrow_lake/knowledge_graph/builder.py`

`build(dataset_name, table)` 把 `graph_name=graph_name_for(dataset_name)` 透传进每次 `client.add_vertices` / `add_edges` 及 ensure_graph/ensure_schema 前置。抽取逻辑不变。

## 6. Phase 2：检索适配 + 删除 hook + 迁移

### 6.1 retriever 迁移 `arrow_lake/knowledge_graph/retriever.py`

- 把 gremlin `find_entity` 步骤替换为 `client.find_vertices_by_property(label, {"name": entity}, graph_name=g)`。后续 `traverser_kneighbor` 已接收 `graph_name`（§5.2）。
- **retriever 是缓存单例**，`dataset_name`/`graph_name` 必须传给其**查询方法**，不能焊进构造器（否则一个单例只能服务一个 dataset）。构造器保持 graph 无关；每次查询派生 `graph_name_for(dataset_name)` 并透传。

### 6.2 dataset 删除 hook（drop-on-delete）

调用点：`arrow_lake/_lake_admin.py:69 Lake.delete_dataset(name)` → `:76 self._get_storage().delete_dataset(name)`。

在 `delete_dataset` 里（storage 删除前后均可，建议之前）加 best-effort：
```python
try:
    asyncio.get_event_loop().run_until_complete(self.kg_drop_graph(name))  # 或同步包装
except Exception:
    logger.warning("drop graph for dataset %s failed (best-effort)", name)
```
删 Lance dataset 同步 drop 对应 `kg_{ds}` 图。

### 6.3 `queries.py` 标注遗留

保留 `GremlinQueries`（默认图任意 gremlin 仍用）；`find_entity` docstring 标注 deprecated，指向 `find_vertices_by_property`。不删除。

### 6.4 迁移脚本 `scripts/migrate-kg-per-dataset.py`（新增，一次性）

遗留 `hugegraph` 图（2079 顶点，多 dataset 混存）保留为默认图。脚本枚举 Lance datasets，对每个跑 `kg_build(ds)` 重建到 `kg_{ds}`。Lance 是 source of truth，不读遗留图。用户按需执行，不自动迁移。

## 9. 验证方法

**功能**：
- `kg_build("ds_a")` / `kg_build("ds_b")` → 创建两个独立图 `kg_ds_a` / `kg_ds_b`，各有独立 schema + 数据。
- **隔离性**：ds_a 的顶点经 `kg_get_neighbors("ds_a", ...)` 可达，经 `kg_get_neighbors("ds_b", ...)` 不可达。
- **GraphRAG**：retriever 在 per-dataset 图上经 REST `find_vertices_by_property` + `traverser_kneighbor` 正常工作（不在动态图上跑 gremlin）。
- **任意 gremlin 无回归**：`kg_query("hugegraph.traversal().V().count()")` 仍 200。
- **drop-on-delete**：删 ds_a → `kg_ds_a` 消失，`kg_ds_b` 不受影响。

**错误路径**：
- 查未构建 dataset → REST traverser 404 → catch 返回空集（视为空图，不报错）。
- `drop_graph` 图已不在 → 吞异常，成功返回。
- sanitize 重名 → build 时 WARN。

**测试**：
- 单元：`graph_name_for` 幂等/中文/特殊字符/长度/空输入；`find_vertices_by_property`（mock httpx）；`graph_name` override 传到 `_graph_base_for`。
- 集成：两图隔离性 + drop 后另一图完好。
- spike：扩展 `tests/spike/test_hugegraph_connectivity.py` 加多图隔离用例。
- 回归：现有 399 个 kg 单元测试（按新签名调整后）全绿。覆盖率 ≥ 80%。

## 10. 风险与回退

| 风险 | 缓解 |
|------|------|
| API 变更面大（图作用域方法加 `dataset_name`） | `graph_name`/`dataset_name` 在 client 层可选有默认；facade 层必选但同步改全部调用方 |
| 任意 gremlin 不能查 per-dataset 数据 | 文档明确；用结构化 traverser 或遗留默认图。可接受（用户已选纯隔离） |
| 图数量膨胀（多 dataset → 多图） | PD 天然支持；监控 PD/store 内存；drop 无用 dataset 回收 |
| `drop_graph` 端点语义未在 1.7 实测 | 实施首步实测 `DELETE /graphspaces/DEFAULT/graphs/{name}`，失败则退回 `clear()` + 记录 |
| retriever 单例与 per-dataset 冲突 | 钉死查询方法传参（§6.1），不动构造器 |

**回退**：分图是增量能力。保留遗留 `hugegraph` 图与 `kg_query` 默认图路径，任何 per-dataset 路径异常都可回退到单图模式（config `graph_name=hugegraph` + 不调用新 facade 路径）。
