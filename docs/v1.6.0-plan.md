## 一、版本定位

**主题: 修好已知问题，让现有能力更稳更健壮**

v1.5.x 完成了安全加固、Gravitino 治理、平台系统化、公开 API 补齐。
v1.6.0 的核心原则：**不追新特性，修好已知缺陷，夯实基础。**

| 维度 | 目标 |
|------|------|
| Bug 修复 | RRF 公式错误、配置端口冲突、会话池泄漏 |
| 异常与健壮性 | 补齐异常层次，让错误可追踪可恢复 |
| 资源控制 | 查询超时、并发限制、背压 —— 生产环境必需 |
| 类型安全 | Protocol 接口落地，消除 `Any` 类型泄漏 |
| 安全加固 | Prompt 注入、SQL 注入防护补强 |
| 代码质量 | 清理已知小债务，中间件顺序显式化 |
| **E2E 摄取** | 嵌入批处理容错、Lance 写入补偿、Lock 超时 |
| **E2E 搜索/RAG** | 空检索保护、Hybrid 降级、SSE 错误传播、超时级联 |
| **E2E 基础设施** | 熔断器集成外部服务、Correlation ID 顺序、Error mapping 补齐 |
| 测试补齐 | query/ 模块测试薄弱，E2E 流程测试缺失 |

## Phase 1: Bug 修复 + 安全加固（1 周）

> 必须立即修复的正确性问题和安全漏洞。

### 1.1 RRF 公式可读性优化

**问题**: Hybrid search RRF 公式 `1.0 / (rank + 1 + k)` (rank 从 0) 在数学上**等价于**标准 RRF `1.0 / (rank + k)` (rank 从 1)，不是 bug。但当前写法不够直观，每次阅读都需要心算验证偏移量。

**方案**: 重构为论文标准写法，提升可读性

```python
# hybrid.py — 当前（数学正确但需心算）
for rank, doc_id in enumerate(ids):
    rrf_scores[str(doc_id)] += 1.0 / (rank + 1 + k)

# hybrid.py — 修正后（与论文 Cormack et al., 2009 一致）
for rank, doc_id in enumerate(ids, start=1):
    rrf_scores[str(doc_id)] += 1.0 / (rank + k)
```

**注意**: 这是纯可读性重构，排序结果数学上完全相同。不是 bug 修复。

**同步**: 添加 RRF 排序稳定性保证（等分文档稳定排序）

**工作量**: 0.5d | **影响**: `query/hybrid.py`

### 1.2 配置冲突修复

**问题**: 多个配置验证缺口和端口冲突

**方案**:
1. **端口冲突**: `metrics_port` 默认值改为 `8001`
2. **JWT 跨字段验证**: 新增 `@model_validator` 确保 auth_mode=JWT 时密钥完整
3. **超时验证统一**: 所有 `*_timeout_seconds` 字段补 `ge=1` 约束
4. **RAGConfig.default_top_k**: 补 `@field_validator` 与 search.py 一致

```python
# config/api.py — 端口修复
metrics_port: int = 8001  # 避免与 API server 8000 冲突

# config/api.py — JWT 跨字段验证
@model_validator(mode="after")
def validate_jwt_credentials(self) -> ApiConfig:
    if self.auth_mode == AuthMode.JWT:
        has_secret = bool(self.jwt_secret_key)
        has_pair = bool(self.jwt_public_key and self.jwt_private_key)
        if not (has_secret or has_pair):

    return self
```

### 1.5 API 安全加固

**问题**: Rate limit 注释与代码不一致（注释说"默认禁用"但代码 `enabled=True`）、可被 X-Forwarded-For 绕过、chunked encoding 绕过大小限制

**方案**:
1. 修正注释与代码一致，确认 Rate limit 默认启用（当前代码已正确）
2. 修复 X-Forwarded-For 可信代理 IP 提取：**从右往左跳过可信代理**，取第一个非可信 IP
3. Chunked 请求也执行大小限制（读取 Content-Length 为 0 时设上限）

```python
# rate_limit.py — 可信代理感知（修正后）
def _get_client_ip(request: Request, trusted_proxies: set[str]) -> str:
    xff = request.headers.get("x-forwarded-for", "")
    if xff and trusted_proxies:
        ips = [ip.strip() for ip in xff.split(",")]
        # 从右往左跳过可信代理，取最右边的非可信 IP
        while ips and ips[-1] in trusted_proxies:
            ips.pop()
        if ips:
            return ips[-1]
    return request.client.host
```

**工作量**: 1d | **影响**: `api/rate_limit.py`, `api/middleware.py`, `config/api.py`

```python
def encode_batch(self, texts: list[str], shard_size: int = 100) -> np.ndarray:
    results = []
    for i in range(0, len(texts), shard_size):
        shard = texts[i : i + shard_size]
```

| **E2E: RBAC 降级集中化** | 需要设计 fallback 策略框架 |

## 五、验收标准

| 维度 | 标准 |
|------|------|
| **可读性** | RRF 改为论文标准写法 `enumerate(start=1)` + `1/(rank+k)`，排序结果数学不变 |
