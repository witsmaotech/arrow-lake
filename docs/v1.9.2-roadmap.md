## 2. 缺口分析:前端 vs 后端(最大短板)

**6 个后端能力域,界面零体现**:

| 能力 | 后端 | 价值 | 融合 | 难度 |
|---|---|---|---|---|
| **系统运维** | system.py(/health/version/duckdb-pool/gravitino/lance-rest/metrics) | 🔴 高(运维必备) | 新 system.html | 低 |
| **审计日志** | audit.py(_audit_trail:谁/何时/操作/对象,HMAC 签名) | 🔴 高(合规) | 新 audit.html(admin 组) | 中 |
| **数据血缘** | lineage.py(_lineage_events:ingest→索引→KG→RAG) | 🟠 中(治理) | dataset-detail 血缘 Tab | 中 |
| **备份恢复** | backup.py(快照/restore/manifest) | 🟠 中(数据安全) | dataset-detail 版本 Tab | 中 |
| **元数据治理** | gravitino.py(metalake/catalog/schema/table) | 🟡 中(治理) | 新 governance.html | 高 |
| **维护清理** | maintenance.py | 🟡 低 | system 子 Tab | 低 |

→ **console 从"数据智能 + 管理"升级到"含运维/合规/治理的完整数据平台"的关键缺口**。

## 4. 实施批次(优先级路线)

### 批次 1:运维 + 合规(最高价值,低-中难度)🟥
- **system.html**:接 `/health` + `/system/version` + duckdb-pool/gravitino/lance-rest 状态 + Prometheus metrics 摘要 → 运维监控面板(健康灯/版本/依赖/配置)
- **audit.html**:接 `/audit`(_audit_trail:record/query/export)→ 审计事件列表(user/action/dataset/时间 过滤 + HMAC 校验指示)+ 导出
- NAV 加「运维」「合规」组
- **价值**:运维一眼看全 + 安全合规可追溯(v1.9.1 安全加固配套)

### 批次 2:数据治理(中价值,中难度)🟧
- **dataset-detail 血缘 Tab**:接 `/lineage`(_lineage_events:dataset → 下游 KG/RAG/索引)→ 血缘表/图
- **dataset-detail 版本 Tab**:接 `/backup` + Lance 版本 → 快照 timeline + restore
- **governance.html**:接 `/gravitino`(metalake/catalog/schema/table 浏览)→ 元数据治理(后置,Gravitino 复杂)

### 批次 3:质量深化(清债,中难度)🟨
- **测试隔离治理**:conftest 全局清理 fixture(治全量 106 不稳定)
- **KG 模板收紧**:concept_graph 固定 type 枚举 + 必填 description(提质量)
- **he build 0 实体**:重置 HG 集群拿干净信号 / 修提交环节(memory)
- **审计日志全覆盖**:structlog security event 补齐(登录/角色/token 全)

### 批次 4:多模态 + 导出深化(中价值)🟦
- **图像库检索专区**:search 加"图像数据集"入口(image_embedding 向量检索 UI)
- **全局导出**:export.py 统一到各页"导出"按钮(CSV/Parquet)
- **以图搜图 demo**:批量摄入图片 ≥256 行,IVF_PQ 建索引,端到端

### 批次 5:security/部署加固(收尾)🟪
- **rate_limit → Redis**:per-(username,ip) lockout 迁 Redis(多 worker)
- **docling GPU 验收**:gpu-full 镜像 + RTX3090 测速(552 页 PDF)
- **dashboard.html 清理**:残留页入口挪 index(data-prep 卡片归位)
