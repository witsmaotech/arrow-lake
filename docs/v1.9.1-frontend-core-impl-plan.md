# Arrow Lake 前端核心界面实施规划 · v1.9.1

> **版本**:v1.9.1(前端核心界面) · **日期**:2026-07-17 · **状态**:规划中
> **对齐后端**:v1.9.0(libSQL 控制面:RBAC/身份/personal_token/任务历史/用户态/血缘,已部署验证)
> **设计蓝本**:`docs/frontend-prototype/`(高保真静态原型 · Mission Control 设计语言)
> **本文定位**:把原型从"高保真静态演示"升级为"端到端真跑通的核心界面"的实施规划。只做规划,不含代码实现。

---

## 摘要

现有原型视觉与信息架构成熟,但有**三层结构性短板**:数据层完全缺失(全站 0 个 `fetch`,每页是硬编码静态截图)、交互深度为零(无读写、无异步状态、无跨页上下文)、页面模板感(同套 panel+kpi+feed 堆叠)。v1.9.1 以原型为设计蓝本,引入轻量数据层(`api/store/task/ui` 四件套),把**两条轨道**的核心页面接入真实 `/api/v1` **端到端真跑通**:① 数据智能轨(数据集→摄入→索引→检索→RAG);② 管理治理轨(用户/角色 RBAC/任务跟踪)。技术栈保留原生 JS + ES 模块(零构建、复用现有设计系统),以"批0 地基先行 + 两轨并行"分批交付,每批端到端可演示、可验证。

## 1. 目标与定位

### 1.1 目标

把 `docs/frontend-prototype/` 从**静态原型**升级为**核心界面真正可用**的控制台:

- **真跑通**:核心页接真实 `/api/v1`,读真实数据、发真实写操作、跟踪真实异步任务状态。
- **端到端**:数据智能主链路(摄入→索引→检索→RAG)页间状态流转,不是孤立页。
- **基础管理面可用**:用户/角色/RBAC/任务跟踪真接 v1.9.0 控制面 API。
- **保留原型优势**:Mission Control 设计语言、双击/起 server 即开、零构建、易演示。

### 1.2 非目标(v1.9.1 不做)

- 不重写为 React/Vue 框架项目(留待产品前端正式立项)。
- 不做审计 `audit` / 治理 `governance` / 备份 `backup` / 系统 `system` 的真跑通(保持现有 mock 演示,后续版本接)。
- 不做生产化安全硬化(DOMPurify/CSP/真实鉴权流程)——v1.9.1 仍是本地可信环境原型,仅留接口与说明。

### 1.3 成功标准

- 批0 完成后:在 `tasks.html` 看到真实任务列表与状态流转(PENDING→RUNNING→COMPLETED),DLQ 可重试。
- 全部批次完成后:一条真实数据链路可演示——选 `jd_ddd` 数据集 → 摄入新文档(任务轮询到完成)→ 建索引 → 检索真实命中 → RAG 真实回答+引用;并在 `admin.html` 创建用户/分配角色/看 ACL 生效。
- 像素验证 + 端到端真数据验收全部通过(§9)。

## 4. 技术架构与技术选型

### 4.1 选型总原则(约束所有后续决策)

| 原则 | 含义 | 动因 |
|---|---|---|
| **零外部运行时依赖** | 除 Google Fonts(已有)外,不引入任何 npm 运行时库 | 保住"起 server 即开、易分享演示、无供应链/版本风险"的原型核心优势 |
| **零构建** | 源码即运行,浏览器原生加载 ES 模块 | 砍掉 npm/打包/编译链;改完刷新即见 |
| **复用优先** | `tokens.css`/`app.css`/`layout.js` 不动,新模块挂在其上 | 现有设计系统成熟,不重造 |
| **够用即止(YAGNI)** | 不为"将来可能"引入抽象或库 | 原型 scope,9 页真跑通 |
| **可离线/可演示** | http server 5180 即跑;后端可达接真 API,不可达降级 | 演示场景多样 |

### 4.2 运行模型:无构建 + ES 模块 + 多页架构

- 浏览器原生 `<script type="module">` + `import/export`,`http.server 5180` 直加载,无打包/编译。
- **否决 Vite/打包链**:违反零构建原则;其 dev proxy 解 CORS 的便利不抵 npm 工具链复杂度(后端 CORS 白名单加一行 `localhost` 即等价解)。
- **否决 SPA 路由**:保持多页架构(每页独立 HTML,利于渐进改造、直链、孤立排查);跨页靠 URL `?ds=` + localStorage。

### 4.3 语言:JavaScript(非 TypeScript)

- 选 JS:TS 需编译步骤,与零构建冲突;原型 scope 下类型收益 < 工具链成本。
- 数据层契约靠 JSDoc 注释 + §5 接口定义约束。
- 迁移框架时(§4.7)一并引入 TS。

### 4.4 技术选型矩阵(逐维度:选定 / 否决 / 理由)

| 维度 | 选定 | 否决 | 理由 |
|---|---|---|---|
| 框架 | 无(原生 JS) | React/Vue/Svelte | 9 页在良好抽象下可控;引框架=原型→项目,scope 失控 |
| HTTP 客户端 | 原生 `fetch` + `AbortController` | axios/ofetch | 零依赖;超时/重试/错误分类自封装即够 |
| 状态管理 | 自写极简 pub/sub(~30 行) | valtio/nanostores | 只需"当前数据集 + 订阅",不值得引库 |
| 跨页上下文 | URL `?ds=` + `localStorage` | SPA router/state lib | 多页架构,URL param 是最简跨页载体 |
| 异步任务轮询 | 自写退避轮询器(`task.js`) | — | 业务特定(PENDING→DONE + DLQ),无现成库契合 |
| UI 反馈(toast/模态/空载错) | 自写,复用 `app.css` | 通知/弹窗库 | 设计系统一致性;零依赖 |
| 图表 | 复用 `layout.js` 手绘 SVG(sparkline/donut) | chart.js/d3/echarts | 已有且零依赖;新图按需手绘 |
| 图标 | 复用 `layout.js` `icon()` 内联 SVG | 图标库(lucide 等) | 已统一,零依赖 |
| 单元测试 | 不单独引;数据层由 E2E 端到端覆盖 | vitest/jest | 引单测需 npm 工具链(破零构建);E2E 已覆盖关键路径 |
| E2E 测试 | playwright + chromium-1217(已有) | — | 像素 + 端到端真数据验收 |
| 模块组织 | ES 模块(`import/export`) | IIFE/全局变量 | 维护性;http server 原生支持 |

**一句话**:整个 v1.9.1 前端 = 现有静态原型 + 4 个原生 JS ES 模块(`api/store/task/ui`)+ 后端一行 CORS 白名单。**零 npm 依赖、零构建步骤**。

### 4.5 模块拓扑

```
assets/
├── tokens.css / app.css / layout.js      # 现有(不动,渐进增强)
├── api.js      # 新:fetch 客户端 + 端点封装 + 鉴权/错误/重试
├── store.js    # 新:跨页上下文(当前数据集)+ 极简响应式
├── task.js     # 新:异步任务轮询器(共享单例)
└── ui.js       # 新:toast / loading / 空·载·错 / confirm
```

每核心页:`<script type="module">` 引入所需模块,页内调 `api.*` / `store.*` / `task.*` / `ui.*`。

### 4.6 与现有原型的关系:渐进增强,非重写

- `layout.js`/`tokens.css`/`app.css` 不改,新模块在其上扩展。
- 每核心页:保留现有静态结构作骨架,`<script type="module">` 接真实 API 后**用真数据渲染替换硬编码 mock**;后端不可达时 `ui.state(error)` 降级(非白屏)。
- 非核心页(演示保留)完全不动。

### 4.7 框架迁移触发条件(未来从原生 JS 升 React/Vue)

满足任一即评估迁移:① 核心真跑通页 ≥ 12;② 状态/异步交互复杂到原生 JS 难维护;③ 需要组件复用与单测栈;④ 产品前端正式立项。迁移时一并引入 TS + 构建链 + 组件库,本规划归档。

## 5. 数据层接口(四件套契约)

> 端点为高层映射;**精确路径/请求体/响应字段在 writing-plans 阶段逐页对照 `arrow_lake/api/routers/` 与 `api/models/` 落实**。

### 5.1 `api.js` — fetch 客户端

```js
// 契约骨架(实施时精确化)
const API_BASE = 'http://127.0.0.1:8000/api/v1';
// 鉴权:JWT Bearer(v1.9.0 libSQL IdentityStore);access_token 从 store(sessionStorage)取
//   X-API-Key 仅 dev/应急 admin fallback(auth_mode='both')

async function request(path, {method, body, query, timeout=10000, retries=1} = {});
//   - 注入 Authorization: Bearer <access_token>(store 取);401→refresh,再失效→跳 login
//   - 超时(AbortController)+ 指数退避重试(5xx/网络错)
//   - 错误分类:NetworkError / AuthError(401) / ValidationError(422) / ServerError(5xx) / NotFound(404)
//   - 统一返回 {success, data, error} 信封(对齐后端 envelope)

export const api = {
  health:  () => request('...', ...),           // GET /health (无鉴权)
  // 数据智能轨
  datasets: { list, get, ingest, ... },          // GET /datasets, POST /datasets/{n}/ingest/{type}
  index:    { create, delete, list },            // POST/DELETE /embed, /index
  search:   { vector, fts, hybrid, faceted },    // POST /datasets/{n}/search/{mode}
  rag:      { query, templates, sessions },      // POST /rag/query, GET /rag/templates
  // 管理治理轨
  users:    { list, create, update, delete, tokens },  // /admin/users, /users/{id}/tokens
  rbac:     { roles, datasetAcl, schemaAcl, deny },    // /admin/roles, /admin/acl, /admin/acl/schema, /admin/deny
  tasks:    { list, history, dlq, retry },       // /tasks, /tasks/history, DLQ
  me:       { savedQueries, favorites, preferences, notifications }, // /me/*
};
```

### 5.2 `store.js` — 跨页上下文 + 响应式状态

- **当前数据集**:`localStorage` 持久 + URL `?ds=<name>` 双向同步;进入检索/RAG/KG/工作区自动回填。
- **会话级状态**:RAG session_id、最近查询、命令面板历史。
- **响应式**:`store.subscribe(key, cb)` 简单发布订阅(原生实现,无依赖)。

### 5.3 `task.js` — 异步任务轮询器(共享单例)

- 全局轮询 `/tasks`(活跃任务),按 `task_id` 跟踪状态 `PENDING → RUNNING → COMPLETED/FAILED`。
- 订阅者注册 `task.on(taskId, cb)`;摄入/嵌入/KG build 提交后拿 `task_id` 挂订阅,完成回调刷新对应 UI + toast。
- 退避轮询(2s→5s→10s),任务终态停止;超时(默认 5min)告警。
- `tasks.html` 页直接消费同一单例渲染列表 + 历史 + DLQ。

### 5.4 `ui.js` — 反馈与状态组件

| 组件 | 职责 |
|---|---|
| `toast(msg, level)` | 操作反馈(成功/失败/进行中),右上角堆叠,自动消失 |
| `loading(target)` | 骨架屏/spinner,挂载到面板 |
| `state(target, kind)` | 空(empty)/ 载(loading)/ 错(error,含重试按钮)三态,替代当前"硬编码永不满" |
| `confirm(msg, cb)` | 危险操作二次确认(删数据集/撤销令牌/deny) |

## 6. 逐页实施规格(核心 8 页)

> 每页:接哪些端点 / 读交互 / 写交互 / 异步状态 / 空·载·错 / 跨页上下文。深度 = 读写 + 异步状态(已定)。

### 6.1 `tasks.html`(批0 · 地基,最先)

- **端点**:`GET /tasks`(活跃)、`GET /tasks/history`(历史,超 Redis 2h TTL 回退)、DLQ 列表 + `重试/丢弃`。
- **读**:三 Tab(活跃/历史/死信)真实任务列表,状态灯 `PENDING/RUNNING/COMPLETED/FAILED`,耗时、类型(ingest/embed/kg_build)、关联数据集。
- **异步**:`task.js` 单例驱动,活跃 Tab 实时刷新(轮询);任务终态 toast。
- **写**:DLQ 条目"重试"(重新入队)/"丢弃"(确认)。
- **跨页**:点任务跳关联数据集工作区(`?ds=`)。
- **空载错**:无任务→空态;"后端不可达"→错误态 + 重试。

### 6.2 `datasets.html`(批1)

- **端点**:`GET /datasets`(真实列表 + version/num_rows)。
- **读**:catalog 卡片/表格,真实数据集(`jd_ddd` 等),按行数/版本排序,搜索过滤。
- **写**:"新建数据集"(弹窗 → `POST /datasets`)。
- **跨页**:点数据集 → `store.set('ds', name)` → 跳 `dataset-detail.html?ds=<name>`。
- **空载错**:无数据集→空态引导摄入。

### 6.3 `dataset-detail.html`(批1)

- **端点**:`GET /datasets/{n}`(元数据/schema/行数)、质量/血缘/ACL Tab 接对应端点。
- **读**:9-Tab 工作区,概览 Tab 真实 schema + 采样行;质量/血缘 Tab 真实(若 v1.9.1 接)或演示保留。
- **跨页**:从 `?ds=` 回填当前数据集,所有 Tab 操作挂在该上下文。
- **写**:概览 Tab "追加摄入"按钮 → 跳 `ingest.html?ds=`。

### 6.4 `ingest.html`(批1)

- **端点**:`POST /datasets/{n}/ingest/{documents|sql|kafka|iceberg|...}`(按来源切换真实表单字段,对齐 03-fidelity-review §3.2)。
- **写**:来源切换(documents/sql/kafka/iceberg 四种真实表单),提交 → 拿 `task_id` → `task.on` 轮询 → 进度条 + 完成 toast。
- **异步**:摄入任务状态流转可见(挂 task.js)。
- **跨页**:`?ds=` 预选目标数据集。
- **documents**:doc_type 路由 + chunk 策略 + auto-embed + FTS 索引(对齐 v1.8.9)。

### 6.5 `embeddings.html`(批2)

- **端点**:`POST /embed/{text|image|clip}`、`POST/DELETE /index`(向量/FTS/标量/分面索引)。
- **读**:索引状态列表(已有索引 + 类型 + 列)。
- **写**:建索引(选类型/列/参数)→ 异步任务 → 完成可检索;删索引(确认)。
- **异步**:建索引任务轮询。
- **跨页**:`?ds=` 限定数据集。
- **定位**:检索的前置条件面(03-fidelity-review §2.3 P0)。

### 6.6 `search.html`(批2)

- **端点**:`POST /datasets/{n}/search/{vector|fts|hybrid|faceted|ensemble}`。
- **关键修复**(对齐保真度):文本查询先经"查询嵌入"(`POST /embed/text` → query_vector)再检索;移除虚构的 index type 下拉与 reranker 开关;加 `nprobes`、faceted 的 `facets[]`、ensemble 的 `columns[]+weights`、fts 的 `offset`。

## 8. 鉴权 · CORS · 安全

### 8.1 鉴权:接 v1.9.0 libSQL/JWT(真跑通前置,非"生产化才做")

v1.9.0 控制面已在 libSQL(SystemDB)落地完整鉴权——`IdentityStore`(用户/personal_token)+ `RbacStore`(角色/ACL)在 `arrow_lake/system_db/stores/`,JWT 签发在 `api/jwt_auth.py` + `api/auth_service.py`,**fail-close**(无合法身份→401,memory 已实证)。因此前端"真跑通"**必须接真实鉴权链路**,不可硬编码 key 绕过(fail-close 会直接 401)。

**真实鉴权流程**(端点已验证,`api/routers/auth.py`):

| 步骤 | 端点 | 说明 |
|---|---|---|
| 登录 | `POST /auth/token` | 用户名+密码 → JWT **token pair**(access + refresh) |
| 调 API | (所有受保护端点) | `Authorization: Bearer <access_token>` |
| 续期 | `POST /auth/refresh` | access 过期(401)→ 用 refresh 换新;refresh 失效→跳登录 |
| 当前用户 | `GET /auth/me` | 取用户/角色 → 驱动 UI 权限态(菜单/按钮可见性) |
| 登出 | `POST /auth/logout` | 撤销当前 token |
| 长期凭证 | personal_token(`al_` 前缀) | admin 发,作免登录 bearer(如 `/me/*`、CI) |

**X-API-Key 的角色**:后端 `auth_mode='both'` 时仍接受 `X-API-Key`(bootstrap/admin,如 `dev-api-key-for-local-testing-only`)。v1.9.1 **主体走 JWT Bearer**;X-API-Key 仅作开发期 seed/应急 admin fallback,不作产品鉴权路径。

→ **login.html 升级为核心页(批0)**:从演示页升级为真跑通鉴权入口(login → token pair → sessionStorage → Bearer → 401 刷新/重定向)。

### 8.2 CORS(后端一行配置)

浏览器从 `localhost:5180` fetch `localhost:8000` 需后端 CORS 放行。后端中间件已配(`Allow-Headers` 含 `X-API-Key`/`Authorization`,`Allow-Methods` 齐),需确认 `Access-Control-Allow-Origin` 回显/白名单含 `localhost:5180`(实施时浏览器实测预检;不通则后端加白名单)。

### 8.3 生产化前安全清单(v1.9.1 不做,留接口)

- DOMPurify 净化所有用户来源内容(数据集名/文档 title/KG 实体/SQL 单元格)后再 `innerHTML`。
- CSP `script-src 'self'`(移除 Google Fonts inline 或自托管)。
- SQL/Gremlin 走参数化(后端已具备)。
- access/refresh token 仅存 sessionStorage(关闭即清),不落 localStorage 明文。
