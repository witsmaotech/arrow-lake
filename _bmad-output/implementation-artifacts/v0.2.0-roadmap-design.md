## 1. Executive Summary

### 1.1 Problem Statement

Arrow Lake v0.1.0 is a Python SDK and CLI tool for multimodal data lakehouse operations.
It provides excellent programmable access to 80 Stories worth of functionality (vector search,
full-text search, OLAP analytics, quality pipelines, lineage tracking, workflow orchestration),
but has no HTTP API — making it impossible to use from non-Python services (frontend apps, microservices,
BI tools, other programming languages).

### 1.2 Proposal

Transform Arrow Lake into a **deployable data service** by adding a FastAPI-based REST
layer on top of the existing Lake SDK. The API layer is a thin orchestration layer — it delegates
all data operations to the existing SDK, preserving the 14,000+ lines of battle-tested business logic.

### 1.3 Scope

v0.2.0 covers four phases:
- **Phase 1** (P0): RESTful API with 30+ endpoints, authentication, OpenAPI docs
- **Phase 2** (P1): Multimodal content management metadata model
- **Phase 3** (P1): GPU-accelerated inference, adaptive indexing, distributed ingestion
- **Phase 4** (P2): OpenTelemetry, Grafana dashboards, Kubernetes Operator, external connectors

### 1.4 Target Business Scenarios

| Scenario | Description | Priority |
|----------|-------------|----------|
| **Data Search Service** | Backend service providing vector + FTS + hybrid search for other applications via REST API | Primary |
| **Multimodal Content Platform** | Unified management of text/image/audio/video content with metadata, quality scoring, and cross-modal retrieval | Primary |
| **Enterprise Knowledge Base** | Foundation for RAG pipelines — store documents, embed, and retrieve via API (Phase 3+) | Secondary |

### 2.2 Design Principles

| Principle | Description |
|-----------|-------------|
| **Thin API Layer** | Every endpoint maps 1:1 to an existing Lake SDK method. No business logic duplication. |
| **Pydantic-First** | All request/response models are Pydantic BaseModel, enabling automatic validation and OpenAPI schema generation. |
| **Arrow IPC over JSON** | Large result sets (search results, query output) use Arrow IPC binary encoding via base64 to avoid JSON serialization overhead. |
| **Graceful Degradation** | Optional dependencies (Ray, GPU, NeMo Curator) degrade to CPU/sequential/error when unavailable. |
| **Backward Compatible** | Existing Lake SDK and CLI continue to work unchanged. API is additive. |

### 2.3 Technology Stack

| Component | Technology | Rationale |
|-----------|-----------|-----------|
| Web Framework | **FastAPI 0.115+** | Native Pydantic v2 integration, async, auto-generated OpenAPI 3.1, dependency injection |
| ASGI Server | **uvicorn** (dev), **gunicorn + uvicorn** (prod) | Standard production ASGI setup |
| Serialization | **pyarrow IPC Stream** for large results, **JSON** for small payloads | Arrow binary format is 10-100x faster than JSON for tabular data |
| Authentication | **API Key** (v0.2) → **JWT + RBAC** (v0.3) | Gradual security hardening |
| Documentation | **Swagger UI** (built-in) + **Redoc** (optional) | Auto-generated from Pydantic models |
| Testing | **httpx** (async client), **pytest** + **pytest-asyncio** | Type-safe async test client |
| Monitoring | **Prometheus** (existing), **OpenTelemetry** (Phase 4) | Backward compatible with existing /metrics |

### 3.2 Detailed API Specifications

#### 3.2.1 POST `/api/v1/datasets/{name}/ingest` — File Ingestion

**Request Body** (multipart/form-data):
```
files: List[UploadFile]         — Files to ingest (CSV, JSON, JSONL, Parquet)
modality: Optional[str]        — "text" | "auto-detect" (default: "auto-detect")
columns: Optional[str]          — JSON string of column type overrides
                               (e.g., '{"text":"string","embedding":"float32"}')
overwrite: Optional[bool]       — Allow overwriting existing dataset (default: false)
```

**Response** (200):
```json
{
  "success": true,
  "data": {
    "dataset_name": "documents",
    "total_rows": 1250,
    "total_bytes": 4500000,
    "sources": [
      {"path": "papers.csv", "rows": 1200, "status": "success"},
      {"path": "notes.json", "rows": 50, "status": "success"}
    ],
    "schema": {
      "fields": [
        {"name": "text_content", "type": "string", "nullable": true},
        {"name": "id", "type": "string", "nullable": false}
      ]
    }
  },
  "error": null,
  "meta": {"request_id": "abc-123", "latency_ms": 1523.4}
}
```

**Error Responses**:
- `400` — Unsupported file format, empty file list
- `409` — Dataset already exists and `overwrite=false`
- `413` — Total file size exceeds limit
- `422` — Schema validation failure

**SDK Mapping**: Calls `Lake.ingest(dataset_name, [file_paths])` then `Lake.catalog()` for schema.

**Streaming**: For large files (>100MB), returns a `202 Accepted` with a `Location` header
pointing to a status endpoint. Client polls until 200.

#### 3.2.2 POST `/api/v1/datasets/{name}/search/vector` — Vector Search

**Request Body** (JSON):
```json
{
  "query_vector": [0.12, -0.34, 0.56, "..."],
  "top_k": 10,
  "metric": "cosine",
  "vector_column": "text_embedding",
  "where": "category = 'technology'",
  "nprobes": 20
}
```

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| `query_vector` | `list[float]` | Yes | — | Query embedding vector. Must match `embedding_dim`. |
| `top_k` | `int` | No | config (10) | Number of results. Max: 10,000. |
| `metric` | `str` | No | config (cosine) | Distance metric: "cosine", "l2", "dot" |
| `vector_column` | `str` | No | "text_embedding" | Which embedding column to search. |
| `where` | `str` | No | null | LanceSQL filter expression. |
| `nprobes` | `int` | No | config (20) | IVF probe count. |

**Response** (200):
```json
{
  "success": true,
  "data": {
    "row_count": 10,
    "query_vector_dim": 1024,
    "metric": "cosine",
    "top_k": 10,
    "max_distance": 0.823,
    "columns": ["id", "text_content", "category", "_distance"],
    "rows": [
      {"id": "doc-001", "text_content": "...", "category": "tech", "_distance": 0.123},
      "..."
    ],
    "arrow_ipc": "base64-encoded-arrow-ipc-stream"
  },
  "meta": {"request_id": "abc-123", "latency_ms": 12.7}
}
```

**Serialization Modes**:
- `?format=json` (default): Returns `rows` as JSON array (suitable for < 100 results)
- `?format=arrow`: Returns `arrow_ipc` as base64-encoded Arrow IPC Stream (suitable for large results)
- `?format=arrow_stream`: Returns raw binary Arrow IPC Stream (maximum performance)

**SDK Mapping**: Calls `Lake.search(dataset_name, query_vector, top_k=top_k, ...)`.

**Behavior Notes**:
- Validates `query_vector` dimension matches `vector_column`'s list_size. Returns `422` if mismatch.
- Validates `where` clause against SQL injection blacklist (INSERT, UPDATE, DELETE, DROP, etc.).
- Falls back to flat (brute-force) search if no index exists (logged as warning).
- `_distance` column always appended to results.

#### 3.2.3 POST `/api/v1/datasets/{name}/search/hybrid` — Hybrid Search

**Request Body**:
```json
{
  "query_vector": [0.12, -0.34, "..."],
  "query_text": "machine learning in production",
  "top_k": 10,
  "vector_column": "text_embedding",
  "fts_column": "text_content",
  "where": "source = 'arxiv'"
}
```

**Response**: Same envelope as vector search, with `_rrf_score` instead of `_distance`.

**SDK Mapping**: `Lake.hybrid_search(dataset_name, query_vector, query_text, ...)`.

**Behavior Notes**:
- Runs vector search and FTS search in parallel (not sequentially).
- Fuses results using Reciprocal Rank Fusion (RRF): `score = 1/(k + rank)`.
- Default multipliers: `vector_top_k_multiplier=3`, `fts_top_k_multiplier=3`.
- Deduplicates by row `id` column.

#### 3.2.4 POST `/api/v1/datasets/{name}/search/faceted` — Faceted Search

**Request Body**:
```json
{
  "query_vector": [0.12, -0.34, "..."],
  "facets": ["modality", "source", "quality_score"],
  "top_k": 10,
  "vector_column": "embedding",
  "where": "modality = 'image'"
}
```

**Response**:
```json
{
  "success": true,
  "data": {
    "row_count": 10,
    "facets": [
      {"name": "modality", "value": "image", "count": 42},
      {"name": "source", "value": "wikimedia", "count": 30},
      {"name": "source", "value": "upload", "count": 12}
    ],
    "rows": [...],
    "arrow_ipc": "..."
  },
  "meta": {"request_id": "abc-123", "latency_ms": 45.2}

```

**SDK Mapping**: `Lake.faceted_search(dataset_name, query_vector, facets=facets, ...)`.

**Behavior Notes**:

- Filters out NULL super-aggregate values from facet results.
- Default facet columns from config: `["modality", "source"]`.

#### 3.2.5 POST `/api/v1/datasets/{name}/query/olap` — OLAP Analytics

**Request Body**:
```json
{
  "sql": "SELECT category, COUNT(*) as cnt, AVG(quality_score) as avg_score FROM __dataset__ GROUP BY category ORDER BY cnt DESC",
  "max_rows": 1000,
  "tables": {}
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `sql` | `str` | Yes | SQL query. Must be SELECT-only (validated). |
| `max_rows` | `int` | No | Max result rows (default: 100,000 from config). |
| `tables` | `dict[str, Any]` | No | Additional tables for JOIN. Keys must match `[a-zA-Z_][a-zA-Z0-9_]*`. |

**Response**: Same envelope with Arrow IPC result.

**SDK Mapping**: `Lake.olap_query(dataset_name, sql, max_rows=max_rows, tables=tables)`.

**Behavior Notes**:
- SQL injection validation: blocks INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, GRANT, REVOKE.
- `__dataset__` magic table name refers to the dataset's Lance table (auto-substituted).
- JOIN support controlled by `enable_join` config (default: true).
- Streaming mode for large result sets: returns RecordBatchReader chunks.

#### 3.2.8 POST `/api/v1/datasets/{name}/quality/filter` — Quality Filtering

**Request Body**:
```json
{
  "filters": ["text_length", "image_resolution"],
  "mode": "all",
  "write_dead_letter": true
}
```

**Response** (200):
```json
{
  "success": true,
  "data": {
    "total": 1250,
    "passed": 1180,
    "rejected": 70,
    "duration_seconds": 2.3,
    "filter_results": [

```

**SDK Mapping**: `Lake.quality_filter(dataset_name, active_filters=",".join(filters), mode=mode)`.

**Behavior Notes**:

- Dead letter records (rejected rows) written to `_dead_letter/{dataset_name}` dataset when `write_dead_letter=true`.

### 3.3 Unified Response Envelope

All API responses follow a consistent envelope structure:

```python
class APIResponse(BaseModel, Generic[T]):
    """Unified response envelope for all Arrow Lake API endpoints."""

    success: bool
    data: T | None = None
    error: APIError | None = None
    meta: ResponseMeta

class APIError(BaseModel):
    code: str           # Machine-readable error code (DATASET_NOT_FOUND, etc.)
    message: str        # Human-readable description
    details: dict = {}  # Additional context (field, constraint, hint)

class ResponseMeta(BaseModel):
    request_id: str     # UUID v4
    latency_ms: float   # Server processing time in milliseconds
    timestamp: str      # ISO 8601 UTC
```

### 3.4 Error Code Taxonomy

Error codes are derived from existing `arrow_lake/exceptions.py`:

| Code | HTTP | Category | Description |
|------|------|----------|-------------|
| `DATASET_NOT_FOUND` | 404 | Catalog | Dataset does not exist |
| `DATASET_ALREADY_EXISTS` | 409 | Catalog | Dataset name collision |
| `STORAGE_CONNECTION_FAILED` | 503 | Storage | Cannot reach storage backend |
| `STORAGE_WRITE_FAILED` | 500 | Storage | Write operation failed |
| `QUERY_SYNTAX_ERROR` | 422 | Query | Invalid SQL or filter expression |
| `QUERY_NO_RESULTS` | 200 | Query | Search returned empty (not an error) |
| `QUERY_INDEX_NOT_FOUND` | 200 | Query | No index, using flat search |
| `VECTOR_DIMENSION_MISMATCH` | 422 | Query | Query vector dim ≠ column list_size |
| `VECTOR_INVALID_QUERY` | 422 | Query | Empty or malformed vector |
| `FTS_INDEX_FAILED` | 500 | Query | FTS index creation failed |
| `HYBRID_SEARCH_FAILED` | 500 | Query | Hybrid fusion error |

### 3.5 Serialization Strategy

For large result sets (search results, query output, dataset listing), provide two serialization
modes to balance compatibility and performance:

| Format | Content-Type | Use Case |
|--------|-------------|----------|
| JSON | `application/json` | Small results (<100 rows), debugging, BI tool compatibility |
| Arrow IPC | `application/x-arrow-ipc-stream` | Large results, inter-service communication, data science tools |

**JSON mode** (default, `?format=json`):
```json
{
  "rows": [
    {"id": "doc-001", "text_content": "...", "_distance": 0.123}
  ],
  "row_count": 10
}
```

**Arrow IPC mode** (`?format=arrow`):
```json
{
  "arrow_ipc": "base64-encoded-S2JCSQwGBgACAAKB/2ZBAAAAAAAKAF...",
  "row_count": 10
}
```

Implementation:
```python
import pyarrow.ipc as ipc
import base64

buf = ipc.new_stream(table.to_reader())
body = base64.b64encode(buf.readall()).decode()
```

### 3.6 Authentication & Authorization

#### v0.2: API Key Authentication

```python
# middleware/auth.py
class APIKeyAuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        api_key = request.headers.get("X-API-Key")
        if not api_key:
            return JSONResponse(status_code=401, content={"detail": "Missing X-API-Key header"})

        if not self._validate_key(api_key):
            return JSONResponse(status_code=401, content={"detail": "Invalid API key"})

        response = await call_next(request)
        return response

    def _validate_key(self, api_key: str) -> bool:
        """Check against configured keys."""
        master_key = self.settings.arrow_lake.api.master_key
        if master_key and api_key == master_key:
            return True
        valid_keys = self.settings.arrow_lake.api.keys
        return api_key in valid_keys
```

### 3.8 Dependency Injection & Lifecycle

```python
# deps.py
from functools import lru_cache

@lru_cache(maxsize=1)
def get_lake() -> Lake:
    """Get or create Lake instance (singleton per worker process)."""
    config = ArrowLakeConfig()
    return Lake(base_uri=config.storage.base_uri, config=config)
```

**Lifecycle**:
1. App startup: Validate config, check storage accessibility
2. Per-request: Inject `Lake` instance via FastAPI `Depends()`
3. Shutdown: Close Lake connections, flush metrics

```python
# app.py
@asynccontextmanager
async def lifespan(app: FastAPI):
    # Startup
    lake = get_lake()
    logger.info("api_started", version=version(), datasets=lake.list_datasets())
    yield
    # Shutdown
    logger.info("api_stopping")

def create_app() -> FastAPI:
    return FastAPI(
        title="Arrow Lake API",
        version=__version__,
        lifespan=lifespan,
        docs_url="/docs",
        redoc_url="/redoc",
        openapi_url="/openapi.json",
        middleware=[
            CORSMiddleware,
            APIKeyAuthMiddleware,
            RequestLogMiddleware,
        ],
        dependencies=[Depends(get_lake)],
    )
```

## 5. Phase 3 — Performance & Scale

### 5.1 GPU-Accelerated Embedding

```
API Request → FastAPI → BackgroundTask
                           │
                           ▼
                    Ray Serve Deployment
                    ┌─────────────┐
                    │ GPU Worker 1│  ← batch shard 0
                    │ GPU Worker 2│  ← batch shard 1
                    │ CPU Worker  │  ← fallback
                    └─────────────┘
                           │
                           ▼
                    Embedding Results → Cache → Response
```

- Batch requests auto-sharded across available GPU workers
- CPU fallback when no GPU available
- Embedding results cached in LRU cache (configurable TTL)

## 7. Non-Goals

The following are explicitly out of scope for v0.2.0:

| Item | Reason |
|------|--------|
| **Frontend UI** | Arrow Lake is a data service layer. Frontends are consumer applications. |
| **Multi-tenant isolation** | Requires auth overhaul. Planned for v0.3. |
| **Data encryption at rest** | Delegated to S3/MinIO server-side encryption. |
| **GraphQL API** | REST + Arrow IPC sufficient. GraphQL adds complexity without benefit. |
| **Alternative storage backends** | Lance + S3 is the core design choice. Not changing. |
| **Model fine-tuning** | Out of scope. Arrow Lake uses pre-trained models only. |

|------|--------|------------|-----------|
