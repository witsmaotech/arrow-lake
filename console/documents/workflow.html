工作流编排（Metaflow）

用 Metaflow 编排并行摄取、GPU 嵌入、知识图谱构建与批量 RAG。覆盖 @foreach / branch / @retry、运行历史、Argo 部署、自定义 Flow 与后台 TaskManager 异步任务。

难度 · 高级 耗时 · 20 分钟 依赖 · Metaflow（可选 Argo / Ray）

Arrow Lake 以 Metaflow 作为工作流编排层，提供并行执行（@foreach）、分支（branch）、容错（@retry / @catch）、资源管理（@resources）与运行历史追踪（Client API）。所有 Flow 位于 flows/ 目录。

前置

安装依赖 pip install metaflow（已包含在 Arrow Lake 依赖中）。Metaflow 适合多步、可恢复、带产物追踪的 CLI/Argo 流水线；单次 API 异步操作请用本章末尾的 TaskManager。

8编写自定义 Flow

错误处理推荐

优先在 step 内用 try/except，而非 @catch / @retry——后者在 Metaflow v2.19+ 可能产生 "Internal error" 并绕过 catch 机制。新 Flow 需在 flows/__init__.py 的 _flow_map 中注册。

10后台异步任务（TaskManager）

Metaflow Flow 经 CLI 在进程外运行；而从 API 触发的长耗时操作（KG 构建、导出、大规模清洗），由进程内 TaskManager（arrow_lake/api/tasks.py:115）在后台跑协程并暴露轮询状态端点——console 进度条即由它驱动。

  • fire-and-forget、GC 安全：run_background() 存有 asyncio task 的强引用，垃圾回收器不会中途静默杀掉它（v1.6.1 从仅限导出的 tracker 泛化而来）。
  • 跨 worker 可见（v1.6.2）：配置 Redis 后，任务状态写入共享 Redis HASH，任意 worker 都能应答状态轮询（TaskManager.init_redis_store()）。
  • 持久历史（v1.9.0）：接入 libSQL TaskHistoryStore 后，完成/失败任务记录超越 Redis TTL，/tasks 列表能在 Redis 刷新或重启后存活。
  • 归属通知（v1.9.3）：init_user_state_store() 接入 my-workspace 通知存储，任务完成时给所有者写一条通知。
何时用哪个

Metaflow（flows/*.py）用于多步、可恢复、带产物追踪、经 CLI/Argo 运行的流水线；TaskManager 用于需要在 console 显示进度条、可轮询 task_id 的单次 API 内异步操作。
