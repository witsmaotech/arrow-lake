v1.8–v1.9 新特性实战

11 项 v1.8.0 roadmap 落地能力（CLIP 跨模态、Lance branches、blob 存储、hf://、VLM、Gravitino 联邦、行级血缘、Daft 流式写、async 检索、日文分词）+ v1.9.0–v1.9.6 控制面/多模态/治理/RAG 质量/KG 性能演进。

难度 · 进阶 耗时 · 25 分钟 依赖 · Python 3.11+ · 部分需模型/外部服务

本章分两部分：§16.1–16.13 是 v1.8.0 roadmap 落地的 11 项新能力（+ 2 项压测 DEFER）；§16.14 是 v1.9.0–v1.9.6 的演进。每项给一句话价值、facade 方法签名、最小用法。

1CLIP 跨模态检索（#6）

用 CLIP/SigLIP 的 text tower 把文本查询编入与图像相同的嵌入空间，实现文搜图。

签名：encode_text_clip(texts, *, model=None, model_source="huggingface") -> list[list[float]]。需预先有含 image_embedding 列的数据集（用 CLIPImageEncoder.encode 摄入）。

2Lance 数据集 branches（#1）

数据集像代码一样打 tag、开 branch，支持 A/B、回滚、可复现训练。本地 Lance 即可跑，无需额外服务。

3blob 存储（#2）

把 image/audio/video 的原始字节原地存为 Lance binary 列，与嵌入同库——省一次 IO，多模态一致性更好。

4hf:// 数据集（#8）

用 lancedb 的 hf:// scheme 直接读 HuggingFace 上的 Lance-format 数据集——评测/种子数据一键加载。需联网与 HF_TOKEN。

5VLM decode_image 变换（#18）

decode_image 是注册到 build_transforms 的 builder，补全 VLM 链：image bytes → 解码 → classify_image / prompt。

6Gravitino 统一 catalog facade（#19）+ Daft 联邦（#14）

把数据集注册到 Gravitino（Table + Fileset），让 DuckDB / Daft / lancedb 三引擎都经 Gravitino 解析——真正的联邦 catalog。Daft 用 daft.io.GravitinoConfig 直连，联邦查询不经 DuckDB 转译。

7行级 lineage（#3）

在事件级血缘之上叠加 Lance row_id 行级溯源——精确到"这一行从哪几行派生来"。

8Daft 流式写（#16）

Daft lazy DataFrame 直接写 Lance，跳过 Arrow 中转，处理超内存负载（>16×）。KG build / 大批量 ingest 推荐。

9全链路 async 检索（#17）

向量 search_async 走 lancedb 原生 connect_async（GIL-free）；fts / hybrid / faceted 的 *_async 是 asyncio.to_thread 线程卸载——async handler 不阻塞事件循环。

v1.8.x 更新

向量 search_async 的 AsyncConnection/AsyncTable 句柄现已进程级池化（async_conn_pool.py），消除每次调用的连接建立开销；并修复了 v1.7.1 起遗留的 AsyncTable.search 缺 await 缺陷（此前一调即崩）。

10日文分词 lindera（#4）

FTS 多语言分词：在日文场景接入 lindera 假名分词（模块级缓存 + 优雅降级）。lindera 是可选依赖；未装时自动降级到默认分词器，不报错。

11压测 DEFER 与已知限制

两项诚实记录的 DEFER：#15 分布式索引（单节点 21s/1M，1B+ 行才需 Ray 分布式 backfill，ray_runtime 基建已就绪待触发）；#7 ColBERT/colpali（现实 recall 96%，病态下降源于 IVF_PQ 量化，修法是 HNSW，非 ColBERT 场景）。

能力前置条件已知限制
CLIP（§1）需联网下载 CLIP 权重（首次），HF 镜像需 HF_TOKEN无
hf://（§4）需 HF_TOKEN（否则 HF 返回 401）无
VLM decode（§5）build_transforms 签名是 list[dict]（非单 dict）；真实图像需 Daft image decode无
Daft↔Gravitino（§6）需 Gravitino 运行⚠️ facade bug（v1.8.1 已修：改用 GravitinoConfig(endpoint=, metalake_name=)）
Daft 流式写（§8）需 Daft⚠️ facade bug（v1.8.1 已修：加 .collect() 并改用 _lance_dir）

12v1.9.0–v1.9.6 演进总览

v1.9 系列围绕控制面统一、质量闭环、治理兑现三条主线推进。

v1.9.0 — Turso/libSQL 统一控制面

把 RBAC / 身份 / personal_token / catalog / 任务历史 / RAG 会话 / 血缘索引从分散存储收敛到 libSQL（system_db 配置，enabled 默认关，生产置 true；store 不可达 fail-closed 返 401）。迁移 V001–V004 自动跑。新增 personal token 签发 POST /admin/users/{id}/tokens 与 /me/* 用户态。

v1.9.1 — console 全页实施

console 全页真跑通：admin（users / ACL / deny）+ my-workspace 五区；personal token 经 X-API-Key 鉴权。

v1.9.2 — 多模态深化 + OLAP

  • 以图搜图：POST /embed/image（CLIP/SigLIP，JSON images:[base64]）→ /datasets/{name}/search/vector。
  • 导出统一：/datasets/{name}/export（异步 202 + output_path 必填）+ /export-to（parquet/csv/json/iceberg/clickhouse）。
  • DuckLake 物化视图：/api/v1/materialized/*（ducklake_enabled 默认关）。
  • Pivot 助手 + 纯 SVG 图表（零 vendor 依赖）。

v1.9.3 — 数据集字段注释

field_comments（PyArrow 直读 parquet/CSV sidecar + MySQL/PG 捕获）+ POST /datasets/{name}/schema/annotate → SchemaField.comment。

v1.9.4 — 血缘 actor + KG 质量

  • 血缘 actor 传递链：ingest / delete 透传认证用户，history 响应含 actor。
  • KG project_concept_graph（22 类型 + 14 关系）+ MERGE_FIELD 合并（替 BALANCED，非 LLM，消除内存爆炸）。

v1.9.5 — RAG 质量全链路

  • default_retrieval_strategy="hybrid" 真生效（此前是死配置，检索实际只走 FTS）。
  • faithfulness 校验（lightweight 引用校验，返 verification.support_ratio）。
  • GraphRAG 三路并行（延迟 -40~50%）+ KA LRU 缓存。
  • reranker 三连修复 + OllamaReranker 默认（dengcao/Qwen3-Reranker-0.6B:F16）。
  • 两阶段 LLM（rag.extract_llm / qa_llm）+ query_transform（hyde/multi_query）。

v1.9.6 — 治理兑现 + KG 性能 + 安全加固

  • 血缘可视化 console/lineage.html（vis-network 列级血缘 + max_nodes 截断）。
  • masking 治理：4 函数 + HMAC fail-fast（缺 ARROW_LAKE__MASKING__HMAC_KEY 启动阻断）+ mask-preview。
  • KG 质量/性能：snap 编辑距离归一化 + he_strict_definition 严格过滤 + GraphRAG 三路并行 + QuestionEntityCache。
  • 安全 fail-closed：masking/RBAC 全 fail-closed；lineage XSS 转义；Gravitino 写端点去 ?body= URL param。
生产必配

ARROW_LAKE__MASKING__HMAC_KEY（fail-fast）；system_db.enabled=true + url。
