## 16.1 CLIP Cross-Modal Retrieval (#6)

Use the **text tower** of CLIP/SigLIP to encode a text query into the same embedding space as images, enabling text-to-image search.

```python
qvecs = lake.encode_text_clip(["a cat sitting on a sofa"], model="openai/clip-vit-base-patch32")
hits = lake.search("photos", qvecs[0], vector_column="image_embedding", top_k=5)
```

> Signature: `encode_text_clip(texts, *, model=None, model_source="huggingface") -> list[list[float]]`. Requires a dataset with an `image_embedding` column (ingested via `CLIPImageEncoder.encode`).

## 16.2 Lance Dataset Branches (#1)

Tag and branch datasets like code — supports A/B testing, rollback, and reproducible training.

```python
lake.create_branch("docs", "experiment-a")          # defaults from HEAD
lake.create_branch("docs", "v1.8-baseline")
lake.list_branches("docs")                          # → ['experiment-a', 'v1.8-baseline']
head = lake.read_at_branch("docs", "experiment-a")  # read the branch HEAD
lake.delete_branch("docs", "v1.8-baseline")
```

> Signatures: `create_branch(dataset_name, branch, version=None)`, `list_branches(dataset_name) -> list[str]`, `read_at_branch(dataset_name, branch)`, `delete_branch(...)`. Runs on local Lance — no extra service required.

## 16.3 Blob Storage (#2)

Store the **raw bytes** of image/audio/video in place as a Lance binary column, co-located with embeddings — saves one IO hop and improves multimodal consistency.

```python
lake.add_blob_column("docs", "image_bytes", [png_bytes_1, png_bytes_2, png_bytes_3])
```

> Signature: `add_blob_column(dataset_name, column_name, blobs: list[bytes]) -> None`. Appends a binary column via `add_columns_table` under the hood.

## 16.4 `hf://` Datasets (#8)

Read Lance-format datasets hosted on HuggingFace directly via lancedb's `hf://` scheme — one-click loading of evaluation/seed data.

```python
tbl = lake.load_hf_dataset("lance-format/quora-duplicates-embedding-bge-small", table="quora")
```

> Signature: `load_hf_dataset(repo_id, *, table=None)`. Requires network access; raises on empty/unreachable tables.

## 16.5 VLM `decode_image` Transform (#18)

`decode_image` is a builder registered with `build_transforms` that completes the VLM chain: image bytes → decode → `classify_image` / `prompt`.

```python
from arrow_lake.ingest.transforms import build_transforms

transforms = build_transforms({"decode_image": {"column": "image_bytes"}})
lake.ingest("ds", file_paths, transforms=transforms)   # auto-decodes at ingest time
```

## 16.6 Gravitino Unified Catalog Facade (#19)

Register datasets into Gravitino (Table + Fileset) so that DuckDB / Daft / lancedb all resolve through Gravitino — a true federated catalog.

```python
lake.gravitino_register_dataset("docs")     # register into Gravitino
stats = lake.table_statistics("docs")       # statistics
```

> Signature: `gravitino_register_dataset(dataset_name, *, location="")`. Requires Gravitino to be running.

## 16.7 Daft ↔ Gravitino (#14)

Daft connects directly to Gravitino tables via `daft.io.GravitinoConfig` — federated queries without DuckDB translation.

```python
df = lake.daft_from_gravitino("docs", url="http://localhost:8090", metalake="arrow_lake")
df.collect()   # lazy; triggers execution
```

> Signature: `daft_from_gravitino(table_name, *, url, metalake)`.

## 16.8 Row-Level Lineage (#3)

Layer Lance `row_id` row-level provenance on top of event-level lineage — trace exactly which source rows a given row was derived from.

```python
lake.lineage_record_row(
    "docs", row_id=2,
    source_rows=[{"dataset": "raw_docs", "row_id": 42}],
    operation="derive",
)
```

> Signature: `lineage_record_row(dataset_name, row_id, *, source_rows=None, operation="derive")`. Queryable via the existing lineage store / query / graph APIs.

## 16.9 Daft Streaming Write (#16)

Write a Daft lazy DataFrame directly to Lance, bypassing the Arrow round-trip — handles out-of-memory workloads (>16×).

```python
import daft
df = daft.from_pydict({"id": [10, 11], "text": ["streaming write", "OOM-friendly"]})
lake._get_storage().write_lance_from_dataframe("docs_daft", df, mode="create")
```

> Signature: `write_lance_from_dataframe(name, df, mode="create")` (on `LanceStorageManager`). Recommended for KG builds / bulk ingest.

## 16.10 End-to-End Async Retrieval (#17)

Vector `search_async` uses lancedb's native `connect_async` (GIL-free); the `*_async` variants of fts / hybrid / faceted are `asyncio.to_thread` offloads — async handlers never block the event loop.

> **v1.8.x update (#1)**: the `AsyncConnection` / `AsyncTable` handles behind vector `search_async` are now pooled at process level (`async_conn_pool.py`), eliminating per-call connection setup cost; also fixes a leftover defect from v1.7.1 where `AsyncTable.search` was missing `await` (previously `search_async` would crash on first call and was unusable).

```python
res = await lake.search_async("docs", query_vec, top_k=10)          # vector (native async + connection pool)
res = await lake.text_search_async("docs", "data lakehouse", top_k=5)  # FTS
res = await lake.hybrid_search_async("docs", query_vec, "Lance", top_k=5)
res = await lake.faceted_search_async("docs", query_vec, facets=["category"], top_k=10)
```

> Signature: `async text_search_async(dataset_name, query, *, top_k=None, fts_column=None, ...)` etc. FTS requires a prior `create_fts_index`.

## 16.11 Japanese Tokenization with Lindera (#4)

FTS multilingual tokenization: integrate lindera kana tokenization for Japanese (module-level cache + graceful degradation).

```python
# Enable via FullTextSearchConfig tokenizer config, or specify at index build time (if the build supports it)
lake.create_fts_index("docs_ja", fts_column="text", tokenizer="lindera")
```

> lindera is an optional dependency; when not installed it auto-falls back to the default tokenizer without error.

## 16.12 Two Benchmark Items DEFERRED (honest record)

- **#15 Distributed indexing**: 21s/1M rows on a single node; Ray distributed backfill is only needed at 1B+ rows (`ray_runtime` infrastructure is ready, awaiting trigger).
- **#7 ColBERT/colpali**: real-world recall is 96%; pathological degradation stems from IVF_PQ quantization (the fix is HNSW, not a ColBERT scenario).

Re-benchmark: `tests/benchmark/test_bench_batch3_gates.py` — re-run after data-scale/feature changes to re-evaluate.

## 16.13 Prerequisites & Known Limitations (read before running)

The demos in this section gracefully SKIP when models/external services are missing. To run them truly end-to-end, note:

| Capability | Prerequisite | Known limitation |
|---|---|---|
| **§16.1 CLIP** | Needs network to download CLIP weights (first run); HF mirror needs `HF_TOKEN` | None |
| **§16.4 hf://** | Needs `HF_TOKEN` (HF returns 401 "Invalid username or password") | None |
| **§16.5 VLM decode** | `build_transforms` signature is **`list[dict]`** (not a single dict); real images need Daft image decode | None (example already uses list form) |
| **§16.7 Daft↔Gravitino** | Needs Gravitino running | ⚠️ **facade bug**: `daft_from_gravitino` passes `url=` to `daft.io.GravitinoConfig`, but that PyO3 class does not accept a `url` kwarg → `TypeError`. Facade needs to use the correct field name (to be fixed) |
| **§16.9 Daft streaming write** | Needs Daft | ⚠️ **facade bug**: `write_lance_from_dataframe` calls `df.write_lance(uri, mode=...)` but Daft is lazy and the **result is never `.collect()`-ed** → the write is silently dropped (`list_datasets` is empty). Fix: `df.write_lance(...).collect()` (to be fixed) |

> Both ⚠️ items **were fixed in v1.8.1**: `daft_from_gravitino` now uses `GravitinoConfig(endpoint=, metalake_name=)`; `write_lance_from_dataframe` adds `.collect()` and uses `_lance_dir` (the `.lance` path) — Daft writes are now visible to `list_datasets` and readable back. VLM spec uses `{"op":"decode_image",...}`. CLIP / hf still need `HF_TOKEN` / model download.

## 16.14 v1.9.0 – v1.9.6 Evolution Overview

The v1.9 series advances along three main lines: **control-plane unification, quality closed-loop, and governance delivery**. Key points per release (see the corresponding release notes `docs/arrow-lake-v1.9.*-release-zh.md`):

### v1.9.0 — Turso/libSQL Unified Control Plane

Converged RBAC / identity / personal_token / catalog / task history / RAG sessions / lineage index from scattered storage into **libSQL** (`system_db` config; `enabled` defaults off, set true in production; store unreachable → fail-closed 401). Migrations V001–V004 run automatically. Added personal-token issuance `POST /admin/users/{id}/tokens` and the `/me/*` user workspace (saved-queries / notifications / preferences / dashboards / favorites).

### v1.9.1 — Console Full-Page Implementation

The console runs end-to-end across all pages: admin (users / ACL / deny) + the five my-workspace areas; personal tokens authenticate via `X-API-Key`.

### v1.9.2 — Multimodal Deepening + OLAP

- **Image-to-image search**: `POST /embed/image` (CLIP/SigLIP, JSON `images:[base64]`) → `/datasets/{name}/search/vector`.
- **Unified export**: `/datasets/{name}/export` (async 202 + required `output_path`) + `/export-to` (parquet/csv/json/iceberg/clickhouse).
- **DuckLake materialized views**: `/api/v1/materialized/*` (list/drop/cleanup; `ducklake_enabled` defaults off).
- **Pivot helper + pure-SVG charts** (zero vendor dependencies).

### v1.9.3 — Dataset Field Comments

`field_comments` (PyArrow reads parquet/CSV sidecar directly + MySQL/PG capture) + `POST /datasets/{name}/schema/annotate` → `SchemaField.comment`; `lake.update_field_comments(name, comments)`.

### v1.9.4 — Lineage Actor + KG Quality

- **Lineage actor propagation chain**: ingest / delete propagates the authenticated user; history responses include the actor.
- **KG `project_concept_graph`** (22 types + 14 relations, for project proposals) + `MERGE_FIELD` merging (replaces BALANCED; non-LLM; eliminates memory blowups).

### v1.9.5 — RAG Quality Full Chain

- **`default_retrieval_strategy="hybrid"` truly effective** (before v1.9.5 it was a dead config — retrieval actually only used FTS and the vector index sat idle).
- **Faithfulness verification** (lightweight `[n]` citation check; `enable_verification` opt-in; returns `verification.support_ratio`).
- **GraphRAG three-way parallel** (asyncio.gather, latency -40~50%) + KA LRU cache.
- **Reranker triple fix** + **OllamaReranker default** (`rag.reranker="ollama"`, `dengcao/Qwen3-Reranker-0.6B:F16`).
- **Two-stage LLM** (`rag.extract_llm` / `qa_llm`) + `query_transform` (hyde/multi_query).
- **Storage**: `lance_cache_size` local read cache + raw files split across buckets (`s3_uploads_bucket`).

### v1.9.6 — Governance Delivery + KG Performance + Security Hardening

- **Lineage visualization** `console/lineage.html` (vis-network column-level lineage + `max_nodes` truncation + node-click queries `/lineage/history`).
- **Masking governance**: 4 functions (redact/hash/partial/nullify) + **HMAC fail-fast** (missing `ARROW_LAKE__MASKING__HMAC_KEY` blocks startup) + `POST /datasets/{name}/quality/mask-preview` + audit reuses Lance (zero new tables).
- **KG quality/performance**: snap edit-distance normalization + `he_strict_definition` strict filtering + enum parsing; GraphRAG three-way parallel + `QuestionEntityCache` monotonic clock.
- **Security fail-closed**: masking/RBAC `_apply_masking`/`_apply_row_filter`/`_fetch_rules` all fail-closed; lineage XSS escaping; Gravitino write endpoints drop the `?body=` URL param (PII kept out of logs).

> ⚠️ **Required for production**: `ARROW_LAKE__MASKING__HMAC_KEY` (fail-fast); `system_db.enabled=true` + url.
