# v1.9.7 — 结构化大表 Web 性能 + OLAP scan_mode 安全默认

> noaa_china(1070 万行)详情页加载 ~50s → 翻页 0.27s。详见 `CHANGELOG.md` [1.9.8]。

## 升级影响(必读)

### `lance_scan_mode` 默认值变更:auto → pyarrow_fallback

`config/olap.py` `OlapConfig.lance_scan_mode` 默认从 `auto` 改为 **`pyarrow_fallback`**。

- **历史问题**:默认 `auto` 让 DuckDB native lance scanner 对带 IVF_PQ 向量索引的数据集执行 vector scan 时触发 Rust panic(SIGABRT,绕过 Python fallback,RAG 502 / worker 崩)。之前只在 `prod_minimal` compose 显式设 `pyarrow_fallback` 规避,config 默认未改。
- **现在**:所有部署默认安全。无向量列的结构化数据集由 per-dataset 逻辑自动加速(见下),不损失性能。
- **升级动作**:**无需任何操作**。若某部署曾依赖默认 `auto` 的行为并显式想要 native scan,需手动设 `ARROW_LAKE__OLAP__LANCE_SCAN_MODE=auto`(但仅对无向量索引的数据集安全)。

## 核心机制:per-dataset scan_mode

`arrow_lake/query/olap.py` `OlapSearchBridge._register_dataset`:

```
全局 mode = pyarrow_fallback(默认)
  ├─ source 无 fixed_size_list 向量列 → 临时 auto(native lance scan,下推 LIMIT/OFFSET)
  └─ source 有向量列 → 保持 pyarrow_fallback(避免 IVF_PQ panic)
```

`_has_vector_column(source)` 检查 Arrow source 的 schema 有无 `fixed_size_list` 列(项目向量列标准类型,`ingest/schema.py:59`)。纯增量,不改变 `auto`/`native` 模式原行为。
