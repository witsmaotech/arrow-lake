数据脱敏

读取路径上的列级隐私控制。四种脱敏函数、HMAC 签名、发布前预览、fail-closed 强制执行与审计闭环——对 VIEWER 透明，ADMIN 跳过。

难度 · 进阶 耗时 · 10 分钟 依赖 · HMAC_KEY（fail-fast）

脱敏由 MaskingEngine（arrow_lake/quality/masking_engine.py）治理，经 Gravitino 策略层 + 预览端点暴露。它启动时必须有 HMAC 密钥——缺失则服务拒绝启动。策略把敏感列映射到四种脱敏函数之一，对 VIEWER 角色透明强制执行，fail-closed，并经 Lance 审计轨迹记录。

1配置 HMAC 密钥（必需）

引擎对 hash 输出签名，并在密钥缺失时 fail-closed。启动 API 前必须设置密钥。

fail-fast

密钥缺失时，启动抛 RuntimeError，容器退出。仅开发环境可 opt-in 降级：ARROW_LAKE__MASKING__ALLOW_MISSING_KEY=1（此时 hash() 在调用时抛错）。

3发布前预览

在提交规则前用真实数据验证。返回前几行的脱敏前/后对比：

预览权限

预览为 ADMIN 专属（非 EDITOR），以防绕过列级 ACL；列名经标识符白名单校验以拒绝 SQL 注入。

4强制执行与 Fail-Closed

策略指向某数据集后，RBAC 层对 VIEWER/EDITOR 角色在读取时透明应用脱敏；ADMIN 角色完全跳过脱敏（返回原始数据）。

角色读取行为
VIEWER / EDITOR透明应用脱敏（返回脱敏后值）
ADMIN完全跳过脱敏（返回原始数据）
fail-closed

强制执行为 fail-closed：若脱敏引擎抛错（脱敏错误、hash 缺密钥、未知函数，或 Gravitino 故障拉取策略失败），查询返回空表，而非泄露未脱敏的源数据。未知函数名在策略创建时即被校验拒绝（HTTP 400）；即便漏网，执行时 _mask_column 仍会抛 ValueError 兜底。
