部署与运维

从 Docker Compose 全栈部署到 Prometheus 监控、备份恢复、安全加固与 Helm on Kubernetes——同一套引擎与配置，从笔记本到生产集群。

难度 · 高级耗时 · 30 分钟形态 · SDK / Compose / K8s

Arrow Lake 支持三种递进部署形态：嵌入式 SDK（进程内 Lake facade）、Docker Compose 全栈（profile 按需启服务）、Helm on Kubernetes（HPA 自动扩缩、NetworkPolicy、CronJob 备份）。同一份引擎与配置贯穿三者。

6踩坑提示

HPA 无 Redis 必崩

多副本不启用 Redis 时各 Pod 独立用进程内信号量，负载下 DuckDB 连接池耗尽；HPA 强依赖 redis.enabled: true。

安全默认

API 默认仅 127.0.0.1 绑定，远程访问须显式 api.host: 0.0.0.0 或走 Ingress；空 JWT 密钥拒绝启动，须配 32+ 字符随机密钥；Redis 默认密码已移除，生产必须显式配 REDIS_PASSWORD。

prod_minimal 现实部署（v1.9.6）

当前生产栈 docker-compose.prod_minimal.yml 共 11 服务：api / minio(+init) / nginx / lance-rest / hg-server(+hubble) / redis / system-db / gravitino(+init) / ollama-relay / proxy-forwarder。api 容器 read_only: true——改 Python 需 rebuild 或 dev.override 热重载；模型权重 bake 进镜像（HF_HUB_OFFLINE=1），离线即用。

WSL2 代理中继

WSL2 mirrored 网络下容器外网经 socat 中继：ollama 11534 / proxy 17887；NO_PROXY 必含 host.docker.internal + 内部服务名（minio / redis / hg-server…），否则内部调用误走代理。

CronJob 非幂等清理

每次备份生成带时间戳新备份，旧备份需单独 backup delete 清理，不会自动轮转。

v1.9.6 · system_db fail-closed + Masking HMAC

v1.9.0 起控制面（RBAC / 身份 / personal_token / catalog / 任务历史 / RAG 会话 / 血缘）迁移至独立 system-db 服务（libSQL / Turso sqld），deploy/.env 须设 SYSTEM_DB_ENABLED=true；store 不可达时 RBAC 读返 401 fail-closed（不放行；opt-in SYSTEM_DB_SERVE_STALE_ON_ERROR 会 honor 宕机期撤销的权限，慎用）。v1.9.6 masking 的 ARROW_LAKE__MASKING__HMAC_KEY 是纯环境变量（非 YAML 段），缺失则启动阻断（fail-fast，openssl rand -hex 32），仅 dev 可 ALLOW_MISSING_KEY=1 降级。

v1.9.6 · HugeGraph 堆 + drop 重启 / Gravitino proxy 中和

HugeGraph start 脚本自带 -Xmx32768m 与 compose JAVA_OPTS -Xmx2g 冲突，JVM 对重复 -Xmx 取末值→ 实际堆仅 2g 致稠密图遍历 OOM；修 HG_SERVER_MEMORY_LIMIT=12288M + JAVA_OPTS="-Xms2g -Xmx8g"，验证 ps -ef|grep -oE Xmx[0-9]+[mg] 应输出 Xmx8g。drop/clear 图后必须 restart hg-server（内存 schema 缓存不刷新否则 ensure_schema 报 500），一键 make kg-(drop|clear)-graph DS=<ds>（自动 restart + 等 healthy）。Gravitino 1.3.0 须在 compose 显式 HTTP(S)_PROXY: "" + NO_PROXY: "*" 中和 Docker daemon 注入的死代理，否则 s3a 经代理 → SigV4 被改 → minio 403 Forbidden。

v1.9.6 · docling GPU 热重载 / RAG hybrid 502 修复

docling GPU 叠 gpu.override.yml 重建即可切 CUDA；API_CPU_LIMIT 默认 1.0 是 PDF 渲染 / layout / 表格后处理的 CPU 侧瓶颈（552 页 / 1 核会超时崩），宿主多核设 API_CPU_LIMIT=8.0（约 5.4min / 552 页，接近 host）。改 arrow_lake/ Python 源码不必 rebuild——叠 dev.override.yml 挂源码 + uvicorn --reload，必须 --force-recreate（否则保留 prod command，新端点 404）。RAG hybrid 502（DuckDB lance scanner 对 IVF_PQ async vector stream 的 Rust panic，uvicorn worker died）修复：api env ARROW_LAKE__OLAP__LANCE_SCAN_MODE: "pyarrow_fallback"（绕 DuckDB path，性能略降但 RAG 通）。
