# v1.8.8 — KG per-dataset KA 抽取 + feed_text 跨 chunk 合并 + KA 目录落盘 方案

> 状态:📋 方案(v1.8.8 KG 第二阶段,待实现)。本方案是 `v1.8.8-kg-doc-type-template-plan.md` §7 "后续候选" 第 1 条(并发根因)的落地。
> 起因:hyper-extract 当前被当成"单 chunk 抽取器"在用 —— `HyperExtractExtractor` 对每个 chunk 新建 fresh KA 调 `.parse()`,完全绕过了 hyper-extract 的跨 chunk 合并/去重核心能力,且 KA 产物大部分被丢弃。这与 v1.8.7 芜湖全量 0 实体、v1.8.8 §7 并发根因是同一架构错位。
> 关联:`v1.8.8-kg-doc-type-template-plan.md`、`v1.8.6-per-dataset-kg-isolation-plan.md`、`v1.7.0-hyper-extract-kg-extraction-plan.md`、`issue_he_build_zero_entities.md`

---

## 1. 背景与目标

### 1.1 问题

当前 `HyperExtractExtractor.extract()`(he_extractor.py:155-245)对**每个 chunk 独立**走 `Template.create(path).parse(chunk_text)`(he_extractor.py:125-139),带来三个架构错位:

1. **跨 chunk 合并/去重全废**:hyper-extract 的 `merge_batch_data` + LLM 智能合并 + 悬空边裁剪(`_prune_dangling_edges`)都没激活。跨 chunk 同实体靠 HugeGraph `entity` 顶点的 `name` PRIMARY_KEY 精确 upsert 归并 —— "芜湖市城市生命线安全工程一期"与"芜湖一期工程"不会合并,实体爆炸/重复。
2. **KA 产物大部分丢弃**:只有 `nodes.name/type` + `edges.source/target/type` 进 HugeGraph;`nodes.description/properties`、`edges.description/keywords/strength/observation_date`、置信度、FAISS 索引、`data.json` 快照全部在 `extract()` 返回前丢弃(he_extractor.py:212-245)。legacy `EntityExtractor` 反而保留了 `properties`,he 后端更粗。
3. **架构错位放大故障**:v1.8.7 芜湖全量 0 实体的根因之一即此 —— fresh KA 在 `BUILD_CONCURRENCY=10` 并发下状态污染(`_chat_client` / hyper-extract `Template.create` / `ka.parse` 的并发安全性),叠加 doc_type 路由到 hypergraph 模板时 `merge_batch_data` 对空 nodes 抛 `IndexError`,单 chunk 故障被放大成全量空(v1.8.8 §7 第 1 条)。

### 1.2 目标

让 hyper-extract 回归设计意图(每文档一个 KA,内部自动分块+并行+合并):

1. **per-dataset 一个 KA**:dataset 下所有 chunk `feed_text` 进**同一个** KA 实例,激活 `merge_batch_data` 的跨 chunk 实体去重 + LLM 字段富化合并 + 悬空边裁剪。消除 fresh KA per chunk 的并发状态污染(直接解决 v1.8.8 §7 并发根因)。
2. **合并策略 LLM.BALANCED**:用 hyper-extract 默认的 LLM 智能合并(质量优先,接受慢)。
3. **保留领域 template 路由**:`doc_type_router` 机制不动,doc_type 粒度从 per-PDF 提升为 per-dataset(整 dataset 一个 template、一个 KA)。
4. **KA 目录落盘**:`<base_uri>/<dataset>/ka/`(`data.json` + `metadata.json` + FAISS `index/`),作为 HugeGraph 之外的第二套自包含知识库,支持 `he search/talk/show` + MCP 复用。完整产出(description/properties/索引/快照)不再丢弃。

### 1.3 非目标

- **不改 HugeGraph schema**(8 顶点/9 边,`entity` 只有 `name/type`)。完整产出靠 KA 目录 `data.json` 解耦,HugeGraph 仍只存图遍历子集。
- **不切 itext2kg_star method / SemHash 语义去重**。保留领域 template 的 prompt 价值;"Tesla vs Nikola Tesla"跨别名归并非本方案目标(与 per-chunk 行为一致,无回归)。
- **不砍 legacy `EntityExtractor`**。保留 `extractor_backend="legacy"` 与 `he_kg_granularity="chunk"` 双开关做对照/降级。
- **不做 Lake facade 的 `kg_ka_search`/`kg_ka_chat` 包装**(后续 Phase 2)。

## 3. 设计基石(已读 hyper-extract 源码确认)

1. **AutoGraph 默认 merger = `MergeStrategy.LLM.BALANCED`**(`.venv/.../hyperextract/types/graph.py:164-167`,`node_strategy_or_merger` / `edge_strategy_or_merger` 形参默认值)。`feed_text` → `_update_data_state`(`types/graph.py:430-445`)→ `OMem.add`(`ontomem/core/omem.py:342-422`)→ L402 `self._merger.merge`;L386-388 **key 已存在时把现有 item 拉进 merge 集合** → 同名实体跨 chunk 真正触发 LLM 字段富化合并。**用户要的 LLM.BALANCED 是开箱默认,无需 hack**。实现时显式传 `node_strategy_or_merger="llm_balanced", edge_strategy_or_merger="llm_balanced"` 做 belt-and-suspenders(防未来领域 YAML 加 `options.merge_strategy` 降级)。
2. **"Tesla vs Nikola Tesla 不合并"是 `node_key_extractor` 按 name 精确分桶**(跨别名),不是 merger 限制。与 per-chunk fresh KA 行为完全一致,**无回归**。
3. **`Template.create(source, language, llm_client=, embedder=, **kwargs)`**:`embedder` 形参类型 = `langchain_core.embeddings.Embeddings`(**不是**项目的 `LocalEmbeddingEncoder`)。当前 he_extractor.py:137 硬编码 `embedder=None`,触发 hyper-extract 回退全局 `get_client()` 读 `~/.he/config.toml`(不可控)。
4. **KA 全生命周期 API**:`ka.feed_text(t)` 原地增量(self,链式)、`ka.build_index()` 建 FAISS、`ka.dump(dir)` 写 `data.json`+`metadata.json`+`index/`、`ka.load(dir)` 恢复。全同步阻塞 → async builder 里一律 `asyncio.to_thread`。`feed_text` 后索引失效,需 `build_index` 重建。
5. **embedder 配置来源**:`ArrowLakeConfig.embedding`(`config/media.py:37-78`,`EmbeddingConfig`:model/model_source/backend/api_base/api_key/batch_size/expected_dim/daft_*)。ingest 三分支构造参照 `_lake_ingest.py:731-780`(DAFT→`DaftBatchEncoder`、OPENAI→`ApiEmbeddingEncoder`、else→`LocalEmbeddingEncoder`)。**无全局 encoder 工厂**。
6. **extractor 切换 + 单例**:`HugeGraphConfig.extractor_backend`(`config/rag.py:153`,默认 `"he"`),走 `Lake._get_component`(`__init__.py:143-149`)Lake 级懒加载单例。
7. **doc_type_router/classifier 已就绪**,无需改:`DocTypeRouter.resolve(doc_type)->template_path`、`.default_template()`、`DocTypeClassifier.from_llm_config(llm_config)`。
8. **`HugeGraphConfig` 在 `config/rag.py`**(非 storage.py)。已含 `he_default_template="general/concept_graph"`、`he_doc_type_templates`、`he_language="zh"`、`he_model=None`。**无 embedder 字段**(embedder 走独立的顶层 `EmbeddingConfig`)。

## 4. AutoGraph vs HugeGraph:两套图的职责边界

改造后项目会同时存在两套"图":hyper-extract 的 **AutoGraph**(KA 内部)+ **HugeGraph**(图数据库)。它们不是冗余,而是流水线上下游 + 互补的查询能力。

### 4.1 能力对比

| 维度 | AutoGraph(KA 内部) | HugeGraph |
|---|---|---|
| 定位 | LLM 抽取产物 + 自包含知识库 | 生产级图数据库(OLTP 图遍历) |
| 存储 | 文件目录(`data.json` + FAISS `index/`) | RocksDB 服务化,per-dataset graph `kg_{ds}` |
| **抽取** | **内置**(`feed_text` + LLM.BALANCED 跨 chunk 合并)★ | 无(靠外部喂) |
| **查询** | 语义检索(FAISS 余弦)+ RAG 问答(chat) | **Gremlin 图遍历**(最短路径/多跳邻居/模式匹配)★ |
| 规模 | 单机内存,千~万节点(大语料 dump/load 分批) | 分布式,亿级顶点/边 |
| 事务/并发 | 无(append-only 增量合并) | ACID + 多用户并发 |
| Schema | Pydantic 软校验 + 悬空边裁剪 | 强 schema(8 顶点/9 边,PRIMARY_KEY + 二级索引) |
| 消费 | `he search/talk/show` + MCP(Claude/IDE) | Gremlin REST + 项目 REST API |

★ = 独有、不可替代的能力。

### 4.2 为什么并存(各自不可替代)

- **只留 AutoGraph**:失去 Gremlin 图遍历 / 生产规模 / 强 schema / 多用户并发。芜湖场景"桥梁监测系统 → 关联传感器 → 历史报警"这种**多跳精确遍历**做不了(AutoGraph 只能语义检索,不能按边类型遍历)。
- **只留 HugeGraph**:失去 LLM 抽取/合并 / 语义检索 / RAG 问答 / 自包含可移植。回到现状(每 chunk 独立抽、无合并、KA 产物丢弃)。

### 4.3 新架构职责边界

```
LanceDB(chunks + chunk 级向量,检索回原文)
    │ feed_text(每 dataset 一个 KA)
    ▼
AutoGraph KA ── 抽取 + 跨 chunk LLM.BALANCED 合并(独有)
              ── FAISS 语义检索(实体/边级,he search)
              ── RAG 问答(he talk/chat)
              ── dump → <base>/<ds>/ka/(自包含,MCP/Obsidian 可移植)
    │ ka.nodes / ka.edges(合并后的干净产物)
    ▼
HugeGraph kg_{ds} ── Gremlin 图遍历(最短路径/多跳/模式匹配,独有)
                   ── 生产规模/并发/事务
                   ── 强 schema 索引(8 顶点/9 边)
```

**AutoGraph = 抽取+合并+语义检索+RAG;HugeGraph = 图遍历+生产规模+强 schema**。AutoGraph 的产物是 HugeGraph 的输入。三套检索(LanceDB chunk 级向量、KA FAISS 实体级向量、HugeGraph Gremlin 图遍历)粒度与能力不同,互不冲突。

## 5. 设计详情

### 5.1 改动 1 — embedder 适配器(新文件 `arrow_lake/knowledge_graph/_he_embedder.py`)

`_LakeEmbedderAdapter(langchain_core.embeddings.Embeddings)` 包项目的 `LocalEmbeddingEncoder`/`ApiEmbeddingEncoder`/`DaftBatchEncoder`,实现 `embed_query(text)->list[float]` + `embed_documents(texts)->list[list[float]]`。

- `ApiEmbeddingEncoder` 有干净的 `encode(list[str])->EmbeddingBatch`(`encoder.py:345`);`LocalEmbeddingEncoder` 走 `encode_to_vectors`(Arrow 表)。adapter 按能力分发。
- **保证与 LanceDB 向量索引同模型同维度**(复用 `EmbeddingConfig`,非 hyper-extract 自建)。
- 实现第一步:Read `arrow_lake/embed/encoder.py` 精确确认 `encode`/`encode_to_vectors` 签名,按实际接口写 adapter。
- 可选简化:给 `LocalEmbeddingEncoder` 加 `encode(list[str])->EmbeddingBatch` 薄方法(镜像 `ApiEmbeddingEncoder`),adapter 不必判类型。

```python
class _LakeEmbedderAdapter(Embeddings):
    def __init__(self, encoder): self._encoder = encoder
    def embed_documents(self, texts: list[str]) -> list[list[float]]: ...
    def embed_query(self, text: str) -> list[float]:
        return self.embed_documents([text])[0]
```

### 5.2 改动 2 — `he_extractor.py`

- `__init__(..., embedder=None, kg_granularity="dataset")`:存 `self._embedder`、`self._kg_granularity`。
- 抽 `_ka_to_extraction_result(ka, raw_text="")` 静态方法:把 he_extractor.py:212-245 的 nodes/edges→`ExtractionResult` 转换(stopword filter + endpoint validity)提成复用,`extract` 与 `build_dataset_ka` 共用。
- 新增 `DatasetKA` dataclass:`ka`, `ka_dir`, `entity_chunks: dict[str,list[str]]`(name→[chunk_id] 溯源), `result: ExtractionResult`。
- 新增 `build_dataset_ka(template_path, chunks: list[tuple[str,str]], ka_dir: Path, *, checkpoint_every=20) -> DatasetKA`:

```python
ka = Template.create(
    template_path, self._language,
    llm_client=self._get_chat_client(), embedder=self._embedder,
    node_strategy_or_merger="llm_balanced", edge_strategy_or_merger="llm_balanced",
)
entity_chunks: dict[str, list[str]] = {}
for i, (cid, text) in enumerate(chunks):
    before = {getattr(n, "name", "") for n in (ka.nodes or [])}
    try:
        await asyncio.to_thread(ka.feed_text, text.strip())
    except Exception as exc:
        logger.warning("feed_text failed chunk %s, skipped: %s", cid, exc)
        continue   # 单块失败跳过,不切模板(schema 撕裂禁忌)
    after = {getattr(n, "name", "") for n in (ka.nodes or [])}
    for name in after:                       # 新增 + 重现都记溯源
        entity_chunks.setdefault(name, []).append(cid)
    if checkpoint_every and (i + 1) % checkpoint_every == 0:
        await asyncio.to_thread(ka.dump, ka_dir)   # §9 大语料 checkpoint
if not ka.empty():
    await asyncio.to_thread(ka.build_index)
await asyncio.to_thread(ka.dump, ka_dir)
return DatasetKA(ka=ka, ka_dir=ka_dir, entity_chunks=entity_chunks,
                 result=self._ka_to_extraction_result(ka))
```

## 8. 风险/取舍

- **LLM.BALANCED 性能**:`feed_text` 在实体跨 chunk 重复出现时触发额外 LLM 合并调用(首次出现不触发)。芜湖场景项目/子系统/技术实体高频跨 chunk,会有可观额外调用。用户已选质量优先。`he_kg_granularity="chunk"` 可降级回精确 upsert。
- **大 dataset 内存**:`feed_text` 累积所有节点常驻内存;checkpoint dump 只防崩溃不释放内存。千 chunk 级安全,万级以上需评估(可加分批 dump+load 续建)。
- **溯源精度**:`entity_chunks` 基于 name diff,与 `node_key_extractor` 精确匹配一致;别名场景漏记(可接受,无回归)。
- **template 中途切换禁忌**:dataset 级 KA 必须单一 template;单块失败只能跳过不能切模板(已设计)。
- **embedder 模型变更**:若 config 切换 embedding 模型,KA 索引需重建(`load` 后检测维度不匹配强制 `build_index`)。
