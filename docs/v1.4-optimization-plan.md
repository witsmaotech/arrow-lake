### 0.2 DuckDB Relational API 试点 ✅

**目标**：在简单查询场景用类型安全的链式 API 替代字符串拼接 SQL，减少注入风险。

**修改文件**：

| 文件 | 修改内容 |
|------|----------|
| `arrow_lake/query/metadata.py` | 新增 `_relational_query()` 私有方法 |

**实现细节**：
- 仅用于 schema discovery 类查询（列出表名、列信息），保持向后兼容
- 示例：
  ```python
  def _relational_query(self, conn, table_name: str, columns: list[str], where: str | None = None):
      rel = conn.table(table_name)
      if where:
          rel = rel.filter(where)
      return rel.select(*columns).arrow()
  ```
- 复杂 SQL 查询（JOIN、子查询、聚合）仍保持字符串拼接
- 后续版本根据试点效果决定是否扩展

**验证**：
- 单元测试：验证 Relational API 查询结果与 SQL 查询等价
- 安全测试：验证无法通过 Relational API 注入

### 1.4 Daft 原生媒体处理迁移 ✅

**目标**：利用 Daft 原生 Rust 实现的图像/视频处理能力，替代 PIL/Pillow 和直接 PyAV 调用，提升性能并简化依赖。

#### 依赖迁移矩阵

| 能力 | 当前实现 | Daft 原生替代 | 可移除依赖 |
|------|----------|---------------|------------|
| 图像解码 | PIL `Image.open()` | `daft.functions.decode_image()` | Pillow（部分） |
| 图像编码 | PIL `Image.save()` | `daft.functions.encode_image()` | Pillow（部分） |
| 图像缩放 | PIL `Image.thumbnail()` | `daft.functions.resize()` | Pillow（部分） |
| 缩略图生成 | PIL resize + encode | Daft `resize()` + `encode_image()` | Pillow（部分） |
| 感知哈希 | 自定义 pHash | `daft.functions.image_hash()` (8种算法) | 自定义代码 |
| 图像属性 | PIL `img.size/mode` | `image_width/height/mode()` | Pillow（部分） |
| 视频帧读取 | PyAV 直接调用 | `daft.read_video_frames()` | PyAV 直接使用 |
| 视频元数据 | PyAV `stream.duration` | `daft.functions.video_metadata()` | PyAV 直接使用 |
| 视频关键帧 | PyAV 解码循环 | `daft.functions.video_keyframes()` | PyAV 直接使用 |
| EXIF 提取 | PIL `img.getexif()` | **Daft 不支持** | 保留 Pillow |
| 场景检测 | PyAV + NumPy 直方图 | **Daft 不支持** | 保留 NumPy |

#### 保留的最小依赖

- **Pillow**：仅用于 EXIF 提取（GPS、相机型号、拍摄时间）
- **PyAV**：仅用于场景检测的帧级访问（直方图比较）
- **NumPy**：仅用于场景检测的直方图计算

#### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `arrow_lake/ingest/media.py` | 重写 `ImageProcessor`：decode/resize/encode 改用 Daft 原生 |
| `arrow_lake/ingest/media.py` | 重写 `VideoProcessor`：关键帧提取改用 `daft.functions.video_keyframes()` |
| `arrow_lake/quality/dedup.py` | 感知哈希改用 `daft.functions.image_hash()` |
| `arrow_lake/ingest/ingest_embed.py` | 批量嵌入管线适配 Daft 原生图像列 |

#### ImageProcessor 重写方案

```python
# 改造前 (PIL)：
img = Image.open(io.BytesIO(original_bytes))
img.thumbnail((size, size), Image.Resampling.LANCZOS)
buf = io.BytesIO()
img.save(buf, format="JPEG", quality=85)
return buf.getvalue()

# 改造后 (Daft 原生)：
import daft
df = daft.from_pydict({"bytes": [original_bytes]})
df = df.with_column("image", daft.functions.decode_image(df["bytes"]))
df = df.with_column("resized", daft.functions.resize(df["image"], size, size))
df = df.with_column("jpeg", daft.functions.encode_image(df["resized"], format="JPEG"))
return df.to_pydict()["jpeg"][0]
```

**注意**：单张图片处理不产生 Daft 分布式优势。实现策略：
- **单张模式**：保留 PIL 路径（仅 EXIF），Daft 用于批量
- **批量模式**（`ingest_images` 路径）：全部使用 Daft DataFrame 管线，一次 decode→resize→encode 整批处理
- 新增 `_process_image_batch()` 方法：接收 bytes 列表，返回 Daft DataFrame

#### VideoProcessor 重写方案

```python
# 改造前 (PyAV 直接)：
container = av.open(str(path))
for frame in container.decode(stream):
    arr = frame.to_ndarray(format="rgb24")
    # 手动场景检测...

# 改造后 (Daft)：
import daft
# 关键帧提取
df = daft.read_video_frames(str(path), image_height=self.keyframe_size)
# 场景检测仍需自定义（Daft 不提供）
# 但帧读取和缩放由 Daft 原生处理，无需 PyAV 解码循环
```

**实现策略**：
- `extract_keyframes()` 改用 `daft.read_video_frames()` 获取帧 DataFrame
- 场景检测保留直方图比较逻辑，但输入从 PyAV 帧改为 Daft 返回的 numpy 数组
- `_frame_to_jpeg()` 改用 Daft `encode_image()`
- 视频元数据改用 `daft.functions.video_metadata()`

#### 感知哈希迁移

```python
# 改造前 (quality/dedup.py 自定义 pHash)：
```

**规则定义格式**（JSON/YAML）：
```yaml
rules:
  - name: reject_short_text
    column: text_content
    check: length < {min_chars}
    params: {min_chars: 10}
    action: reject
    message: "文本过短（<{min_chars}字符）"
    
  - name: flag_low_quality_image
    column: image_width
    check: value < {min_width}
    params: {min_width: 100}
    action: flag  # 不拒绝，仅标记
    
  - name: dedup_content
    column: text_content
    check: exact_hash_duplicate
    action: remove
```

**QualityRuleEngine** 支持：
- 4 种检查类型：`length`, `range`, `regex`, `duplicate`
- 3 种动作：`reject`（拒绝）, `flag`（标记）, `remove`（去重）
- 自定义消息模板
- 从文件或 API 加载规则集

**ACL 定义**：
```python
@dataclass(frozen=True)
class DatasetACL:
    dataset: str
    role: Role
    # 列级：可见列白名单（空 = 全部可见）
    visible_columns: frozenset[str] = frozenset()
```

**实现策略**：
- 列级：查询后裁剪，搜索后移除不可见列

- 管理端点：
  - `PUT /api/v1/admin/acl/{dataset}` — 设置 ACL 规则（ADMIN）
  - `GET /api/v1/admin/acl/{dataset}` — 查看 ACL（ADMIN）
  - `DELETE /api/v1/admin/acl/{dataset}/{role}` — 删除 ACL（ADMIN）

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| DuckDB 多实例 Redis 信号量竞争 | 查询超时 | 渐进扩展（1→2→3），监控 `queued_requests` |
| 大文件拆分引入导入断裂 | 测试失败 | 拆分后全量回归，保持公共 API 不变 |
| 行级 ACL 注入 WHERE 条件性能影响 | 查询变慢 | ACL 条件缓存 + 简单谓词下推到 Lance |
| GPU Autoscaling 实测需要真实负载 | 无法验证 | 使用 benchmark 测试套件模拟负载 |
| Relational API 试点范围蔓延 | 超出预期 | 严格限制为 schema discovery，复杂查询不改 |
| Daft 媒体迁移兼容性 | 图像/视频结果不一致 | 像素级等价测试 + 保留 PIL 回退路径 |
