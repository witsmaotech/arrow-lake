混合搜索与分面搜索

RRF 融合向量搜索 + 全文搜索实现混合检索；DuckDB CUBE 实现分面导航；加权 RRF 实现多列 Ensemble 搜索。三类进阶检索一次讲清。

难度 · 进阶 耗时 · 12 分钟 依赖 · 向量索引 + FTS 索引

本章把混合搜索（RRF 融合向量 + 全文）、分面搜索（向量召回 + DuckDB CUBE 维度计数）与 Ensemble 多列搜索（加权 RRF 融合多 embedding 列）串联起来，并给出搜索策略选择指南与 REST API。

2RRF 融合原理

Reciprocal Rank Fusion 在 HybridSearchBridge._rrf_fuse() 中实现：

  • rank(doc, list_i)：文档在第 i 个排序列表中的排名（从 1 开始）
  • k：平滑常数，默认 60（论文推荐值）
rrf_k效果推荐场景
30–50高排名结果权重更大重视精确匹配
60（默认）平衡融合通用推荐
100–200排名差异被拉平重视多样性

注意

重排是配置驱动，非请求参数：reranker_type / reranker_model 在 HybridSearchConfig 中全局设定，搜索端点（POST /{name}/search/hybrid）不接受 per-request 重排参数。设为 cross_encoder 时用 reranker_model（默认 BAAI/bge-reranker-v2-m3）对 RRF 粗排结果做连续分精排。

5Ensemble 多列搜索

ensemble_search 在多个 embedding 列上执行向量搜索，通过加权 RRF 融合。适用于多模态 embedding 场景。

API 签名

不指定 columns 时自动检测所有与查询向量维度匹配的 fixed_size_list 列。

加权 RRF 公式：score(doc) = SUM( weight_i / (rank(doc, list_i) + k) )

6搜索策略选择指南

策略对比

策略API输入适用场景
向量搜索lake.search()embedding 向量语义检索、RAG、相似推荐
全文搜索lake.text_search()文本字符串精确关键词、标识符搜索
混合搜索lake.hybrid_search()向量 + 文本兼顾语义和关键词

场景推荐

业务场景推荐策略原因
