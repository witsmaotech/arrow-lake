## 16.1 CLIP 跨模态检索（#6）

用 CLIP/SigLIP 的 **text tower** 把文本查询编入与图像相同的嵌入空间，实现文搜图。

```python
qvecs = lake.encode_text_clip(["a cat sitting on a sofa"], model="openai/clip-vit-base-patch32")
hits = lake.search("photos", qvecs[0], vector_column="image_embedding", top_k=5)
```

> 签名：`encode_text_clip(texts, *, model=None, model_source="huggingface") -> list[list[float]]`。需预先有含 `image_embedding` 列的数据集（用 `CLIPImageEncoder.encode` 摄入）。

## 16.2 Lance 数据集 branches（#1）

数据集像代码一样打 tag、开 branch，支持 A/B、回滚、可复现训练。

```python
lake.create_branch("docs", "experiment-a")          # 默认从 HEAD
lake.create_branch("docs", "v1.8-baseline")
lake.list_branches("docs")                          # → ['experiment-a', 'v1.8-baseline']
head = lake.read_at_branch("docs", "experiment-a")  # 读 branch HEAD
lake.delete_branch("docs", "v1.8-baseline")
```

> 签名：`create_branch(dataset_name, branch, version=None)`、`list_branches(dataset_name) -> list[str]`、`read_at_branch(dataset_name, branch)`、`delete_branch(...)`。本地 Lance 即可跑，无需额外服务。

## 16.3 blob 存储（#2）

把 image/audio/video 的**原始字节**原地存为 Lance binary 列，与嵌入同库——省一次 IO，多模态一致性更好。

```python
lake.add_blob_column("docs", "image_bytes", [png_bytes_1, png_bytes_2, png_bytes_3])
```

> 签名：`add_blob_column(dataset_name, column_name, blobs: list[bytes]) -> None`。底层经 `add_columns_table` 追加 binary 列。

## 16.4 `hf://` 数据集（#8）

用 lancedb 的 `hf://` scheme 直接读 HuggingFace 上的 Lance-format 数据集——评测/种子数据一键加载。

```python
tbl = lake.load_hf_dataset("lance-format/quora-duplicates-embedding-bge-small", table="quora")
```

> 签名：`load_hf_dataset(repo_id, *, table=None)`。需联网；空表/不可达会 raise。

## 16.5 VLM decode_image 变换（#18）

`decode_image` 是注册到 `build_transforms` 的 builder，补全 VLM 链：image bytes → 解码 → `classify_image` / `prompt`。

```python
from arrow_lake.ingest.transforms import build_transforms

transforms = build_transforms({"decode_image": {"column": "image_bytes"}})
lake.ingest("ds", file_paths, transforms=transforms)   # 摄取期自动解码
```

## 16.6 Gravitino 统一 catalog facade（#19）

把数据集注册到 Gravitino（Table + Fileset），让 DuckDB / Daft / lancedb 三引擎都经 Gravitino 解析——真正的联邦 catalog。

```python
lake.gravitino_register_dataset("docs")     # 注册到 Gravitino
stats = lake.table_statistics("docs")       # 统计
```

> 签名：`gravitino_register_dataset(dataset_name, *, location="")`。需 Gravitino 在运行。

## 16.7 Daft ↔ Gravitino（#14）

Daft 用 `daft.io.GravitinoConfig` 直连 Gravitino 表，联邦查询不经 DuckDB 转译。

```python
df = lake.daft_from_gravitino("docs", url="http://localhost:8090", metalake="arrow_lake")
df.collect()   # lazy，触发执行
```

> 签名：`daft_from_gravitino(table_name, *, url, metalake)`。

## 16.8 行级 lineage（#3）

在事件级血缘之上叠加 Lance `row_id` 行级溯源——精确到"这一行从哪几行派生来"。

```python
lake.lineage_record_row(
    "docs", row_id=2,
    source_rows=[{"dataset": "raw_docs", "row_id": 42}],
    operation="derive",
)
```

> 签名：`lineage_record_row(dataset_name, row_id, *, source_rows=None, operation="derive")`。经现有 lineage store / query / graph 可查。

## 16.9 Daft 流式写（#16）

Daft lazy DataFrame 直接写 Lance，跳过 Arrow 中转，处理超内存负载（>16×）。

```python
import daft
df = daft.from_pydict({"id": [10, 11], "text": ["流式写", "超内存友好"]})
lake._get_storage().write_lance_from_dataframe("docs_daft", df, mode="create")
```

> 签名：`write_lance_from_dataframe(name, df, mode="create")`（`LanceStorageManager`）。KG build / 大批量 ingest 推荐。

## 16.10 全链路 async 检索（#17）

向量 `search_async` 走 lancedb 原生 `connect_async`（GIL-free）；fts / hybrid / faceted 的 `*_async` 是 `asyncio.to_thread` 线程卸载——async handler 不阻塞事件循环。

> **v1.8.x 更新（#1）**：向量 `search_async` 的 `AsyncConnection`/`AsyncTable` 句柄现已进程级池化（`async_conn_pool.py`），消除每次调用的连接建立开销；并修复了 v1.7.1 起遗留的 `AsyncTable.search` 缺 `await` 缺陷（此前 `search_async` 实际一调即崩、不可用）。

```python
res = await lake.search_async("docs", query_vec, top_k=10)          # 向量（原生 async + 连接池）
res = await lake.text_search_async("docs", "数据湖仓", top_k=5)      # FTS
res = await lake.hybrid_search_async("docs", query_vec, "Lance", top_k=5)
res = await lake.faceted_search_async("docs", query_vec, facets=["category"], top_k=10)
```

> 签名：`async text_search_async(dataset_name, query, *, top_k=None, fts_column=None, ...)` 等。FTS 需先 `create_fts_index`。

## 16.11 日文分词 lindera（#4）

FTS 多语言分词：在日文场景接入 lindera 假名分词（模块级缓存 + 优雅降级）。

```python
# 经 FullTextSearchConfig 分词器配置启用，或建索引时指定（若 build 支持）
lake.create_fts_index("docs_ja", fts_column="text", tokenizer="lindera")
```

> lindera 是可选依赖；未装时自动降级到默认分词器，不报错。

## 16.12 压测 DEFER 的两项（诚实记录）

- **#15 分布式索引**：单节点 21s/1M，1B+ 行才需 Ray 分布式 backfill（`ray_runtime` 基建已就绪待触发）。
- **#7 ColBERT/colpali**：现实 recall 96%，病态下降源于 IVF_PQ 量化（修法是 HNSW，非 ColBERT 场景）。

复测：`tests/benchmark/test_bench_batch3_gates.py`，数据规模/特征变化后重跑即可重评。

## 16.13 前置条件与已知限制（实跑前必读）

本节 demo 在缺模型/外部服务时优雅 SKIP。要真正端到端跑通，注意：

| 能力 | 前置条件 | 已知限制 |
|---|---|---|
| **§16.1 CLIP** | 需联网下载 CLIP 权重（首次），HF 镜像需 `HF_TOKEN` | 无 |
| **§16.4 hf://** | 需 `HF_TOKEN`（HF 返回 401 "Invalid username or password"） | 无 |
| **§16.5 VLM decode** | `build_transforms` 签名是 **`list[dict]`**（非单 dict）；真实图像需 Daft image decode | 无（示例已用 list 形参） |
| **§16.7 Daft↔Gravitino** | 需 Gravitino 运行 | ⚠️ **facade bug**：`daft_from_gravitino` 把 `url=` 传给 `daft.io.GravitinoConfig`，而该 PyO3 类不接受 `url` kwarg → `TypeError`。需改 facade 用正确字段名（待修） |
| **§16.9 Daft 流式写** | 需 Daft | ⚠️ **facade bug**：`write_lance_from_dataframe` 调 `df.write_lance(uri, mode=...)` 但 Daft 是 lazy，**结果未 `.collect()` 触发** → 写入静默丢弃（`list_datasets` 为空）。修法：`df.write_lance(...).collect()`（待修） |

> 两个 ⚠️ **已在 v1.8.1 修复**：`daft_from_gravitino` 改用 `GravitinoConfig(endpoint=, metalake_name=)`；`write_lance_from_dataframe` 加 `.collect()` 并改用 `_lance_dir`（`.lance` 路径）—— Daft 写现已 `list_datasets` 可见、可读回。VLM spec 用 `{"op":"decode_image",...}`。CLIP / hf 仍需 `HF_TOKEN` / 模型下载。

## 16.14 v1.9.0 – v1.9.6 演进总览

v1.9 系列围绕**控制面统一、质量闭环、治理兑现**三条主线推进。各版本要点（详见对应 release 说明 `docs/arrow-lake-v1.9.*-release-zh.md`）：

### v1.9.0 — Turso/libSQL 统一控制面

把 RBAC / 身份 / personal_token / catalog / 任务历史 / RAG 会话 / 血缘索引从分散存储收敛到 **libSQL**（`system_db` 配置，`enabled` 默认关，生产置 true；store 不可达 fail-closed 返 401）。迁移 V001–V004 自动跑。新增 personal token 签发 `POST /admin/users/{id}/tokens` 与 `/me/*` 用户态（saved-queries / notifications / preferences / dashboards / favorites）。

### v1.9.1 — console 全页实施

console 全页真跑通：admin（users / ACL / deny）+ my-workspace 五区；personal token 经 `X-API-Key` 鉴权。

### v1.9.2 — 多模态深化 + OLAP

- **以图搜图**：`POST /embed/image`（CLIP/SigLIP，JSON `images:[base64]`）→ `/datasets/{name}/search/vector`。
- **导出统一**：`/datasets/{name}/export`（异步 202 + `output_path` 必填）+ `/export-to`（parquet/csv/json/iceberg/clickhouse）。
- **DuckLake 物化视图**：`/api/v1/materialized/*`（list/drop/cleanup，`ducklake_enabled` 默认关）。
- **Pivot 助手 + 纯 SVG 图表**（零 vendor 依赖）。

### v1.9.3 — 数据集字段注释

`field_comments`（PyArrow 直读 parquet/CSV sidecar + MySQL/PG 捕获）+ `POST /datasets/{name}/schema/annotate` → `SchemaField.comment`；`lake.update_field_comments(name, comments)`。

### v1.9.4 — 血缘 actor + KG 质量

- **血缘 actor 传递链**：ingest / delete 透传认证用户，history 响应含 actor。
- **KG `project_concept_graph`**（22 类型 + 14 关系，项目方案书）+ `MERGE_FIELD` 合并（替 BALANCED，非 LLM，消除内存爆炸）。

### v1.9.5 — RAG 质量全链路

- **`default_retrieval_strategy="hybrid"` 真生效**（v1.9.5 前是死配置，检索实际只走 FTS，向量索引 0 参与）。
- **faithfulness 校验**（lightweight `[n]` 引用校验，`enable_verification` opt-in，返 `verification.support_ratio`）。
- **GraphRAG 三路并行**（asyncio.gather，延迟 -40~50%）+ KA LRU 缓存。
- **reranker 三连修复** + **OllamaReranker 默认**（`rag.reranker="ollama"`，`dengcao/Qwen3-Reranker-0.6B:F16`）。
- **两阶段 LLM**（`rag.extract_llm` / `qa_llm`）+ `query_transform`（hyde/multi_query）。
- **存储**：`lance_cache_size` 本地读缓存 + 原始文件分 bucket（`s3_uploads_bucket`）。

### v1.9.6 — 治理兑现 + KG 性能 + 安全加固

- **血缘可视化** `console/lineage.html`（vis-network 列级血缘 + `max_nodes` 截断 + 节点点击查 `/lineage/history`）。
- **masking 治理**：4 函数（redact/hash/partial/nullify）+ **HMAC fail-fast**（缺 `ARROW_LAKE__MASKING__HMAC_KEY` 启动阻断）+ `POST /datasets/{name}/quality/mask-preview` + audit 复用 Lance（零新表）。
- **KG 质量/性能**：snap 编辑距离归一化 + `he_strict_definition` 严格过滤 + enum 解析；GraphRAG 三路并行 + `QuestionEntityCache` monotonic。
- **安全 fail-closed**：masking/RBAC `_apply_masking`/`_apply_row_filter`/`_fetch_rules` 全 fail-closed；lineage XSS 转义；Gravitino 写端点去 `?body=` URL param（PII 不入日志）。

> ⚠️ **生产必配**：`ARROW_LAKE__MASKING__HMAC_KEY`（fail-fast）；`system_db.enabled=true` + url。
