## 3. 特性详述

### #3 type 后处理过滤 ⭐ 阶段1首选
- **现状**：LLM 对 ddd 模板 type 枚举有 ~5% 残留非枚举值（"概念"等），P2.1 未能 100% 强制。
- **方案**：`he_extractor._to_extraction_result` 在 entity_type 赋值后，若 type ∉ 模板枚举则归"实体"（最通用 fallback）。从节点/模板拿合法枚举集。
- **验收**：HugeGraph entity.type 100% ∈ 枚举，"概念"残留 0%。

### #10 chunk/performance 调优
- **现状**：chunk_size=2048 / chunk_overlap=256 / max_workers=10 默认（hyper-extract BaseAutoType 默认）。
- **方案**：`HugeGraphConfig` 暴露 `he_chunk_size` / `he_chunk_overlap` / `he_max_workers`，按文档规模调（大文档降 max_workers 避限流，小文档提 chunk_size 减调用）。
- **验收**：config 可调；大文档吞吐提升、无 LLM 限流。

### #8 模板 validator 校验
- **现状**：项目模板手写，未系统校验。
- **方案**：套用 hyper-extract `he-template-validator` 4 层 checklist（通用/Graph/Hypergraph/Temporal-Spatial）+ auto-fix（relation_type→type、多语言纯度、字段数≤5）。可写脚本扫 `arrow_lake/knowledge_graph/templates/*.yaml`。
- **验收**：项目模板过 4 层校验，CI 可集成。

### #1 TemplateTypeSelector ⭐ 阶段2核心 ✅（核心）
- **现状**：doc_type 路由只选 graph 模板（concept_graph），无结构维度选择。
- **实现**：新模块 `template_type_selector.py`，6 类注册表（graph/temporal_graph/hypergraph/list/set/model），每类映射一个 gallery 默认模板。
  - 选择优先级：显式 `template_type` > 配置默认 `he_template_type` > 时序启发（content/doc_type 含 事件/流程/传记/timeline… → temporal_graph）> None（defer DocTypeRouter，保留旧行为）。
  - hypergraph 仍 opt-in + HIGH-RISK 警告（复用 issue_hypergraph_template_indexerror 保护）。
  - 集成：`he_extractor._resolve_template()` + `extract(template_type=)`；builder dataset 路径走 `_resolve_template`（吃 config 默认 + 时序启发）；config `he_template_type`；facade `_create_kg_extractor` 透传。
  - 测试 9 个（`test_template_type_selector.py`），全绿。
- **验收**：✅ 6 Auto-Type 可选（config `he_template_type` + per-call `extract(template_type=)`）；✅ 时序内容自动 temporal_graph；✅ hypergraph 降级保护。
- **遗留（薄层，后续）**：per-call `template_type=` 透传到 kg_build facade → builder（API `/kg/build` + CLI `--template-type`）。当前 config 默认 + 时序启发已覆盖核心；per-call 是薄 passthrough。

### #2 RAG 查询暴露 ✅
- **现状**：arrow_lake 入 HugeGraph 后查询走 HugeGraph REST。hyper-extract KA 的 `search()`/`chat()`（语义检索/RAG）**未暴露**。
- **实现**（commit `5cebf42` + `8384332` + 本批次）：
  - `he_extractor.search_ka/chat_ka`：load KA（读 metadata.json template → create-then-load）→ search/chat。
  - `_ensure_ka_index` 优化：`load()` 已从 dump `index/` 恢复 FAISS（hyper-extract `base.load` 证实），不再每次 query 重建 ~60s；仅缺失时 build，`except: pass` → logger.warning。
  - facade `_lake_kg.kg_search/kg_chat`：asyncio.to_thread 包 sync extractor + `_serialize_ka_item`（pydantic/`__dict__`）+ top_k clamp [1,50] + legacy extractor 降级 KGError。
  - API `POST /api/v1/kg/search` + `/ask`：per-dataset 读 ACL（`_enforce_read_acl`），VIEWER+，models `KGSearchRequest/Response`、`KGChatRequest/Response`。
  - 测试 13 个（facade 6 + router 3 + extractor 4），全绿。
- **验收**（`docs/cookbook/examples_busi3/` E2E）：jd_ddd（66 chunk）build 10min → KA **411 节点 / 100% definition** + HG 475 顶点/988 边。search 0.3–5s 召回相关概念、chat 1–2s 生成领域答案，extractor + facade 两路径全通。
- **对比**（`04_compare_rag_vs_graph.py`）：RAG 按意思召回 + 生成（FAISS over definitions）；HugeGraph 按字面 + 拓扑（邻居遍历 / 全局结构）。二者**互补非替代**——RAG 强在开放问题语义召回，图查询强在精确实体关系/路径。
- **遗留**：`chat_ka` 本版 `additional_kwargs['retrieved_items']` 未填（retrieval_count=0，答非空证明 context 已用），后续可从 `chat()` 回调取 retrieved。
- **运维坑（已入 CLAUDE.md）**：本机无直连外网，百炼（dashscope）**必须走代理** `HTTPS_PROXY=127.0.0.1:7887`；**勿**把 dashscope 放 NO_PROXY（→ 直连 Network unreachable → 0 实体 + build 24min timeout）。

### #7 增量 rebuild 调度 ✅（架构适配）
- **现状**：arrow_lake 的 `kg_build` 是**全量重建**（clear + re-feed 全 chunk + build_index + dump），无增量 feed 路径。故 plan 原始方案（"周 feed + 月 rebuild_index" + `he_rebuild_interval`）的"增量 feed"前提不成立——"feed 后 search/chat 反映新内容"已被全量重建 + `_ensure_ka_index`（query 时按需补建 index）覆盖。
- **实现（适配全量重建架构）**：补一个**轻量 index-only rebuild**，不重跑 LLM 抽取：
  - `he_extractor.rebuild_ka_index(ds)`：load dump → force `build_index()`（绕过 `_ensure_ka_index` 的"已加载"守卫）→ dump 回写。用于 index 损坏 / embedder 变更 / dump 早于 build_index 的低成本恢复。
  - facade `_lake_kg.kg_rebuild_index(ds)` + API `POST /api/v1/kg/rebuild-index`（EDITOR+，per-dataset 读 ACL）。
  - 测试 3 个（extractor rebuild + 无 dump 报错 + facade 委托），全绿。
- **验收**：✅ index-only rebuild 可用（无 LLM）；✅ 全量重建 + `_ensure_ka_index` 已保证 search/chat 反映新内容。原始 `he_rebuild_interval` 配置在无增量 feed 模型下 N/A，不引入（避免无用配置）。
- **运维建议**：日常用 `kg_build`（全量，LLM 重抽）；仅 index 问题时用 `kg_rebuild_index`（秒级，无 LLM）。

### #5 Obsidian 导出 ✅
- **现状**：hyper-extract `AutoGraph.export_obsidian()`（图→MD 笔记 + `[[wikilink]]`）未暴露。
- **实现**：
  - `he_extractor.export_ka_obsidian(ds, out_dir, *, vault_name, overwrite)`：load dump → `ka.export_obsidian(out_dir, ...)` → 返回 vault 路径 + 节点/边数。仅 Graph 系 KA 有关系（Record 系 list/set/model 导出无链接笔记）。
  - facade `_lake_kg.kg_export_obsidian(ds, out_dir=None, ...)`：`out_dir` 默认 `he_ka_base_dir/{ds}/obsidian/`（**服务端派生，避免调用方路径穿越**）。
  - API `POST /api/v1/kg/export-obsidian`：VIEWER+ 读 ACL；**不接受调用方 out_dir**（请求体只有 dataset/vault_name/overwrite，路径服务端定）。
  - 测试 4 个（extractor 导出/无 dump + 不泄露路径；facade 委托 + 服务端默认路径），全绿。
- **验收**：✅ per-dataset KA 一键导出 Obsidian vault（MD 笔记 + wikilink，可在 Obsidian 图谱视图漫游）；✅ 路径穿越安全（API 无调用方路径）。
- **安全（本批次顺带修 #7 commit review 3 项）**：① `/rebuild-index` 提权 ADMIN（与 `/build` 一致，KG 状态变更同权限）；② 去掉读 ACL/action 不匹配（mutation 不该用 read gate）；③ `rebuild_ka_index`/`export_ka_obsidian` 的 FileNotFoundError 不再泄露文件系统路径（改 logger.warning 记完整路径 + 抛净化消息）。

### #4 method 等价模板
- **现状**：method 路径 broken（`Template.create("method/xxx")` 报 node_schema 错，memory `issue_hyperextract_method_path_broken`）。atom（时序事实+证据+置信度）等能力未用。
- **方案**：method 能力走等价模板（atom≈temporal_graph、itext2kg≈graph、hyper_rag≈hypergraph）。依赖 #1 TemplateTypeSelector 暴露 temporal_graph 后，atom 的时序事实能力可用。
- **验收**：时序文档抽 time + 证据归因（atom 特性）。
- **风险**：依赖上游 method 路径修复，或永久走等价模板。

### #9 多领域模板扩展 ✅
- **现状**：项目模板系统只有 ddd_concept_graph；medicine/legal/finance doc_type 被 gallery 自动匹配到 hyper-extract 预设（medicine/anatomy_graph 等，自由类型 + optional description → 质量瓶颈）。
- **实现**：新增 3 个项目模板（镜像 ddd 结构，各自 type/relation 严格枚举 + 必填定义）：
  - `medical_concept_graph.yaml`：type 疾病/症状/药物/检查/治疗/解剖/病因/指标；rel 导致/治疗/缓解/禁忌/位于/并发/诱发/属于。
  - `legal_concept_graph.yaml`：type 法条/罪名/主体/权利/义务/行为/客体/程序；rel 触犯/规定/适用/禁止/属于/导致/保护/依据。
  - `finance_concept_graph.yaml`：type 指标/产品/机构/风险/资产/交易/政策/事件；rel 影响/属于/导致/构成/投资/持有/相关/反映。
  - 路由：`he_doc_type_templates` 加 medicine/legal/finance/ddd override；`DocTypeRouter._resolve_override_path` 把裸名（`medical_concept_graph`）解析为项目模板绝对路径（避免硬编码机器相关路径）。
  - validator 4 模板全 PASS（仅 INFO：snake_case 命名 + zh 含英文词，同 ddd，非阻塞）。
  - `_get_type_enum` 正确解析 4 模板 type 枚举 → #3 后置过滤对全部领域生效。
  - 测试 4 个（`test_domain_templates.py`），全绿。
- **验收**：✅ doc_type=medicine/legal/finance → 对应项目模板（override，确定性，不再落到预设）；✅ 多领域 type 规范（严格枚举）。

### #11 KA 版本管理 ✅
- **现状**：per-dataset KA 单版本（dump 覆盖），rebuild 丢历史。
- **实现**：`ka_versioning.py` 版本归档层（active dump 路径不变，版本为 add-on）：
  - 每次 `kg_build`（dataset 路径）前 `archive_current` 把当前 dump 归档到 `<base>/<ds>/ka/versions/v{ts}/` + `manifest.json`；build 后按 `he_ka_max_versions`(默认 5) `prune`。
  - facade `kg_list_ka_versions` / `kg_rollback_ka(version)` / `kg_prune_ka_versions(keep)`；API `GET /kg/ka-versions/{ds}` (VIEWER+) + `POST /kg/ka-rollback` / `/kg/ka-prune` (ADMIN，mutate dump)。
  - rollback 先归档当前（可逆），再恢复指定版本 → active。
  - 测试 5 个（archive/list/rollback 可逆/未知版本报错/prune 保留最新），全绿。
- **验收**：✅ KA 可 rollback 到历史版本（rebuild 失败/退化可恢复）；✅ 自动归档 + prune 约束磁盘。

### #12 embed 维度权衡
- **现状**：ollama qwen3-embedding:4b（2560 维）。
- **方案**：评估 vs 百炼 text-embedding-v4（1024 维，与 Lance num_sub_vectors=32 对齐，更轻）。benchmark 检索质量 + 速度 + cost。
- **验收**：出评估报告；选最优 embed 配置。
