## 1. 执行摘要

### 1.1 问题陈述

Arrow Lake v0.1.0 是一个面向多模态数据湖仓的 Python SDK 和 CLI 工具。
它提供了丰富的编程接口，涵盖 80 个 Story 的功能（向量搜索、全文搜索、OLAP 分析、
质量流水线、血缘追踪、工作流编排），但缺少 HTTP API —— 这使得非 Python 服务
（前端应用、微服务、BI 工具、其他编程语言）无法使用。

### 1.2 方案

在现有 Lake SDK 之上添加基于 FastAPI 的 REST 层，将 Arrow Lake 转化为**可部署的数据服务**。
API 层是薄编排层 —— 所有数据操作委托给现有 SDK，保留 14,000+ 行经过实战检验的业务逻辑。

### 1.3 范围

v0.2.0 涵盖四个阶段：
- **阶段 1** (P0): RESTful API，30+ 端点，认证，OpenAPI 文档
- **阶段 2** (P1): 多模态内容管理元数据模型
- **阶段 3** (P1): GPU 加速推理、自适应索引、分布式摄取
- **阶段 4** (P2): OpenTelemetry、Grafana 仪表板、Kubernetes Operator、外部连接器

### 1.4 目标业务场景

| 场景 | 描述 | 优先级 |
|------|------|--------|
| **数据搜索服务** | 后端服务，通过 REST API 为其他应用提供向量 + FTS + 混合搜索 | 主要 |
| **多模态内容平台** | 统一管理文本/图像/音频/视频内容，含元数据、质量评分和跨模态检索 | 主要 |
| **企业知识库** | RAG 流水线的基础 —— 存储文档、嵌入和通过 API 检索（阶段 3+） | 次要 |

### 2.2 设计原则

| 原则 | 描述 |
|------|------|
| **薄 API 层** | 每个端点与现有 Lake SDK 方法 1:1 映射。不重复业务逻辑。 |
| **Pydantic 优先** | 所有请求/响应模型使用 Pydantic BaseModel，实现自动校验和 OpenAPI Schema 生成。 |
| **Arrow IPC 优于 JSON** | 大结果集（搜索结果、查询输出）使用 Arrow IPC 二进制编码（Base64），避免 JSON 序列化开销。 |
| **优雅降级** | 可选依赖（Ray、GPU、NeMo Curator）在不可用时降级为 CPU/顺序/错误处理。 |
| **向后兼容** | 现有 Lake SDK 和 CLI 继续正常工作。API 是增量添加的。 |

### 2.3 技术栈

| 组件 | 技术 | 选型理由 |
|------|------|----------|
| Web 框架 | **FastAPI 0.115+** | 原生 Pydantic v2 集成、异步、自动生成 OpenAPI 3.1、依赖注入 |
| ASGI 服务器 | **uvicorn** (开发), **gunicorn + uvicorn** (生产) | 标准生产级 ASGI 方案 |
| 序列化 | **pyarrow IPC Stream** 用于大结果集, **JSON** 用于小载荷 | Arrow 二进制格式比 JSON 快 10-100 倍（表格式数据） |
| 认证 | **API Key** (v0.2) → **JWT + RBAC** (v0.3) | 渐进式安全加固 |
| 文档 | **Swagger UI** (内置) + **Redoc** (可选) | 从 Pydantic 模型自动生成 |
| 测试 | **httpx** (异步客户端), **pytest** + **pytest-asyncio** | 类型安全的异步测试客户端 |
| 监控 | **Prometheus** (已有), **OpenTelemetry** (阶段 4) | 与现有 /metrics 向后兼容 |

### 3.2 详细 API 规格

#### 3.2.1 POST `/api/v1/datasets/{name}/ingest` — 文件摄取

**请求体** (multipart/form-data):
```
files: List[UploadFile]         — 待摄取文件 (CSV, JSON, JSONL, Parquet)
modality: Optional[str]        — "text" | "auto-detect" (默认: "auto-detect")
columns: Optional[str]          — 列类型覆盖的 JSON 字符串
                               (例如: '{"text":"string","embedding":"float32"}')
overwrite: Optional[bool]       — 允许覆盖已有数据集 (默认: false)
```

**响应** (200):
```json
{
  "success": true,
  "data": {
    "dataset_name": "documents",
    "total_rows": 1250,
    "total_bytes": 4500000,
    "sources": [
      {"path": "papers.csv", "rows": 1200, "status": "success"},
      {"path": "notes.json", "rows": 50, "status": "success"}
    ],
    "schema": {
      "fields": [
        {"name": "text_content", "type": "string", "nullable": true},
        {"name": "id", "type": "string", "nullable": false}
      ]
    }
  },
  "error": null,
  "meta": {"request_id": "abc-123", "latency_ms": 1523.4}
}
```

**错误响应**:
- `400` — 不支持的文件格式，空文件列表
- `409` — 数据集已存在且 `overwrite=false`
- `413` — 总文件大小超限
- `422` — Schema 校验失败

**SDK 映射**: 调用 `Lake.ingest(dataset_name, [file_paths])`，然后 `Lake.catalog()` 获取 Schema。

**流式处理**: 对于大文件 (>100MB)，返回 `202 Accepted` 并在 `Location` 头中指向状态端点。客户端轮询直到收到 200。

#### 3.2.2 POST `/api/v1/datasets/{name}/search/vector` — 向量搜索

**请求体** (JSON):
```json
{
  "query_vector": [0.12, -0.34, 0.56, "..."],
  "top_k": 10,
  "metric": "cosine",
  "vector_column": "text_embedding",
  "where": "category = 'technology'",
  "nprobes": 20
}
```

| 字段 | 类型 | 必填 | 默认值 | 描述 |
|------|------|------|--------|------|
| `query_vector` | `list[float]` | 是 | — | 查询嵌入向量。维度必须匹配 `embedding_dim`。 |
| `top_k` | `int` | 否 | 配置值 (10) | 返回结果数量。上限: 10,000。 |
| `metric` | `str` | 否 | 配置值 (cosine) | 距离度量: "cosine"、"l2"、"dot" |
| `vector_column` | `str` | 否 | "text_embedding" | 搜索哪个嵌入列。 |
| `where` | `str` | 否 | null | LanceSQL 过滤表达式。 |
| `nprobes` | `int` | 否 | 配置值 (20) | IVF 探测数量。 |

**响应** (200):
```json
{
  "success": true,
  "data": {
    "row_count": 10,
    "query_vector_dim": 1024,
    "metric": "cosine",
    "top_k": 10,
    "max_distance": 0.823,
    "columns": ["id", "text_content", "category", "_distance"],
    "rows": [
      {"id": "doc-001", "text_content": "...", "category": "tech", "_distance": 0.123},
      "..."
    ],
    "arrow_ipc": "base64-encoded-arrow-ipc-stream"
  },
  "meta": {"request_id": "abc-123", "latency_ms": 12.7}
}
```

**序列化模式**:
- `?format=json` (默认): 以 JSON 数组返回 `rows` (适合 < 100 条结果)
- `?format=arrow`: 以 Base64 编码的 Arrow IPC Stream 返回 `arrow_ipc` (适合大结果集)
- `?format=arrow_stream`: 返回原始二进制 Arrow IPC Stream (最高性能)

**SDK 映射**: 调用 `Lake.search(dataset_name, query_vector, top_k=top_k, ...)`。

**行为说明**:
- 校验 `query_vector` 维度与 `vector_column` 的 list_size 匹配。不匹配时返回 `422`。
- 对 `where` 子句执行 SQL 注入黑名单校验 (INSERT, UPDATE, DELETE, DROP 等)。
- 无索引时回退到平坦（暴力）搜索 (记录为警告)。
- `_distance` 列始终追加到结果中。

#### 3.2.3 POST `/api/v1/datasets/{name}/search/hybrid` — 混合搜索

**请求体**:
```json
{
  "query_vector": [0.12, -0.34, "..."],
  "query_text": "machine learning in production",
  "top_k": 10,
  "vector_column": "text_embedding",
  "fts_column": "text_content",
  "where": "source = 'arxiv'"
}
```

**响应**: 与向量搜索相同的信封结构，使用 `_rrf_score` 替代 `_distance`。

**SDK 映射**: `Lake.hybrid_search(dataset_name, query_vector, query_text, ...)`。

**行为说明**:
- 向量搜索和 FTS 搜索并行执行（非顺序）。
- 使用倒数排名融合 (RRF) 合并结果: `score = 1/(k + rank)`。
- 默认倍数: `vector_top_k_multiplier=3`, `fts_top_k_multiplier=3`。
- 按行 `id` 列去重。

#### 3.2.4 POST `/api/v1/datasets/{name}/search/faceted` — 分面搜索

**请求体**:
```json
{
  "query_vector": [0.12, -0.34, "..."],
  "facets": ["modality", "source", "quality_score"],
  "top_k": 10,
  "vector_column": "embedding",
  "where": "modality = 'image'"
}
```

**响应**:
```json
{
  "success": true,
  "data": {
    "row_count": 10,
    "facets": [
      {"name": "modality", "value": "image", "count": 42},
      {"name": "source", "value": "wikimedia", "count": 30},
      {"name": "source", "value": "upload", "count": 12}
    ],
    "rows": [...],
    "arrow_ipc": "..."
  },
  "meta": {"request_id": "abc-123", "latency_ms": 45.2}
}
```

**SDK 映射**: `Lake.faceted_search(dataset_name, query_vector, facets=facets, ...)`。

**行为说明**:
- 使用 DuckDB CUBE 进行分面计算（两个分面最坏情况 O(n*2)）。
- 从分面结果中过滤掉 NULL 超聚合值。
- 配置中的默认分面列: `["modality", "source"]`。

#### 3.2.5 POST `/api/v1/datasets/{name}/query/olap` — OLAP 分析

**请求体**:
```json
{
  "sql": "SELECT category, COUNT(*) as cnt, AVG(quality_score) as avg_score FROM __dataset__ GROUP BY category ORDER BY cnt DESC",
  "max_rows": 1000,
  "tables": {}
}
```

| 字段 | 类型 | 必填 | 描述 |
|------|------|------|------|
| `sql` | `str` | 是 | SQL 查询。必须为 SELECT-only（已校验）。 |
| `max_rows` | `int` | 否 | 最大结果行数（默认: 配置值 100,000）。 |
| `tables` | `dict[str, Any]` | 否 | 用于 JOIN 的额外表。键名必须匹配 `[a-zA-Z_][a-zA-Z0-9_]*`。 |

**响应**: 同一信封结构，含 Arrow IPC 结果。

**SDK 映射**: `Lake.olap_query(dataset_name, sql, max_rows=max_rows, tables=tables)`。

**行为说明**:
- SQL 注入校验: 阻断 INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, GRANT, REVOKE。
- `__dataset__` 魔术表名引用数据集的 Lance 表 (自动替换)。
- JOIN 支持由 `enable_join` 配置控制（默认: true）。
- 大结果集流式模式: 返回 RecordBatchReader 分块。

#### 3.2.6 POST `/api/v1/embed/text` — 文本嵌入

**请求体**:
```json
{
  "texts": ["Hello world", "Machine learning"],
  "model": "Qwen/Qwen3-Embedding-0.6B",
  "model_source": "modelscope",
  "normalize": true
}
```

**响应** (200):
```json
{
  "success": true,
  "data": {
    "embeddings": [[0.12, -0.34, "..."], [0.56, 0.78, "..."]],
    "embedding_dim": 1024,
    "model": "Qwen/Qwen3-Embedding-0.6B",
    "total": 2,
    "null_count": 0
  },
  "meta": {"request_id": "abc-123", "latency_ms": 230.5}
}
```

**错误响应**:
- `503` — 模型不可用（首次使用时触发从 ModelScope/HuggingFace 延迟下载）
- `422` — 无效输入（空文本列表，超出 batch_size 限制）

**SDK 映射**: `LocalEmbeddingEncoder(model_name=model).encode_column(pa.table({"text_content": texts}))`。

**行为说明**:
- 首次调用时延迟加载 SentenceTransformer 模型。
- GPU 自动检测: 有 CUDA 时使用 GPU，否则回退到 CPU。
- 批量大小限制来自配置（默认: 128）。超出时返回 422。
- `model_source="modelscope"` 时从 ModelScope 下载模型（国内访问）。

### 3.3 统一响应信封

所有 API 响应遵循一致的信封结构:

```python
class APIResponse(BaseModel, Generic[T]):
    """Arrow Lake API 端点统一响应信封。"""

    success: bool
    data: T | None = None
    error: APIError | None = None
    meta: ResponseMeta

class APIError(BaseModel):
    code: str           # 机器可读错误码 (DATASET_NOT_FOUND 等)
    message: str        # 人类可读描述
    details: dict = {}  # 附加上下文 (字段, 约束, 提示)

class ResponseMeta(BaseModel):
    request_id: str     # UUID v4
    latency_ms: float   # 服务端处理时间 (毫秒)
    timestamp: str      # ISO 8601 UTC
```

#### v0.2: API Key 认证

```python
# middleware/auth.py
class APIKeyAuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        api_key = request.headers.get("X-API-Key")
        if not api_key:
            return JSONResponse(status_code=401, content={"detail": "缺少 X-API-Key 请求头"})

        if not self._validate_key(api_key):
            return JSONResponse(status_code=401, content={"detail": "无效的 API Key"})

        response = await call_next(request)
        return response

    def _validate_key(self, api_key: str) -> bool:
        """对照已配置的密钥进行校验。"""
        master_key = self.settings.arrow_lake.api.master_key
        if master_key and api_key == master_key:
            return True
        valid_keys = self.settings.arrow_lake.api.keys
        return api_key in valid_keys
```

```yaml

  api:
    master_key: ""                    # 拥有完全访问权限的主密钥

    cors_origins: ["*"]              # CORS 允许的来源
    max_upload_size_mb: 500           # 最大文件上传大小
```

### 3.8 依赖注入与生命周期

```python
# deps.py
from functools import lru_cache

@lru_cache(maxsize=1)
def get_lake() -> Lake:
    """获取或创建 Lake 实例（每个 Worker 进程单例）。"""
    config = ArrowLakeConfig()
    return Lake(base_uri=config.storage.base_uri, config=config)
```

**生命周期**:
1. 应用启动: 校验配置，检查存储可达性
2. 每次请求: 通过 FastAPI `Depends()` 注入 `Lake` 实例
3. 关闭: 关闭 Lake 连接，刷新指标

```python
# app.py
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动
    lake = get_lake()
    logger.info("api_started", version=version(), datasets=lake.list_datasets())
    yield
    # 关闭
    logger.info("api_stopping")

def create_app() -> FastAPI:
    return FastAPI(
        title="Arrow Lake API",
        version=__version__,
        lifespan=lifespan,
        docs_url="/docs",
        redoc_url="/redoc",
        openapi_url="/openapi.json",
        middleware=[
            CORSMiddleware,
            APIKeyAuthMiddleware,
            RequestLogMiddleware,
        ],
        dependencies=[Depends(get_lake)],
    )
```

## 5. 阶段 3 — 性能与扩展

### 5.1 GPU 加速嵌入

```
API 请求 → FastAPI → BackgroundTask
                          │
                          ▼
                   Ray Serve Deployment
                   ┌─────────────┐
                   │ GPU Worker 1│  ← 批次分片 0
                   │ GPU Worker 2│  ← 批次分片 1
                   │ CPU Worker  │  ← 回退
                   └─────────────┘
                          │
                          ▼
                   嵌入结果 → 缓存 → 响应
```

- 批量请求自动分片到可用 GPU Worker
- 无 GPU 时回退到 CPU
- 嵌入结果缓存在 LRU 缓存中（可配置 TTL）

### 5.2 自适应向量索引

| 数据规模 | 索引类型 | 分区数 | 子向量数 | 构建时间 |
|----------|----------|--------|----------|----------|
| < 10万 | IVF_FLAT | N/A | N/A | < 1s |
| 10万 - 100万 | IVF_PQ | 256 | 24 | ~10s |
| 100万 - 1000万 | IVF_PQ | sqrt(rows) | 24 | ~2min |
| > 1000万 | IVF_HNSW_PQ | 1024 | 24 | ~15min |

在 `create_vector_index()` 后数据超过阈值时自动触发。
