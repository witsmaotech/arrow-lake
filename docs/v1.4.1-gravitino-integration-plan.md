## 背景

v1.4.0 完成了性能扩展、数据治理基础和 WSL2 代理修复。当前 Arrow Lake 元数据管理依赖 DuckDB `catalog.db`，仅管理 Lance 数据集，无法跨数据源联邦，缺少数据分类标签、细粒度权限、模型版本化等治理能力。

Apache Gravitino 1.2.1 提供 Lance 原生支持（Lance REST Catalog + lakehouse-generic）、Daft 原生 Connector、RBAC/DAC 双模型、Tags/Policies 治理体系，可一站式填补上述空白。

### 1.3 Metalake 初始化脚本

**新增文件**：`deploy/scripts/init-gravitino.sh`

```bash
#!/usr/bin/env bash
# Gravitino Metalake + Catalog 初始化
set -euo pipefail

GRAVITINO_URI="${GRAVITINO_URI:-http://localhost:8090}"
METALAKE="${GRAVITINO_METALAKE:-arrow-lake}"
MINIO_ENDPOINT="${MINIO_ENDPOINT:-http://minio:9000}"

echo "==> 初始化 Gravitino Metalake: ${METALAKE}"

# 创建 Metalake
curl -sf -X POST \
  -H "Accept: application/vnd.gravitino.v1+json" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"${METALAKE}\",\"comment\":\"Arrow Lake 数据湖\",\"properties\":{}}" \
  "${GRAVITINO_URI}/api/metalakes" || echo "Metalake already exists"

# 启用 Metalake
curl -sf -X PATCH \
  -H "Accept: application/vnd.gravitino.v1+json" \
  -H "Content-Type: application/json" \
  -d '{"inUse":true}' \
  "${GRAVITINO_URI}/api/metalakes/${METALAKE}" || true

# 创建 lakehouse-generic Catalog (Lance)
curl -sf -X POST \
  -H "Accept: application/vnd.gravitino.v1+json" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"lance-catalog",
    "type":"RELATIONAL",
    "comment":"Lance 数据集（lakehouse-generic）",
    "provider":"lakehouse-generic",
    "properties":{
      "location":"s3a://arrow-lake/"
    }
  }' \
  "${GRAVITINO_URI}/api/metalakes/${METALAKE}/catalogs" || echo "lance-catalog already exists"

# 创建 Fileset Catalog (MinIO)
curl -sf -X POST \
  -H "Accept: application/vnd.gravitino.v1+json" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"minio-fileset",
    "type":"FILESET",
    "comment":"MinIO 文件管理",
    "provider":"fileset",
    "properties":{
      "location":"s3a://arrow-lake/"
    }
  }' \
  "${GRAVITINO_URI}/api/metalakes/${METALAKE}/catalogs" || echo "minio-fileset already exists"

# 创建 Model Catalog
curl -sf -X POST \
  -H "Accept: application/vnd.gravitino.v1+json" \
  -H "Content-Type: application/json" \
  -d '{
    "name":"ml-models",
    "type":"MODEL",
    "comment":"ML 模型版本管理",
    "provider":"model",
    "properties":{}
  }' \
  "${GRAVITINO_URI}/api/metalakes/${METALAKE}/catalogs" || echo "ml-models already exists"

echo "==> Gravitino 初始化完成"
```

### 3.1 RBAC/DAC 权限增强 ✅ 完成

**修改文件**：`arrow_lake/api/rbac.py`

新增 `GravitinoRBACBridge`，委托 Gravitino 进行权限决策：

```python
class GravitinoRBACBridge:
    """委托 Gravitino 进行访问控制决策。"""

    def __init__(self, config: GravitinoConfig) -> None:
        self._client = GravitinoClient(uri=config.uri, metalake_name=config.metalake)

    # 权限映射
    _ACTION_TO_PRIVILEGE = {
        "read": "SELECT_TABLE",
        "write": "INSERT_TABLE",
        "create": "CREATE_TABLE",
        "delete": "DELETE_TABLE",
        "admin": "CREATE_CATALOG",
    }

    def check_permission(self, user: str, resource: str, action: str) -> bool:
        privilege = self._ACTION_TO_PRIVILEGE.get(action)
        if not privilege:
            return True  # 未知操作默认放行
        try:
            roles = self._client.get_user_roles(user)
            return self._evaluate_privilege(roles, resource, privilege)
        except Exception:
            log.warning("Gravitino RBAC check failed, falling back to local")
            return None  # None 表示降级到本地 RBAC
```

## 风险缓解

| 风险 | 缓解 |
|------|------|
| Gravitino 不可用导致 Arrow Lake 异常 | 所有 Gravitino 调用包裹 try/except，降级到本地逻辑 |
| 元数据双写不一致 | Gravitino 为权威源，DuckDB catalog.db 为缓存，定时从 Gravitino 同步 |
| Lance REST Catalog 与 LanceDB 版本冲突 | CI 矩阵测试 Gravitino 1.2.1 + 当前 Lance 版本 |
| Gravitino Python SDK 不兼容 | 锁定 `gravitino>=0.7.0`，CI 验证 |
| 性能开销 | 异步后台同步，不阻塞请求路径；统计收集在摄取后触发 |
