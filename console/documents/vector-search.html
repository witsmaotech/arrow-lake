向量搜索与索引

从 Embedding 生成、索引创建、相似度搜索到索引管理——覆盖 Python Lake facade 与 REST API 的 ANN 全流程。

难度 · 中级耗时 · 20 分钟前置 · 已摄取带向量列数据

向量相似度搜索（ANN）对 text_embedding 列执行近似最近邻检索。双路径策略优先 DuckDB lance_vector_search()，失败回退 LanceDB SDK；无索引时自动暴力搜索，性能随数据量线性下降。

1索引类型与度量

索引类型特点
IVF_PQIVF 倒排 + 乘积量化，大规模默认，内存小
IVF_FLAT无量化，精度高、内存大
IVF_HNSW_PQIVF + HNSW + PQ，低延迟但构建最贵
IVF_HNSW_SQIVF + HNSW + 标量量化，低延迟、精度优于 PQ
IVF_SQIVF + 标量量化，内存与精度介于 IVF_FLAT / IVF_PQ 之间
IVF_RQIVF + 残差量化，高精度、内存略大
HNSW纯图索引，查询延迟最低、构建内存大
度量值域适用
cosine[0,2] 越小越好方向相似，文本 / RAG 默认
l2[0,+inf)欧氏距离，空间距离有意义时
dot越大越好已归一化向量，最快

3精细控制与多形态搜索

nprobes 调召回 / 延迟

搜索时扫描的 IVF 分区数，越大召回越高、延迟越大；硬上限 max_nprobes（默认 256），推荐起点 num_partitions // 10。

5踩坑提示

索引创建最少 256 行

IVF_PQ 索引创建有硬限制：数据集 < 256 行会抛 VECTOR_INDEX_TOO_FEW_ROWS（小数据集用暴力搜索即可，无需索引）。REST ingest_documents_and_index 摄入后行数 ≥256 才自动建 IVF_PQ，<256 跳过并告警，向量检索仍可走暴力。

RAG 502 / lance_scan_mode

默认 lance_scan_mode: "auto" 下，DuckDB 原生 lance 向量流对 IVF_PQ 有 Rust panic（uvicorn worker 崩 → 浏览器 502）。RAG hybrid 检索 502 时改 olap.lance_scan_mode: "pyarrow_fallback" 走 sub-bridge sync RRF 绕开 DuckDB 路径（性能略降，但 RAG 通）。

多模态以图搜图

图像数据集带 image_embedding 列（CLIP/SigLIP 向量）后，用 POST /embed/image 编码查询图，再 POST /datasets/{name}/search/vector 检索相似图像；文搜图用 lake.encode_text_clip()。

num_sub_vectors 必须 8 的倍数

1024 维推荐 24（子向量 ~42 维）、768 维推荐 24、1536 维推荐 32；子向量越多量化越精，但构建时间与内存越大。

num_partitions 自动策略

<65,536 行取 min(sqrt(rows)*4, 256)；65K–1M用配置值（默认 256）；≥1M取 min(sqrt(rows), 4096)。一般传 None 让系统选。

度量选择

查询向量维度必须与数据集向量列一致（VectorSearchResult.query_vector_dim 可校验）。cosine 是默认且对长度不敏感；已归一化向量用 dot 最快；不确定就用 cosine。
