## 1. 产品定位与核心命题

Arrow Lake 是面向 AI/ML 团队的**生产级多模态数据湖仓库**：文本、图像、音频、向量、知识图谱统一在一个平台。核心命题——**让数据从摄入到可被 RAG/KG/分析消费的全链路，在一个 facade 内可治理、可审计、可离线运行**。

v1.9.6 把这条链路从"能用"推进到"可信赖"：
- **RAG 可溯源防幻觉**（faithfulness verify + cross-encoder reranker）
- **治理兑现**（masking 治理 + 血缘可视化，从能力到 UI）
- **安全 fail-closed**（信任边界出错向安全一侧失败）
- **部署自包含**（模型 bake 进镜像，离线即用）

## 3. 五层架构

```
① 接入 → ② 能力 → ③ 计算 → ④ 存储引擎 → ⑤ 持久化
   ⟂ 治理 / 可观测 / 安全（控制面状态由 system_db 持久化）
```

### 3.1 ① 接入层
四入口归一到 `Lake` facade：**SDK**（Python）· **REST**（FastAPI，20 routers / 159 routes）· **CLI** · **Console**（同源 mount `/console`，复用 REST + RBAC，bind-mount 改即生效）。

### 3.2 ② 能力层
- **摄入**：文件/文档（PDF/多格式）/图像/视频/混合/Kafka/SQL/Iceberg/DeltaLake/HTTP —— `ingest_documents_and_index`（v1.9.6 架构 refactor #4）收口 parse→store→embed→FTS→vector 一条龙，SDK=HTTP 对齐。
- **检索**：vector / fts / hybrid（RRF）/ faceted / ensemble；**cross-encoder reranker**（v1.9.6 默认 bge-reranker-v2-m3）。
- **RAG**：多策略 + 会话 + 引用 + 流式 + **faithfulness verify** + GraphRAG。
- **KG**：hyper-extract 抽取 + per-dataset 图 + Gremlin（注入防御）+ GraphRAG。

### 3.3 ③ 计算层
- **DuckDB OLAP**：主力查询（`olap_query`/`vector_search`/`fts` 全经 DuckDB）。
- **嵌入器矩阵**：Local / Daft / CLIP / RayServe。
- **clean 写回**（v1.9.3）：语义 steps→SQL→`restore_dataset` 原地清洗 + 派生血缘。

### 3.4 ④ 存储引擎层
LanceDB（Table/索引/版本/tags/branches）+ HugeGraph（动态图）+ Gravitino（catalog 联邦）。

### 3.5 ⑤ 持久化层
- **数据面**：MinIO/S3（Lance 列式 + 对象）+ HugeGraph rocksdb + DuckDB 文件。
- **控制面**：libSQL `system_db`（9 store：rbac/identity/catalog/task_history/lineage_index/rag_session/governance/user_state/ingest_dlq）。opt-in + fail_close（RBAC/identity）/ fail_soft（catalog/tasks/rag）双模。

### 3.6 ⟂ 横切面
治理 / 可观测 / 安全 —— 见 §6。

## 5. 核心业务流程

### 5.1 文档摄入 → 索引
```
POST /datasets/{name}/ingest/documents
  → parse (kreuzberg/docling) → chunk → embed → store (Lance)
  → auto create_vector_index (≥256 行 IVF_PQ, <256 WARN skip)
  → auto FTS 索引
```
- v1.9.5：hybrid 默认生效（修 `_rag_retriever` 死配置）。
- v1.9.6 refactor #4：`ingest_documents_and_index` 收口，SDK=HTTP 对齐。

### 5.2 RAG 问答（防幻觉闭环）
```
POST /rag/query
  ① query transform (HyDE / multi_query)
  ② retrieval (hybrid: vector + fts, RRF 融合)
  ③ rerank (cross-encoder bge-reranker-v2-m3, 本地 /opt/models/)
  ④ GraphRAG 三路并行 (vector + search_ka + neighbor) [use_kg=true]
  ⑤ context assembly (token budget)
  ⑥ LLM generate (streaming)
  ⑦ faithfulness verify (逐句 vs context → support_ratio/unsupported)
  → 响应: answer + citations + support_ratio + unsupported
```
- 流式：首帧 `citations`，末帧 `latency` + `verification`。
- 配置：`extract_llm=qwen-turbo`（快，实体抽取/变体），`qa_llm=qwen-plus@16384`（最优 QA）。

### 5.3 KG 构建 + GraphRAG
```
kg_build(dataset)
  → feed_text chunks → hyper-extract (snap/strict/enum 质量门)
  → MERGE_FIELD 合并 (非 LLM, 稳定 15% 内存, 治 BALANCED grouped OOM)
  → HugeGraph upsert (per-dataset kg_{ds}, PRIMARY_KEY 幂等)
  → build_index (KA LRU mtime 失效)
GraphRAG: 三路并行 retrieve (109s→50s)
```

### 5.4 治理闭环（masking + lineage + audit）
```
① mask-preview: POST /datasets/{name}/quality/mask-preview (ADMIN, 列名白名单)
② create policy: POST /gravitino/policies/masking (function 4 选 1, 审计入 Lance)
③ enforce: RBAC _apply_masking 对 VIEWER 透明 (fail-closed 返空表)
④ lineage: GET /lineage/graph/{name}?max_nodes=500 + /history (列级血缘)
⑤ audit: GET /audit/query?event_type=masking_policy_created (HMAC 签名, 零新表)
```

### 5.5 OLAP + 清洗写回
```
POST /datasets/{name}/query/olap (DuckDB SQL, RBAC 行/列 ACL)
POST /datasets/{name}/clean (语义 steps→SQL→restore_dataset 写回)
→ lineage 自动记 clean 派生边 (列级)
```

## 6. 横切关注点

### 6.1 安全（fail-closed 主线）
**原则**：信任边界出错向安全一侧失败，绝不向数据泄露失败。

| 路径 | 失败场景 | fail-closed 行为 |
|---|---|---|
| masking `_apply_masking` | 引擎抛错/未知函数/hash 缺 key | 返空表 `slice(0,0)` |
| row-filter `_apply_row_filter` | 表达式不可解析/列缺失/类型不匹配 | 返空表 |
| masking `_fetch_rules` | Gravitino 拉规则失败 | `raise RuntimeError`（不返空规则集） |
| 启动 | `MASKING__HMAC_KEY` 缺失 | 启动阻断（`ALLOW_MISSING_KEY=1` opt-in） |
| mask-preview | 列名非法 | 标识符白名单拒（防 SQL 注入），端点 ADMIN |
| lineage 图谱 | 节点/边标签 | HTML 转义（vis title + DOT/Mermaid，防 XSS） |

其他：RBAC 3 级（VIEWER/EDITOR/ADMIN）+ API Key/JWT（Redis 黑名单）+ 注入防御（Gremlin 参数化/SQL prepared/路径标准化）+ 限流。

### 6.2 治理
- **Gravitino**：统一 catalog，tag-driven ACL，masking policy，retention。
- **masking**：4 函数（redact/hash 128 位/partial/nullify）+ HMAC fail-fast + mask-preview + audit（复用 Lance `audit_record`，零新表）。
- **lineage**：`lineage.html` 可视化（vis-network ≤2000 / G6 v4 更大）+ 列级血缘 + `max_nodes` 截断 + `stats.truncated` 透明告知。
- **audit**：HMAC-SHA256 防篡改，每个状态转换记录（摄入/验证/分块/嵌入/查询/清洗/masking 策略）。

### 6.3 可观测
`structlog` JSON 日志 + Prometheus 指标 + OpenTelemetry（Jaeger，opt-in `--profile tracing`）+ audit 全覆盖（structlog + libSQL）。

## 7. 部署架构

### 7.1 镜像（模型 bake，离线就绪）
v1.9.6 核心改进：**模型权重 bake 进镜像**，服务启动零网络下载（`HF_HUB_OFFLINE=1`）。

| 镜像 | 基础 | 模型 | 大小 |
|---|---|---|---|
| `arrow-lake:1.9.6`（CPU） | python:3.12-slim | reranker 2.2G (modelscope) + docling 506M (HF) | 16.8GB |
| `arrow-lake:1.9.6-gpu` | nvidia/cuda:12.4.1-runtime | 同上 + cu124 torch | ~18GB |

**bake 机制**（BuildKit named context）：
```dockerfile
COPY --from=msmodels BAAI--bge-reranker-v2-m3/snapshots/master /opt/models/bge-reranker-v2-m3
COPY --from=hfmodels models--docling-project--docling-* /opt/hf-cache/hub/
ENV HF_HOME=/opt/hf-cache
ENV HF_HUB_OFFLINE=1
```
```yaml
# compose
build:
  additional_contexts:
    - "hfmodels=${HF_HUB_DIR}"
    - "msmodels=${MODELSCOPE_DIR}"
environment:
  RERANKER_MODEL: /opt/models/bge-reranker-v2-m3   # 本地路径加载
  HF_HOME: /opt/hf-cache
  HF_HUB_OFFLINE: "1"
```
- reranker 走 modelscope 缓存（HF hub 国内受限）→ 本地路径加载（`CrossEncoder("/opt/models/...")`）。
- docling 走 HF cache（`HF_HOME`）。
- build 时 `--build-context` 指向 host 缓存，零下载。

### 7.2 容器栈（prod_minimal）
11 服务：api / minio(+init) / nginx / lance-rest / hg-server(+hubble) / redis / system-db / gravitino(+init) / ollama-relay / proxy-forwarder。
- api `read_only: true`（改 Python 需 rebuild 或 dev.override 热重载）。
- WSL2 mirrored 网络：容器外网经 socat 中继（ollama 11534 / proxy 17887）。
- `NO_PROXY` 必含 `host.docker.internal` + 内部服务名。

### 7.3 控制面（system_db）
libSQL 接管控制面（v1.9.0），opt-in（`SYSTEM_DB_ENABLED=true`）。数据面零触碰。

## 9. 关键决策（ADR）

### ADR-1: 模型 bake 进镜像 vs 运行时拉
**决策**：bake（reranker + docling）。
**理由**：生产/离线自包含、首启快、版本固定、多副本一致。代价：镜像 +4.6GB。运行时拉在离线/代理环境不可靠（hf-mirror 经代理不稳定）。

### ADR-2: fail-closed 默认
**决策**：masking/rbac 异常返空表或 raise，不泄露未脱敏。
**理由**：隐私/授权路径上宁可空结果也不泄露。与 RBAC"默认拒绝"一致。

### ADR-3: cross-encoder reranker 默认（替 Ollama 二值）
**决策**：bge-reranker-v2-m3（连续分，精度高）。
**理由**：检索质量是 RAG 头号因子；cross-encoder 排序优于二值判断。CPU 可跑，GPU 更快。

### ADR-4: masking HMAC fail-fast
**决策**：缺 key 启动阻断（`ALLOW_MISSING_KEY=1` opt-in）。
**理由**：hash 脱敏需密钥签名；静默 fallback nullify 是合规隐患。强制显式配置。

### ADR-5: GraphRAG 模板方法 + 三路并行
**决策**：`super().query()` 单一模板 + `_extra_context_task` 钩子；`asyncio.gather` 三路并行。
**理由**：消除子类复制（parity bug）；并行砍延迟 40-50%。

### ADR-6: reranker 经 modelscope + 本地路径加载
**决策**：bake modelscope snapshots → `/opt/models/`，`RERANKER_MODEL=本地路径`。
**理由**：HF hub 国内受限（hf-mirror 不稳）；modelscope 缓存可用；`CrossEncoder(本地路径)` 离线加载。
