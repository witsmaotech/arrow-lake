# v1.9.9 阶段 2 实施设计 — 增强图谱顶点关系(关系软降级 + 启发式孤儿连接 + few-shot + embedding 复用)

> 2026-08-01。本文档是 [v1.9.8-graph-build-mapreduce-plan.md](./v1.9.8-graph-build-mapreduce-plan.md) §八 阶段 1 之后的**可执行实施设计**。上游规划讲"为什么",本文档讲"怎么做"。承接 v1.9.8 阶段 1(map_reduce 已交付,commit 3f69692)。

## 一、目标与背景

v1.9.8 map_reduce 让 wuhu(552 页 PDF)图谱构建又快又稳:12188 顶点 / 20851 边,16 合法动词,类型分布干净。但 `/kg/quality` 暴露核心质量短板:

- **孤立率 0.44** — 44% 的 entity 顶点没有任何 entity↔entity 边(平均度数仅 0.84)。
- **主体过判 28%** — 主体类型占 28%,远超合理比例。

三条根因(已结合代码核实):

1. **type-pair 过滤器丢弃关系**(`relation_validator.py:131-134` `dropped += 1`)→ 端点若无其他边则沦为孤立。**过滤器本身制造了它本想治愈的碎片化。**
2. **主体过判** → 主体只能连 {软件,硬件,模型,数据,服务,方案,项目}(`LEGAL_TYPE_PAIRS["提供"]`),主体↔主体 / 主体→要求·指标 的关系全被丢。
3. **真 singleton** — LLM 抽出实体却未连任何边。

**本阶段交付 4 项干预**:

| # | 干预 | 机制 | 成本 | 风险 |
|---|------|------|------|------|
| A | 关系软降级 | 非法 type-pair 关系降级为 `相关`(route→`related_to`,weight 0.4)而非丢弃;端点保持连通 | 零 LLM | 极低(连接是 LLM 从原文抽的,只是动词/类型不搭) |
| B | 启发式孤儿连接 | 共现(同 chunk)+ embedding 余弦 ≥ 阈值 + type-pair 合法动词,无 LLM;复用 embed | 复用 embed | 低(三重证据门控) |
| C | 模板 few-shot | project_concept_graph 加易混类示例,降主体过判 | 零 | 零(仅 prompt) |
| D | embedding 复用 | 构建期算一次 embedding,消歧 + 孤儿连接共用 | 提效 | 零 |

**已核实的底层事实**:
- `route_relation("相关")` → `related_to`(`entity_router.py:194-205`,`相关` 不命中任何 synonym 路由)。
- `related_to` 边定义 `EdgeLabelDef("related_to","entity","entity",("weight","relation_type","description"))` —— 端点是 generic `entity` 顶点,double-write 保证恒存在 → `_insert_kg` 的 endpoint-missing 降级(`builder.py:838-843`)**不会二次触发**。
- `_insert_kg` 对 `related_to` 读 `weight`(`builder.py:848-851`)→ 软降级的 0.4 权重会落到 HugeGraph 边上。
- `_insert_kg` 写边 props 只含 `relation_type`+`description`+(`related_to` 时)`weight`,**不**盲目拷 `ExtractedRelation.properties`。

**阶段 2 不含**:Leiden 社区/超图(层次化检索,阶段 3)、faiss 近邻(>10k 性能,本轮 linker 非 O(n²) 故不需要)、ingest 按 mime 分流、`retriever.py` predicate 压扁(独立 issue)。

## 二、实施细节

### A. 软降级 — `arrow_lake/knowledge_graph/relation_validator.py`

给现有函数加 `on_illegal` 参数(**默认仍是 `"drop"`,向后兼容**;由 builder 显式传 `"degrade"`,不动现有测试):

```python
_GENERIC_VERB = "相关"
_DEGRADED_WEIGHT = 0.4

def filter_relations_by_type_pair(
    result: ExtractionResult, template_path: str | None,
    *, on_illegal: Literal["drop", "degrade"] = "drop",   # NEW; default 不变
) -> ExtractionResult:
```

过滤循环(`relation_validator.py:128-142`):非法且 `on_illegal=="degrade"` 时,**不丢弃**,改写 `relation_type="相关"`,保留原动词到 `properties.original_relation_type`,加 `properties.weight=0.4`(用 `dataclasses.replace`,输入不可变);统计 `degraded` 计数并 `logger.info`。`on_illegal=="drop"` 走原 v1.9.8 逻辑。非 project_concept_graph 仍 no-op。

> 边上的 `relation_type` = `相关`(持久化);原动词仅存 `ExtractedRelation.properties` + 构建日志,**不**往 HugeGraph 边写 `original_relation_type`(那需要加 schema property key,不值)。

### B. 启发式孤儿连接 — 新模块 `arrow_lake/knowledge_graph/orphan_linker.py`

纯逻辑,镜像 `entity_resolver.py` 模式(embeddings 注入,无 I/O,never raises)。**不需要 generate_fn**(纯启发式,无 LLM)。复用 `relation_validator` 的 `LEGAL_TYPE_PAIRS` / `_pair_matches` / `_UNKNOWN_TYPES` / `is_project_concept_graph`。

```python
_MAX_ORPHAN_ENTITIES = 50000   # linker 是 O(orphans×candidates) 非 O(n²);只 embed 是 O(n)
_DEGRADED_WEIGHT = 0.4

def link_orphans(
    result: ExtractionResult,
    entity_chunks: dict[str, list[str]],
    embeddings: dict[str, list[float]],   # normalize_name → vec(构建期一次算好)
    *, template_path: str | None,
    threshold: float, max_partners: int, max_links: int,
) -> tuple[ExtractionResult, list[ExtractedRelation]]:
    """返回 (new_result, new_relations);new_relations 为新增边(空则 no-op)。"""
```

算法:
1. **GUARD**:`is_project_concept_graph(template_path)` 否则 no-op;`<2` 实体 no-op;`>50000` 实体 warn+no-op。
2. **索引**:`type_by_name` / `name_by_norm` / `all_norm_names`;`existing_rel_keys = {(norm_src, verb, norm_tgt)}` 由现有 relations 预建(去重用)。
3. **算孤立**:`connected = {所有 relation 端点的 normalize_name}`;`orphan_norms = all_norm_names − connected`;空则 no-op。
4. **共现索引**:`chunk_to_entities: dict[chunk_id → set[norm_name]]`(由 `entity_chunks` 反转)。
5. **逐孤立找候选**:对该孤立的每个所属 chunk,取 `chunk_to_entities[cid] ∩ connected_norms` 作候选(共现证据门);丢弃自身。无候选 → skip(证据门失败,**不臆造**)。
6. **排序筛选**:对每个候选取 embedding 算 `_cosine`;`< threshold` 丢弃;`_pick_legal_verb(o_type, c_type)` 取合法动词(双方向,选最宽泛),无合法动词 skip;按 sim 降序取前 `max_partners`,累计不超 `max_links`,去重(命中 `existing_rel_keys` skip)。
7. **拼接**:`replace(result, relations=result.relations + tuple(new_relations))`。

`_pick_legal_verb(src,tgt)`:未知类型 → `(None,"")`;否则 forward `(src,tgt)` 找最宽泛动词(LEGAL_TYPE_PAIRS 里 `_pair_matches` 命中且 pair 数最多的 verb),命中返 `(verb,"forward")`;否则 reverse `(tgt,src)`,返 `(verb,"reverse")`;都无 `(None,"")`。`_cosine`:numpy 点积/范数。

### C. 模板 few-shot — `arrow_lake/knowledge_graph/templates/project_concept_graph.yaml`

`guideline.rules_for_entities.zh` 现有第 69 行易混规则后,加 2 条具体示例:
- 易混类判定示例(`"XX云平台"→软件`、`"XX大模型"→模型`、`"响应时间"→指标`(不抽"2秒")、`"ISO9001认证"→资质`、`"5G/IoT"→技术` vs `"OCR引擎/RAG"→模型`)。
- 主体判定补充:仅法人/自然人/机构当事方归主体;平台/系统/中台/引擎归软件,AI 能力归模型,工程目标归项目;二义时按"是否当事方"裁决。

### D. embedding 复用

- `entity_resolver.resolve_entities` 加 `embeddings: list[list[float]] | None = None`;非空且长度匹配时直接用作 `vecs`,否则原逻辑内嵌(`entity_resolver.py:254-268`)。向后兼容。
- `he_extractor.resolve_entities` wrapper(`he_extractor.py:211-240`)加 `embeddings` 透传。
- **builder 在 map_reduce 分支(type-pair 过滤后、消歧前)算一次 embedding**:`texts = [_entity_text(e) ...]`(`_entity_text` 从 entity_resolver 导入);`embed_fn = self._extractor._embedder.embed_documents`;`asyncio.wait_for(to_thread(embed_fn, texts), timeout=600)`;得 `precomputed_vecs`(list,喂消歧)+ `name_to_vec: dict[norm_name→vec]`(喂孤儿连接)。

> **关键**:embed 计算的 guard 用 `2 <= len(result.entities) <= 50000`(O(n) embed 不是 O(n²)),**不**用 `_MAX_RESOLVE_ENTITIES=10000` —— 否则 wuhu(12188)直接 skip embed → name_to_vec 空 → 孤儿连接 no-op,本阶段对 wuhu 无效。entity_resolver 自己的 10k cap(管 `_cosine_clusters` 的 O(n²) 矩阵)不动。
>
> **效率门**:仅当 `he_entity_resolution != "off"` 或 `he_orphan_linking != "off"` 时才算 embed(两者都关则跳过,不浪费 O(n) embed)。

### E. builder wiring — `arrow_lake/knowledge_graph/builder.py`

**map_reduce 分支**(替换 `builder.py:575-604` 的 else 块)新顺序:
1. 软降级:`filter_relations_by_type_pair(result, template_path, on_illegal="degrade")`(原 L578 加 `on_illegal="degrade"`)。
2. 算 embedding(§D 代码块)。
3. 消歧:`self._extractor.resolve_entities(result, embeddings=precomputed_vecs)`(原 L584 加 `embeddings=`);merge_map 重映射 entity_chunks 不变。
4. **孤儿连接(新)**:`he_orphan_linking != "off" and name_to_vec` 时 `link_orphans(result, entity_chunks, name_to_vec, template_path=..., threshold/max_partners/max_links=...)`;best-effort try/except + log。
5. `_insert_kg`(不变)。

**dataset 分支**(L362-434):同样加 `on_illegal="degrade"`(L408)+ 孤儿连接(消歧 L427 后、insert L428 前);embedding 复用同样模式;有 `dataset_ka.entity_chunks` 作共现门。

**chunk 分支(L610-652):不动**(无全局 merge,无意义孤立集)。

### F. 配置 — `arrow_lake/config/rag.py` (`HugeGraphConfig`,L252 后)

```python
he_orphan_linking: Literal["off", "auto"] = "auto"     # 默认开(零LLM+证据门控+best-effort)
he_orphan_threshold: float = 0.75    # 孤儿连接 cosine 阈值(低于消歧 0.86,因"相关"<"同义")
he_orphan_max_partners: int = 3      # 每个孤立最多连几条
he_orphan_max_links: int = 500       # 全局新增边上限(封顶)
```
> 默认 `auto`:embedder 总在(he 后端 `_create_kg_extractor` 恒建);最坏只是几条低权 `related_to`,可 `HE_ORPHAN_LINKING=off` 关。wuhu 重建是验证闸口,有噪声就调阈值/关。

### 持久化核查(实证,builder.py:844-851)
- **软降级边**(`相关`→`related_to`):`relation_type="相关"` + `weight=0.4` 都落库 ✓(均在 related_to schema 内,无需改 schema)。
- **孤儿连接边**:动词是合法 typed verb(如 `提供`→`provides` typed 边),`route_relation` 路由到 typed label(端点解析失败则 L838-843 降级 related_to,恒能插入,不产生新孤立)。**但**:`inferred`/`cosine`/`weight` 这些 properties **不落库**(typed 边不写 weight,仅 related_to 写)→ 推断边在图里与真实抽取边**不可区分**。已知局限:本阶段接受(证据门控 + caps 封顶 + 构建日志可查);后续可加 schema property key `inferred` 标记。精度靠**共现门 + 0.75 阈值 + max_partners=3**,不依赖落库 weight。

## 四、验证方案(wuhu 实证)

**基线**(v1.9.8,commit 3f69692,当前线上):`GET /kg/quality?dataset=wuhu` → entity_vertex_count 12188 / entity_entity_edges 5104 / orphan_rate 0.44 / avg_degree ~0.84 / type_distribution[主体] 28%。

**实施后**:重建 wuhu KG(`he_kg_granularity=map_reduce` + `he_entity_resolution=auto` + `he_kg_type_pair=True` + `he_orphan_linking=auto`,dev override 秒级热重载),再 `GET /kg/quality?dataset=wuhu`。

| 指标 | 预期 | 依据 |
|------|------|------|
| orphan_rate | **↓**(目标 < 0.20) | 软降级回收所有原被丢关系(每条都保两端连通)+ 孤儿连接补证据门控边 |
| entity_entity_edges | **↑**(目标 > 10000) | 软降级回收 K 条 + 孤儿连接至多 500 条 |
| avg_degree | **↑**(目标 > 1.5) | 边增/顶点持平 |
| type_distribution[主体] | **↓**(目标 < 20%) | few-shot 降主体过判 → 更少 type-pair 丢弃 |
| relation_type_coverage | 持平或 +1(多 `相关`) | 合法边保留原动词 |

问答对比:`/kg/ask` 关系密集型问题应更准(邻居上下文更丰富)。可选 A/B:分别只开软降级 / 只开孤儿连接,隔离各自贡献。

## 五、风险 / 边界

- **R1 误连**:共现门保证两端来自同一 chunk(LLM 从同一文本段抽出),embedding 阈值 0.75 是精度过滤,非臆造;`max_partners=3` 防级联。噪声大就调阈值到 0.80 / max_partners=2。
- **R2 mega-hub**:主体连万物 → `max_partners` 限每孤立连几条(可选增强:限每候选被连次数,本版 `max_links=500` 已封顶)。
- **R3 未知类型**:`_pick_legal_verb` 返 None → 不连(不绕过白名单);仍留 `references(chunk→entity)` 边,非全孤立。
- **R4 >10k 实体**:embed guard 放宽到 50k;wuhu 12188 能算 embed → 孤儿连接生效。
- **R5 非 project 模板**:`link_orphans` 顶部 `is_project_concept_graph` 守卫 → no-op(同 type-pair filter)。
- **R6 双重降级**:软降级 → `相关` → `related_to`,端点是恒存在的 generic entity 顶点 → `_insert_kg` endpoint-missing 降级不触发(已核实)。
- **R7 checkpoint**:map_reduce checkpoint(builder L488-565)只存 MAP 输出;软降级/孤儿连接是确定性 reduce 步,resume 时重跑,正确。

## 七、不做(外科边界)

下列 followup 项(`project_v198_mapreduce_followups.md`)与本阶段"增强顶点关系"正交,本轮**不动**:
- faiss 近邻替代 O(n²) cosine(>10k 性能;本轮 linker 非 O(n²),wuhu 12188 能跑)。
- Leiden 社区 / 超图(阶段 2/3 层次化检索,用户本轮未要求)。
- ingest 按 mime 分流(TXT/CSV 跳 docling)。
- `retriever.py` predicate 压扁(`/rag/query?use_kg=true` 路径 kneighbor 不返边语义,独立 issue)。
- build_concurrency 默认 3 调优 / extract timeout 僵尸线程。
- prompt 注入缓解(GraphRAG 通病,记为已知风险,非本路径引入)。
