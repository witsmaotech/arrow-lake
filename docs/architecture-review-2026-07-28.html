Seven candidates, one unifying root cause. Across RAG, KG, and the Lake facade, the same shape keeps generating bugs: config and knowledge are hand-forwarded as positional args through shallow modules, and the orchestration that wires them is untested — only the extracted pure functions are. The recurring "dead config", "fire-and-forget GC", and "host-vs-container divergence" are not coding slips; they are the predictable output of this shape.

Cross-cutting · the testing shape

Pure functions are tested; the wiring is not. verifier.verify(), query_transform, reranker._parse_score have strong unit suites — but the call sites that connect them (getattr(config,"enable_verification",False), the async fan-out, the iscoroutine bridge, the facade→TaskManager→builder dispatch) have none. A test asserts top_k reaches the retriever but never strategy. Deepening fixes this structurally: the interface becomes the test surface, so behaviour is asserted once, at the seam callers actually cross.

2 · Make the control plane a constructor port

Strong ports & adapters

arrow_lake/__init__.py:100,331 · arrow_lake/api/app.py:163,219,232 · arrow_lake/api/deps.py:18 · arrow_lake/config/system_db.py:29

Before · persistence is a runtime attribute

After · ControlPlane port, two adapters

Problem

Persistence is a hidden runtime property — getattr(self,"_…_store",None) probed in three mixins — so a host Lake() silently degrades and writes datasets the container can't see.

Solution

Inject a ControlPlane port in __init__; NullControlPlane and LibSQLControlPlane are the two adapters that justify the seam.

  • · locality: capability check in one constructor
  • · host-vs-container 404 becomes a loud error
  • · aligns + formalizes v1.9.0 control-plane split
  • · stores become testable as a contract
ADR note. ARCHITECTURE.md §3 codifies "Facade + Mixin" as the house philosophy. This candidate keeps the facade and deepens it — the mixin authoring split stays, but the control-plane becomes an injected port rather than poked-on attributes. Worth reopening §3 to write the port down explicitly.

Problem

GraphRAG.query overrides the base end-to-end and copy-pastes message-build / response / session-save — so one mirror (save_turn) was already missed.

Solution

Base query() becomes a template method with a no-op _augment_context hook; GraphRAG overrides only that hook — ~120 LOC → ~40.

  • · locality: parity bugs structurally impossible
  • · leverage: one message/response path
  • · session + verify run once, for both
  • · interface shrinks to one hook

7 · One async contract on the reranker seam

Strong in-process

arrow_lake/rag/reranker.py:42,180,300,317 · arrow_lake/rag/pipeline.py:257 · arrow_lake/query/hybrid.py:290

Before · contract undefined at the seam

After · async on the base, one rule

Problem

The base declares def rerank but two adapters override as async def; the reconciliation rule lives in each caller — and the second caller already got it wrong.

Solution

Declare async def rerank on the base; sync adapters just return. Delete the per-caller bridge; the latent bug in hybrid.py:290 vanishes for free.

  • · locality: one contract, one place
  • · kills latent silent-Noop in hybrid.py
  • · seam stays — 4 real adapters ✓
  • · lowest effort of the seven

Top recommendation

Tackle #1 first — deepen the RAG retrieval stage

↑ to card

It is the purest deepening in the set: two shallow modules merged behind one small interface, with config resolved once into a RAGQueryPlan instead of hand-forwarded six times. It is self-contained (one subsystem, modest blast radius), it is the cleanest illustration of the interface is the test surface, and it kills the exact bug class — dead strategy, dead reranker, the _score/_rrf_score coupling — that has bitten this repo across v1.9.5 and v1.9.6. The retrieval backends are local-substitutable, so the deepened module tests cleanly against stubs without a live LanceDB.

If you want the bigger structural play instead: candidate #2 (the ControlPlane port) is the root behind the host-vs-container divergence and the recurring "config doesn't reach the module" symptoms — but it touches the whole facade, so it is larger blast radius. If you want the cheapest win: #7 (one async rerank contract) is a one-signature change that deletes a latent silent-Noop in hybrid.py:290.
