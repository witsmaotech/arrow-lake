## 1. 第一批 🟥(高价值低成本)—— 详细实现

### #13 Daft AI 函数替代自建嵌入/推理调度

**现状**: 嵌入/LLM 推理用 Ray Serve + 手写批处理/限流/重试(`arrow_lake/embedding/`、`query/vector.py`、`knowledge_graph/he_extractor.py`)
**目标**: 用 Daft `embed_text()` / `prompt()` / `classify_*()` 替代(内置自动批处理/限流/重试/背压)
**PoC 场景**: `19_knowledge_graph_build` / `06_full_pipeline_papers`(嵌入 + LLM 抽取)

**改动文件**:
- `arrow_lake/embedding/daft_encoder.py`(新)—— Daft `embed_text` 封装,实现 `EmbeddingEncoderProtocol`
- `arrow_lake/query/vector.py` —— 可选用 Daft encoder
- `arrow_lake/knowledge_graph/he_extractor.py` —— LLM 抽取改 Daft `prompt()`
- `docs/cookbook/examples/19_knowledge_graph_build.py` —— PoC 改写

**实施步骤**:
1. 写 `daft_encoder.py`:`class DaftEmbedder(EmbeddingEncoderProtocol)`,内部 `daft.from_pylist(...).with_column("emb", embed_text(col, model=...)).collect()`
2. 测试:`test_daft_encoder.py` —— 验证输出维度/归一化与 bge-m3 一致(mock Daft 或小数据)
3. PoC:改 `19_kg_build` 用 Daft `embed_text()` + `prompt()`(实体抽取)
4. 对比:代码行数、批处理/重试代码删除量、性能、健壮性(注入错误测重试)
5. 推广:若 PoC 验证,逐步替换 `query/`、`ingest/` 的嵌入调用

**测试**: 新增 `tests/unit/embedding/test_daft_encoder.py`;`19_kg_build` cookbook 跑通
**风险**:
- Daft 版本(`daft==0.7.8`,核对 `embed_text` 签名在 0.7.15 stable)
- 模型一致性(bge-m3 via Daft vs 直连 Ollama,可能分词/批差异)
- Daft SQL/AI 函数部分 WIP(看 release notes)
**回滚**: 保留 Ray Serve encoder,Daft 作可选 backend(config 切换)

### #5 Reranker 接入(混合搜索精排)

**现状**: `HybridSearchConfig` 有 RAG reranker 配置,未接 lancedb reranker
**目标**: 混合搜索 RRF 粗排后接 cross-encoder 精排(Cohere/Voyage/Jina/AnswerDotAI)

**改动文件**:
- `arrow_lake/config/search.py` —— `HybridSearchConfig` 加 `reranker_type` / `reranker_model`
- `arrow_lake/query/hybrid.py` —— search 后加 `reranker.rerank(results)` step
- `arrow_lake/_lake_search.py` —— facade 暴露 rerank 选项

**实施步骤**:
1. config 加 reranker 字段(type/model/provider)
2. `hybrid.py` 加 reranker step(可选,none=跳过)
3. 测试:mock reranker(验证调用 + 重排)
4. 端到端:`20_rag_qa_system` 验证精度(对比有/无 reranker)

**测试**: `tests/unit/query/test_hybrid_rerank.py`
**风险**: reranker 依赖(Cohere/Jina 需 API key;本地 cross-encoder 需模型下载)
**回滚**: `reranker_type=none` 默认(向后兼容)
