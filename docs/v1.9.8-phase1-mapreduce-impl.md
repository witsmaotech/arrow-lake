# v1.9.8 阶段 1 实施设计 — map-reduce 图谱构建 + 实体消歧 + 模板 type-pair

> 2026-08-01。本文档是 [v1.9.8-graph-build-mapreduce-plan.md](./v1.9.8-graph-build-mapreduce-plan.md) §八 阶段 1 的**可执行实施设计**。上游规划讲"为什么",本文档讲"怎么做"。

## 一、目标与背景

wuhu(552 页 PDF / ~1250 chunks)图谱构建存在**架构层耦合**根因:

| 粒度路径 | 抽取 | 合并 | 速度 | 质量 | 坑 |
|---------|------|------|------|------|----|
| per-chunk(auto>500 默认) | 并发 extract | ❌ 无 | 快 | 差(同实体 N 顶点、跨 chunk 关系断 → 碎片/孤立) | 质量低 |
| per-dataset | 串行 feed_text | ✅ MERGE_FIELD(只精确名)+ 消歧 | 慢(~2.5h)+ fire-forget 卡死 | 中 | 卡死 |

症结 = **抽取粒度和合并粒度被绑死在一条 path**。

**解法**:新增 `map_reduce` 粒度,解耦抽取与合并:
```
MAP      per-chunk 并发抽取(复用 chunk path 的 extract(),不 insert)
         → 每块独立 ExtractionResult
SHUFFLE  全局精确名去重 + provenance(chunk ownership)合并
REDUCE   entity_resolver 同义消歧(已实现,threshold 0.60)+ type-pair 过滤
INSERT   一次 _insert_kg(canonical + 跨 chunk 关系连通 + 重映射 entity_chunks)
```
并发快 + 全局合并质量 + 绕开 dataset path 卡死。

**阶段 1 不含**:层次化检索(Leiden)、超图(阶段 2/3)。

## 二、已铺路(本会话接续)

- 容器现状:无任何 dataset/graph,wuhu 须从头 ingest;GPU 可用(RTX 3090)。

## 三、关键决策(已确认)

1. **auto 路由不改**:auto 大文件仍→chunk,map_reduce 仅显式 opt-in;wuhu 验证通过后再翻 auto→map_reduce(后续单独小改)。
2. **抽取模型**:wuhu 验证用 `he_extract_llm=qwen-turbo`(快 + json_schema),QA 仍 qwen-plus。仅验证用 compose env,不改默认。
3. **type-pair 仅 project_concept_graph**:其他模板 type 体系不同 → map_reduce 对其他模板跳过过滤。
4. **ingest mime 分流延后**:wuhu 是 PDF 必走 docling,mime 分流通用优化留作后续。

## 四、实施细节

### A. `map_reduce` 粒度路径

**A1. config(`arrow_lake/config/rag.py`)**
- `he_kg_granularity` Literal 加 `"map_reduce"`(L211)。auto 行为不动。
- 新增 `he_kg_type_pair: bool = True`(map_reduce 合并阶段是否做 type-pair 过滤)。

**A2. `builder.py` — 新 map_reduce 分支(`_execute_build` L329-452)**
- granularity 解析 auto 逻辑不动;新增 `elif _gran == "map_reduce":`:
  1. **MAP**:复用 `_process_chunk` 并发骨架,但**只抽取不 insert**——`asyncio.gather` 批量调 `self._extractor.extract(content, chunk_id, doc_type)`,收集 `list[(chunk_id, ExtractionResult)]`。沿用 `semaphore` + `batch_delay`,统计 `extraction_failures`。
  2. **SHUFFLE+REDUCE**:调 `_merge_chunk_results(results)`(见 A3)。
  3. **type-pair 过滤**:`filter_relations_by_type_pair(merged, template_path)`(见 C),`he_kg_type_pair` 关时跳过。
  4. **同义消歧**:`he_entity_resolution != "off"` 时调 `self._extractor.resolve_entities(merged)`,按 `merge_map` 重映射 `entity_chunks`。best-effort。
  5. **INSERT**:一次 `_insert_kg(merged, graph_name, chunk_id_map, entity_chunks=entity_chunks, write_sem=write_sem)`。
- 不动 dataset/chunk path / `_insert_kg` / 共享的 doc/chunk vertex 步骤。

**A3. 新助手 `_merge_chunk_results`(builder.py 静态方法,纯逻辑)**
输入 `list[(chunk_id, ExtractionResult)]` → `(merged_result, entity_chunks)`:
- 实体:按 `normalize_name` 去重,canonical 显示名=首次出现;definition 取同 norm 下最长;type 取首个非空。`entity_chunks[canonical] = [出现该实体的 chunk_id 并集]`。
- 关系:端点经 `normalize_name → canonical` 重写,丢弃自环 + `(norm_src, type, norm_tgt)` 去重。
- 复用 `entity_router.normalize_name`;`dataclasses.replace` 保 properties。不依赖 LLM/网络 → 可纯单测。

**A4. `he_extractor.py`**:构造器 `kg_granularity: str` 已是 str,透传即可;docstring 补 map_reduce。

### B. 实体消歧接入(复用)
map_reduce 分支调 `self._extractor.resolve_entities`;compose 已 auto。threshold 0.60 已校准。

### C. 模板 type-pair 约束

**C1. 新模块 `arrow_lake/knowledge_graph/relation_validator.py`(纯逻辑)**
- 常量 `LEGAL_TYPE_PAIRS: dict[str, frozenset[tuple[str,str]]]` —— 只约束**有向**关系(project_concept_graph 关系说明):
  - 提供: 主体→{软件,硬件,模型,数据,服务,方案,项目}
  - 要求: {项目,软件,硬件,模型,方案}→{要求,指标,资质,标准}
  - 承担: 主体→{条款,服务}
  - 采用: {方案,软件,硬件,模型}→{技术,软件,硬件,模型}
  - 集成: {软件,硬件,模型}×{软件,硬件,模型}(peer)
  - 部署: {软件,模型}→{硬件,软件}
  - 部署于: *→区域
  - 训练: 模型→{数据,模型}
  - 处理: {模型,业务流程,软件}→数据
  - 报价: *→金额
  - 交付于: *→节点
  - 达成: *→{项目,指标}
  - 遵循: *→标准
  - **不约束**(通用):包含/属于/依赖 → 任意 pair 放行。
- `filter_relations_by_type_pair(result, template_path) -> ExtractionResult`:仅 project_concept_graph stem 启用;违规边丢弃 + 统计。`*` 通配任意 type。

**C2. 模板 `project_concept_graph.yaml`**
- `relations.fields[description].required: false → true`。
- guideline.rules_for_relations.zh 加:type 须与 source/target 要素类型匹配。

### D. `/kg/quality` 量化端点

复用 `_cached_graph_snapshot(client, graph_name)`(`_lake_kg.py:200-235`,已 `label="entity"` / `limit=10000`)。

**D1. `_lake_kg.py` 新 `async kg_quality(dataset_name=None) -> dict`**
- 调 `_cached_graph_snapshot`;纯 dict 迭代(模仿 `_build_neighbor_context` 的 id2name + 端点成员判定):

```
relation_type_coverage, truncated=False, relation_type_counts={}, type_distribution={}
```

- dataset 可选 + ACL;`lake.kg_quality(dataset_name=dataset)` → `KGQualityResponse(**data)`;`KGError → _kg_error_to_status`。
