## 1. 背景与目标

### 1.1 问题

v1.8.7 用 ministral-3:3b 对芜湖城市生命线 PDF 跑全量 KG，**1161 chunks 抽出 0 实体**。深入排查（builder/doc_type_router/hyperextract 库）后确认根因是 **doc_type 路由机制的设计缺口**，而非单一 bug：

1. **classifier 误判且无降级**：
   - ingest 没传 `doc_type` 时，classifier 对**整个 PDF 全文**判一次（per-PDF 粒度，`_ingest_files.py:181`），芜湖被判 `industry`，全 1161 chunk 写同一 doc_type。
   - `industry` template 对芜湖建设方案内容抽取质量差（0 实体）。
   - 更糟：`tcm` / `medicine` / `legal` 三类下的 4 个 **hypergraph 类型模板**在稀疏/非典型内容上抛 `IndexError`（`hyperextract/types/hypergraph.py:635` `nodes_lists[0][0]` 空 partial 越界）—— auto 误判到这些模板，he_extractor 直接返回空（v1.8.7 已加 parse 失败 fallback 兜底，但 hypergraph 是"parse 成功但 0 实体"或"崩"两种坏结果）。
2. **模板不透明**：hyper-extract 有 **26 个可用模板**（6 category × 7 种 type），但 Lake facade / CLI / REST 三层**都没有**列出/描述模板的方法。用户无从知道有哪些 doc_type / template 可选，只能被动接受 classifier 的误判，无法显式纠偏。

### 1.2 目标

1. **doc_type 三层路由强化**：保留现有 `explicit > auto > default`，但 **auto（classifier）命中的 doc_type 若路由到 hypergraph 模板，自动降级到 default**（规避已知崩溃），override 层（用户/默认显式配置）不受影响。
2. **hyper-extract 模板全套暴露**：扩展 `TemplateInfo` 携带结构化详情（output fields / 中英文 description / 高风险标记），并在 Lake facade / CLI / REST 三层对齐 `list-doc-types` / `list-templates` / `describe-template`，让用户能查可选模板、在 ingest 时显式设置正确 doc_type，绕开 classifier 误判。

### 1.3 非目标

- `industry` template 0 实体的**并发根因**（单 chunk 串行有实体、全量 semaphore=10 并发 0）不在本次范围 —— hypergraph 降级 + 显式 doc_type 已能让用户绕开；并发单独成一个后续项。
- 不改 hyperextract 第三方库（`hypergraph.py:635` 的空索引 bug 上游可 PR，但 arrow_lake 用降级 + fallback 兜底）。

## 3. 设计基石（v1.8.7 实测事实）

这些实测结论决定方案走向：

1. **三层路由逻辑已存在**（`doc_type_router.py:291-303` `resolve_with_source`）：override（`he_doc_type_templates`）> gallery match > default（`he_default_template`）。本次只在 gallery match 后加 hypergraph 降级判断。
2. **explicit 优先已成立**：ingest 传 `doc_type=` 时直接用（`_ingest_files.py:177`），classifier 只在没传时构造（`_lake_ingest.py:407`）+ 调用（`_ingest_files.py:181`）。无需改优先级，只需文档强化 + 暴露让用户知道选什么。
3. **classifier 粒度 = per-PDF / per-doc**（非 per-chunk）：ingest 时 `parsed.text`（整 PDF）判一次（`_ingest_files.py:181`）；kg_build 时拼前 1500 字符判一次广播全 chunk（`builder.py:411`）。这是"全文档同一 doc_type"的根因 —— 误判会扩散到全 chunk。
4. **可复用设施齐全**：
   - `TemplateGallery.build()`（`doc_type_router.py:132`）已扫描 26 个可用模板（跳过 7 个 `base_*`），`TemplateInfo`（`:84`）已有 path/category/name/type/tags/description。
   - `DOC_TYPE_ALIASES`（`:42`）/ `DOC_TYPE_DESCRIPTIONS`（`:315`）/ `KNOWN_DOC_TYPES`（`:331`）/ `normalize_doc_type` / `validate_taxonomy`（`:334`）—— doc_type 的 taxonomy 与一致性校验已就绪。
5. **命名约定清晰**：facade `async def kg_<verb>(...)`（`_lake_kg.py`）；CLI click `@kg_group.command("<kebab>")`（`cli/kg.py`）；REST `@router.get/post("/<path>", response_model=KG*Response, ...)`（`api/routers/knowledge_graph.py`）。
6. **4 个 hypergraph 模板（崩溃源）**：`tcm/formula_composition`、`tcm/syndrome_reasoning`、`legal/contract_obligation`、`medicine/treatment_map`（`general/base_hypergraph` 被 gallery 跳过）。

## 4. 设计详情

### 4.1 改动 1 — auto 命中 hypergraph 自动降级（`doc_type_router.py`）

`resolve_with_source` 的 gallery 命中分支后，检查 `TemplateInfo.type`，hypergraph 则降级：

```python
# doc_type_router.py:resolve_with_source — gallery 分支
hit = self._gallery.match(nt)
if hit is not None:
    if hit.type == "hypergraph":
        # hypergraph templates crash (IndexError) or yield 0 on sparse/atypical
        # content (hyperextract/types/hypergraph.py:635). auto-routed doc_types
        # must not land here — degrade to default. Explicit overrides are NOT
        # affected (operator can still force hypergraph via he_doc_type_templates).
        logger.info(
            "doc_type %r auto-matched hypergraph template %s; degrading to default %s",
            nt, hit.path, self._default,
        )
        return self._default, "degraded"
    return hit.path, "gallery"
```

**只对 auto（gallery match）降级**；override（用户显式配）+ default 不变。source 多一个 `"degraded"` 值供可观测性。

### 4.2 改动 2 — `TemplateInfo` 扩展详情（`doc_type_router.py:84`）

```python
@dataclass(frozen=True)
class TemplateInfo:
    path: str
    category: str
    name: str
    type: str
    tags: tuple[str, ...]
    description: str              # 现有：拍平 zh+en（关键词匹配用，保留）
    description_zh: str           # 新增
    description_en: str           # 新增
    entity_fields: tuple[str, ...]    # 新增：output.entities.fields[].name
    relation_fields: tuple[str, ...]  # 新增：output.relations.fields[].name（无则空）
    is_high_risk: bool            # 新增：type == "hypergraph"（供 UI/CLI 警示）
```

`TemplateGallery.build()` 解析 yaml 时填这些字段（yaml 结构：`description.{zh,en}`、`output.entities.fields[].name`、`output.relations.fields[].name`）。

### 4.3 改动 3 — Lake facade（`_lake_kg.py`）

新增三个 async 方法（复用 `_shared_gallery()` + `DOC_TYPE_DESCRIPTIONS` + `DOC_TYPE_ALIASES`）：

- `async kg_list_doc_types() -> list[dict]`：10 个 canonical doc_type —— `[{doc_type, description, aliases, default_template}]`。
- `async kg_list_templates(category: str | None = None) -> list[TemplateInfo]`：26 个模板（可选 category 过滤）。
- `async kg_describe_template(path: str) -> dict`：单个模板完整详情（含 entity/relation fields、is_high_risk 警示）；不存在抛 `KGError`。

### 4.4 改动 4 — CLI（`cli/kg.py`）

新增三个命令（注册到 `kg_group`，click kebab 对齐）：

- `kg list-doc-types`：表格打印 10 个 doc_type + 说明 + 默认模板。
- `kg list-templates [--category CATEGORY]`：表格打印模板（path / type / tags / desc_zh），hypergraph 行标 ⚠。
- `kg describe-template PATH`：完整详情（entity/relation fields、guideline 摘要、risk）。

### 4.5 改动 5 — REST（`api/routers/knowledge_graph.py` + `api/models/knowledge_graph.py`）

新增三个 GET 端点（`Viewer` 角色即可，只读）：

- `GET /templates?category=` → `KGTemplatesResponse`
- `GET /templates/{path}` → `KGTemplateDetailResponse`（path 含 `/`，注意路由匹配；不存在 404）

响应模型加到 `api/models/knowledge_graph.py`（Pydantic，对齐现有 `KG*Response` 命名）。

## 7. 后续（v1.8.9 候选）

> **演进注记（v1.8.8 第二阶段，2026-07）**：本节第 1、2 条已由 `v1.8.8-kg-per-dataset-ka-plan.md`（per-dataset KA + feed_text + 落盘）承接。该方案把 hyper-extract 从"单 chunk 抽取器"改为"per-dataset 一个 KA"，激活跨 chunk LLM.BALANCED 合并，从根上消除 fresh KA per chunk 的并发状态污染；doc_type 粒度正式定为 **per-dataset**（整 dataset 一个 template、一个 KA），误判扩散由跨 chunk 合并缓解。

- ✅ **并发根因**〔由 `v1.8.8-kg-per-dataset-ka-plan.md` 解决〕：`industry` template 单 chunk 串行有实体、全量 `BUILD_CONCURRENCY=10` 并发 0。根因是 fresh KA per chunk 的并发状态污染 —— per-dataset 单 KA + feed_text 不再创建多个 KA，并发问题随之消失。
- **per-chunk doc_type 推断**〔部分缓解〕：当前 per-PDF/per-doc 粒度，混合文档（芜湖含目录+正文+附录）可能需 per-chunk。per-dataset KA 方案下 doc_type 为 per-dataset（整 dataset 一个 template），误判扩散由 LLM.BALANCED 跨 chunk 合并缓解；但混合文档的 per-chunk 精细化粒度仍为长期项（代价是每 chunk 多一次 LLM）。
- **hypergraph 库 bug 上游 PR**：`hyperextract/types/hypergraph.py:635` 空 `nodes_lists[0][0]` 越界（本方案不改上游，由 §4.1 的 auto 降级 + per-dataset KA 单 template 不切模板 双重兜底）。
