# Arrow Lake v1.6.1 — Performance & Bottleneck Fix Plan

## Context

v1.6.0 测试中发现 22 个同步阻塞调用点，其中 `kg_build` (100+ 分钟)、`rag_extract` (60s+)、`ingest_*` (600s) 会阻塞整个 uvicorn event loop，导致全站不可用。`export` 已有正确的 fire-and-forget 模式（`asyncio.create_task` + `TaskManager` + 轮询），本版本将此模式推广到所有重量级操作。

## Phase P0: CRITICAL — 消除 API 阻塞

### P0-1: 泛化 TaskManager

**文件**: `arrow_lake/api/tasks.py`

- `ExportTask` → `BackgroundTask`（保留 `ExportTask` 别名兼容）
- 新增 `operation_type: str` 字段（`"export"|"ingest"|"backup"|"kg_build"|"quality_filter"|"vector_index"`）
- 新增 `progress_detail: dict | None` 用于操作专属元数据
- 新增 `run_background(task_id, func, *args, progress_callback=None, **kwargs)` 通用方法
- TTL 从 3600 → 7200（backup 可超过 1 小时）

### P0-2: kg_build 异步化

**文件**: `arrow_lake/knowledge_graph/builder.py`

```
build() 拆分为:
  prepare_build(dataset_name, table) → task_id  # 立即返回
  execute_build(task_id)                        # 后台 asyncio.create_task
```

**文件**: `arrow_lake/_lake_kg.py`

```python
async def kg_build(self, dataset_name):
    # ... 加载数据 ...
    task_id = builder.prepare_build(dataset_name, table)
    asyncio.create_task(builder.execute_build(task_id))
    return task_id  # <1 秒返回
```

**文件**: `arrow_lake/api/routers/knowledge_graph.py` — 无结构变更，`await` 即返回

**配置调优** (`arrow_lake/config/rag.py`):
- `build_concurrency`: 1 → **3**
- `build_batch_delay`: 3.0 → **0.5**

**效果**: 1000 行耗时从 100+ 分钟降至 ~30 分钟（后台），API 不再阻塞

### P0-3: 异步 Ingest 端点

**文件**: `arrow_lake/api/routers/datasets.py`

为 10+ 个 ingest 端点各加一个 `/async` 变体：
- `POST /{name}/ingest/async`
- `POST /{name}/ingest/http/async`
- `POST /{name}/ingest/documents/async`
- `POST /{name}/ingest/images/async`
- `POST /{name}/ingest/videos/async`
- `POST /{name}/ingest/mixed/async`

每个返回 `{"task_id": "...", "status": "pending"}` + HTTP 202
原有同步端点保持不变（小数据 <30s 场景）

### P0-4: 异步 Backup/Restore

**文件**: `arrow_lake/api/routers/backup.py`

- `POST /api/v1/backup/create/async` → fire-and-forget
- `POST /api/v1/backup/restore/async` → fire-and-forget
- 原有无超时的同步端点标记 deprecated

## Phase P1: HIGH — 降低线程池压力

### P1-1: RAG Extract 线程池隔离

**文件**: `arrow_lake/api/deps.py` + `arrow_lake/rag/pipeline.py`

- 创建专用 `_llm_executor = ThreadPoolExecutor(max_workers=4, prefix="llm_worker")`
- `rag_extract` 使用专用池而非默认池
- 60s 超时 + 504 响应

### P1-2: 异步 Quality 端点

**文件**: `arrow_lake/api/routers/quality.py`

- `POST /{name}/quality/filter/async`
- `POST /{name}/quality/dedup/async`
- 同步的 `quality_report` / `quality_profile` 保持不变（<30s）

### P1-3: 异步 Index 创建

**文件**: `arrow_lake/api/routers/embedding.py`

- `POST /{name}/index/vector/async`
- `POST /{name}/index/fts/async`
- `embed_text` / `embed_image` 保持同步（请求/响应模式，120s 合理）
