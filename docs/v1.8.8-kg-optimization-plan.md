## 3. 特性详述

### #3 type 后处理过滤 ⭐ 阶段1首选
- **现状**：LLM 对 ddd 模板 type 枚举有 ~5% 残留非枚举值（"概念"等），P2.1 未能 100% 强制。
- **方案**：`he_extractor._to_extraction_result` 在 entity_type 赋值后，若 type ∉ 模板枚举则归"实体"（最通用 fallback）。从节点/模板拿合法枚举集。
- **验收**：HugeGraph entity.type 100% ∈ 枚举，"概念"残留 0%。

### #10 chunk/performance 调优
- **现状**：chunk_size=2048 / chunk_overlap=256 / max_workers=10 默认（hyper-extract BaseAutoType 默认）。
- **方案**：`HugeGraphConfig` 暴露 `he_chunk_size` / `he_chunk_overlap` / `he_max_workers`，按文档规模调（大文档降 max_workers 避限流，小文档提 chunk_size 减调用）。
- **验收**：config 可调；大文档吞吐提升、无 LLM 限流。

### #8 模板 validator 校验
- **现状**：项目模板手写，未系统校验。
- **方案**：套用 hyper-extract `he-template-validator` 4 层 checklist（通用/Graph/Hypergraph/Temporal-Spatial）+ auto-fix（relation_type→type、多语言纯度、字段数≤5）。可写脚本扫 `arrow_lake/knowledge_graph/templates/*.yaml`。
- **验收**：项目模板过 4 层校验，CI 可集成。

### #1 TemplateTypeSelector ⭐ 阶段2核心
- **现状**：doc_type 路由只选 graph 模板（concept_graph）。memory `project_template_type_selector` 已 brainstorm 方向B（待实现）。
- **方案**：新模块 `template_type_selector.py`，6 类注册表（graph/temporal_graph/hypergraph/list/set/model）。推荐规则：时序信号（事件/工序/传记）→temporal_graph；默认→graph；hypergraph 仅显式+警告（复用 DocTypeRouter degraded）。入口：CLI `--template-type` / API `template_type=`。走模板路径（method 路径 broken，见风险）。
- **验收**：用户可选 Auto-Type；时序文档自动用 temporal_graph；hypergraph 仍降级保护。

### #2 RAG 查询暴露
- **现状**：arrow_lake 入 HugeGraph 后查询走 HugeGraph REST。hyper-extract KA 的 `search()`/`chat()`（语义检索/RAG）**待确认是否暴露**。
- **方案**：先确认 he_extractor/Lake 是否暴露 KA search/chat。若否，加 facade `kg_search(dataset, query)` / `kg_chat(dataset, query)`（load KA → build_index → search/chat）。definition 语义检索远强于 HugeGraph 关键词。
- **验收**：API 可语义检索/RAG 问答；对比 HugeGraph 关键词查询召回更准。
- **前置**：确认 arrow_lake 现状（是否已有 KA 查询路径）。

### #7 增量 rebuild 调度
- **现状**：per-dataset KA feed_text 后，index 是否 rebuild 待确认。
- **方案**：hyper-extract 最佳实践周 feed + 月 rebuild_index。feed 后触发 build_index（或批量 feed 完统一 rebuild）。config `he_rebuild_interval`。
- **验收**：feed 后 search/chat 反映新内容；大规模 KA 检索质量不漂移。

### #5 Obsidian 导出
- **现状**：未用。hyper-extract `ka.export_obsidian()` 图→Markdown 笔记 + `[[wikilink]]`。
- **方案**：facade `kg_export_obsidian(dataset, out_dir)` + CLI/REST。仅 Graph 系 KA 支持（Record 系无关系）。
- **验收**：per-dataset KA 一键导出 Obsidian vault，可在 Obsidian 图谱视图漫游。

### #4 method 等价模板
- **现状**：method 路径 broken（`Template.create("method/xxx")` 报 node_schema 错，memory `issue_hyperextract_method_path_broken`）。atom（时序事实+证据+置信度）等能力未用。
- **方案**：method 能力走等价模板（atom≈temporal_graph、itext2kg≈graph、hyper_rag≈hypergraph）。依赖 #1 TemplateTypeSelector 暴露 temporal_graph 后，atom 的时序事实能力可用。
- **验收**：时序文档抽 time + 证据归因（atom 特性）。
- **风险**：依赖上游 method 路径修复，或永久走等价模板。

### #9 多领域模板扩展
- **现状**：项目模板系统已建（`arrow_lake/knowledge_graph/templates/`），只有 ddd_concept_graph。
- **方案**：按业务领域加 `medical_concept_graph.yaml` / `legal_concept_graph.yaml` / `finance_concept_graph.yaml`，各自 type/relation 枚举 + tags。gallery 自动纳入。
- **验收**：doc_type=medical→medical 模板；多领域 KG type 规范。

### #11 KA 版本管理
- **现状**：per-dataset KA 单版本（dump 覆盖）。
- **方案**：hyper-extract knowledge-base 教程模式：版本目录（`ka/{ds}/v{ts}/`）+ `current` 软链 + backup/restore/rollback。rebuild 不丢历史。
- **验收**：KA 可 rollback 到历史版本；rebuild 失败可恢复。

### #12 embed 维度权衡
- **现状**：ollama qwen3-embedding:4b（2560 维）。
- **方案**：评估 vs 百炼 text-embedding-v4（1024 维，与 Lance num_sub_vectors=32 对齐，更轻）。benchmark 检索质量 + 速度 + cost。
- **验收**：出评估报告；选最优 embed 配置。

## 5. 风险与注意事项

| 风险 | 影响 | 缓解 |
|---|---|---|
| method 路径 broken（上游 hyper-extract）| #4 atom 等能力受限 | 走等价模板；可提上游 PR |
| hypergraph 模板 IndexError（稀疏内容崩）| #1 选 hypergraph 风险 | DocTypeRouter 自动降级（已有）；project 模板标记 high_risk |
| LLM type/relation 遵守度 | #3 残留 | 后处理过滤兜底（#3）|
| 项目模板 .venv vs 项目持久 | 模板丢失 | 已迁项目系统（05d17c8）；新模板都进 `templates/` |
| 重建验证 cost | 每特性重跑 10min+ LLM | 批量改完统一重跑；小改用静态验证 |

## 6. 实施节奏建议

- 每阶段一个批次：实施 → 静态验证 → 重跑端到端 → commit → 更新本文档状态。
- 阶段内特性可并行（独立）；跨阶段有依赖（#4 依赖 #1）。
- 每特性完成后在本文档标 ✅ + commit hash。
