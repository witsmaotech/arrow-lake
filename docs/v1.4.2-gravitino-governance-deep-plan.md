# Arrow Lake v1.4.2 — Gravitino 深度治理闭环实施方案

> 聚焦：**策略执行引擎 + 标签驱动访问控制 + 统计优化 + 模型集成 + 血缘闭环 + 联邦查询**
>
> 日期：2026-05-22
>
> 基线：v1.4.1 (Gravitino 集成已完成，但仅存储元数据未形成治理闭环)
>
> 问题诊断：v1.4.1 的 Gravitino 集成 90% 是装饰性的——元数据写入后无人消费，策略不执行，标签不驱动控制，统计不被查询规划器使用。

## P0 — 策略执行引擎

### 保留策略执行

**现状**：`create_retention_policy()` 存 `retention.days` 到 Gravitino，无代码读取并清理。

**方案**：

新增 `arrow_lake/quality/retention_enforcer.py`：

```python
class RetentionEnforcer:
    """后台线程：周期性读取保留策略并清理过期 Lance 版本/行。"""

    def __init__(self, config, storage_manager, interval=3600): ...

    def enforce(self) -> int:
        """执行一轮保留策略，返回清理的版本数。"""
        # 1. 从 Gravitino 读取所有 retention 类型策略
        # 2. 对每个应用了策略的表，获取 retention.days
        # 3. Lance 版本清理: lance.LanceDataset.cleanup_old_versions(older_than=timedelta(days=N))
        # 4. 行级保留: DELETE FROM dataset WHERE created_at < NOW() - INTERVAL 'N days'
```

**修改文件**：
- `arrow_lake/quality/retention_enforcer.py` (新增)
- `arrow_lake/ingest/storage.py` — 添加 `cleanup_versions(dataset_name, older_than)` 方法
- `arrow_lake/api/app.py` — lifespan 中启动/停止 RetentionEnforcer
- `arrow_lake/api/routers/gravitino.py` — 添加 `POST /metadata/policies/enforce` 手动触发端点
- `arrow_lake/config/gravitino.py` — 添加 `retention_enforce_interval_seconds: int = 3600`

**风险**：Lance 版本清理可能影响正在进行的查询。缓解：dry-run 检查 + 执行前日志。

### 脱敏策略执行

**现状**：`create_masking_policy()` 存 `masking.columns`，无代码转换查询结果。

**方案**：

新增 `arrow_lake/quality/masking_engine.py`：

```python
class MaskingEngine:
    """查询时同步脱敏：根据 Gravitino 策略转换 PyArrow 列。"""

    SUPPORTED_FUNCTIONS = {
        "redact": lambda col: pc.replace_substring(col, "****"),   # 全遮盖
        "hash":   lambda col: pc.hash(col, "sha256"),             # SHA-256
        "partial": lambda col: keep_first_last_2(col),            # 保留首尾2字符
        "nullify": lambda col: pc.if_else(pc.is_valid(col), None, None),  # 置空
    }

    def apply_masking(self, table: pa.Table, dataset: str, role: str) -> pa.Table:
        """对 PyArrow Table 应用脱敏，返回转换后的表。"""
        # 1. 从缓存获取该表的脱敏策略
        # 2. 根据 role 决定是否脱敏（admin 跳过）
        # 3. 对指定列应用 masking function
```

**集成点**：`arrow_lake/api/rbac.py` 的 `apply_table_filter()` 中，列过滤后、返回前调用 `MaskingEngine.apply_masking()`。

**缓存层**：`_policy_cache: dict[str, tuple[list[MaskRule], float]]`，TTL 60 秒。

**修改文件**：
- `arrow_lake/quality/masking_engine.py` (新增)
- `arrow_lake/api/rbac.py` — `apply_table_filter()` 调用 MaskingEngine
- `arrow_lake/api/app.py` — 实例化 MaskingEngine 存 app.state
- `arrow_lake/config/gravitino.py` — 添加 `masking_policy_cache_ttl_seconds: int = 60`

## P1 — 标签驱动的访问控制

**现状**：`GravitinoTagService` 创建标签关联到表/列，但 `PermissionChecker` 完全不知道这些标签。

**方案**：

新增 `arrow_lake/catalog/tag_acl_resolver.py`：

```python
class TagAwareACLResolver:
    """将 Gravitino 标签解析为 DatasetACL 条目，填充 PermissionChecker。"""

    # 可配置的标签→角色映射
    DEFAULT_RULES = {
        "pii":       {"visible_to": ["admin"]},
        "sensitive": {"visible_to": ["admin", "editor"]},
        "financial": {"visible_to": ["admin"]},
    }

    def sync_tags_to_acls(self) -> int:
        """读取 Gravitino 标签 → 生成 ACL → 注入 PermissionChecker。"""
        # 1. 对每个表，查询列级标签
        # 2. 根据规则映射：pii 标记的列对非 admin 不可见
        # 3. 调用 PermissionChecker.set_acl(dataset, role, visible_columns, row_filter)
```

**设计优势**：标签→ACL 映射周期性执行（与同步调度器同周期），不是每查询一次。`apply_table_filter()` 无需修改——从 `_row_col_acls` 读取，而 `_row_col_acls` 现在由标签填充。

**修改文件**：
- `arrow_lake/catalog/tag_acl_resolver.py` (新增)
- `arrow_lake/quality/gravitino_tags.py` — 添加 `list_column_tags(table) -> dict[str, list[str]]`
- `arrow_lake/catalog/gravitino_sync.py` — 周期调用 TagAwareACLResolver
- `arrow_lake/config/gravitino.py` — 添加 `tag_access_rules: dict`

**风险**：低。附加性设计，标签解析失败不影响手动配置的 ACL。

## P2 — 数据血缘闭环

**现状**：`_notify_gravitino_version()` 仅设置 `lance.latest_version` 属性。

**方案**：通过 Gravitino 表属性建模血缘（Gravitino 1.2.1 无原生血缘 API）。

丰富 `_notify_gravitino_version()`：

```python
properties = {
    "lineage.sources": json.dumps(list(event.source_datasets)),
    "lineage.operation": event.operation,
    "lineage.transform_type": event.transform_type,
    "lineage.timestamp": event.timestamp,
}
```

**三种机制**：
1. **表属性血缘**：将上下游数据集关系写入目标表属性，Gravitino Web UI 可浏览
2. **标签发现**：自动打标签 `lineage:raw`、`lineage:derived`、`lineage:aggregated`
3. **双向同步**：本地 LineageStore ↔ Gravitino 属性双向同步

**修改文件**：
- `arrow_lake/catalog/lineage.py` — 丰富 `_notify_gravitino_version()`
- `arrow_lake/catalog/gravitino_sync.py` — 添加 `_sync_lineage_to_gravitino()` / `_sync_lineage_from_gravitino()`
- `arrow_lake/api/routers/gravitino.py` — 添加 `GET /metadata/lineage/{name}` 端点

## P3 — 统计驱动查询优化

**现状**：统计信息采集后存储在 Gravitino 属性中，DuckDB 查询规划器完全不知道。

**方案**：不是注入 DuckDB 统计（DuckDB 无此 API），而是 Arrow Lake 级别优化决策：

1. **查询路由**：`stats.row_count > 1M` 时自动路由到 DuckDB OLAP 端点（而非 Daft 内存收集）
2. **Limit 优化**：已知行数时自动添加 LIMIT 防止全表扫描
3. **列裁剪**：`SELECT *` 时根据列类型只投影相关列

新增 `arrow_lake/query/stats_injector.py`：

```python
class StatsInjector:
    """从 Gravitino 读取统计信息，提供查询优化提示。"""

    def get_hints(self, dataset: str) -> QueryHints:
        """返回行数、列数等统计提示。"""
        stats = self._cache.get(dataset)
        if stats is None:
            stats = self._fetch_from_gravitino(dataset)
            self._cache[dataset] = (stats, time.time())
        return QueryHints(
            estimated_rows=stats.get("row_count", 0),
            column_count=stats.get("column_count", 0),
            size_mb=stats.get("size_mb", 0),
        )
```

**修改文件**：
- `arrow_lake/query/stats_injector.py` (新增)
- `arrow_lake/query/olap.py` — 添加统计感知的查询路由
- `arrow_lake/config/gravitino.py` — 添加 `stats_cache_ttl_seconds: int = 300`

## P4 — 模型注册中心集成

**现状**：`GravitinoModelRegistry` 注册模型/版本，但 `embed/` 和 `rag/` 模块从配置读取模型名，不查询 Gravitino。

**方案**：

新增 `arrow_lake/embed/registry_resolver.py`：

```python
class RegistryModelResolver:
    """从 Gravitino 模型注册中心解析模型路径/配置。"""

    def resolve_model_path(self, model_name: str) -> str | None:
        """获取 production 版本的 URI 作为模型路径。"""
        version = self._registry.get_production_version(model_name)
        return version.uri if version else None

    def resolve_model_config(self, model_name: str) -> dict | None:
        """获取模型版本的 properties（api_base, model 等）。"""
        version = self._registry.get_production_version(model_name)
        return dict(version.properties) if version else None
```

**集成点**：
- `embed/encoder.py` 的 `LocalEmbeddingEncoder._load_model()` — 优先从 Resolver 获取模型路径
- `rag/provider.py` 的 `create_llm_provider()` — 从 Resolver 覆盖 model/api_base
- 使用 TTL 缓存（默认 600 秒），过期后重新查询 Gravitino

**热切换**：模型路径缓存过期后自动从 Gravitino 获取新版本，无需重启。

**修改文件**：
- `arrow_lake/embed/registry_resolver.py` (新增)
- `arrow_lake/embed/encoder.py` — 接受可选 model_resolver
- `arrow_lake/rag/provider.py` — 接受可选 model_registry

## P5 — 联邦查询增强

**现状**：`read_gravitino_table()` 仅拼接路径字符串，不查询 Gravitino 元数据。

**方案**：新增 `arrow_lake/query/federated_engine.py`：

```python
class FederatedQueryEngine:
    """元数据驱动的跨 Catalog 联邦查询。"""

    def resolve_table(self, fqn: str) -> TableResolution:
        """查询 Gravitino 获取表元数据（格式、位置、Schema）。"""
        # GET /api/metalakes/{m}/catalogs/{c}/schemas/{s}/tables/{t}

    def load_dataset(self, fqn: str) -> daft.DataFrame:
        """根据元数据格式选择读取方式。"""
        # lance → daft.read_lance(location)
        # parquet → daft.read_parquet(location)
        # csv → daft.read_csv(location)

    def cross_catalog_query(self, queries: list[tuple[str, str]], join_sql: str) -> pa.Table:
        """跨 Catalog 联邦 JOIN：加载到 DuckDB 执行 SQL。"""
```

**修改文件**：
- `arrow_lake/query/federated_engine.py` (新增)
- `arrow_lake/query/daft_api.py` — 替换 `read_gravitino_table()` 为元数据驱动版本
- `arrow_lake/api/routers/query.py` — 添加 `POST /api/v1/query/federated` 端点
- `arrow_lake/config/gravitino.py` — 添加 `federated_query_max_rows: int = 100000`

**风险**：中等。跨 Catalog JOIN 需要物化到 DuckDB 内存，强制行数限制。
