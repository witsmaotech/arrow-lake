知识图谱与 GraphRAG

Arrow Lake 内置 KG 子系统，通过 LLM 抽取实体 / 关系写入 HugeGraph；hugegraph.enabled=True 时 RAG 自动升级为 GraphRAG，融合图谱邻居上下文提升多跳推理。

难度 · 高级耗时 · 30 分钟依赖 · HugeGraph + LLM

知识图谱是能力层直达持久化的唯一旁路。每个数据集可拥有独立的隔离 KG（动态图 kg_{ds}），抽取出的实体 / 关系既能独立查询，也能在 RAG 中作为邻居上下文增强推理。

5踩坑提示

MERGE_FIELD / 增量 / 领域模板

大 dataset 勿用 BALANCED 合并（LLM 合并爆炸 OOM），改 MERGE_FIELD（非 LLM，稳定）；kg_build 支持增量（fed_chunks sidecar，只喂新 chunk，KG 按 PRIMARY_KEY 幂等 upsert，CLI 加 --incremental）；项目方案书等结构化场景用 project_concept_graph 领域模板（22 类型 + 14 关系，质量优于通用 entity_graph）。

HugeGraph 认证

HugeGraphConfig.username/password 默认空=不认证；生产 / 动态建图集群必开 auth（部署态 admin / pa，env HUGEGRAPH_PASSWORD），否则 per-dataset 建图失败。

Gremlin 遍历源绑定缺失

动态图下 g.V() 可能报 MissingProperty（全局遍历源未绑定）；排查顶点 / 边优先走 REST（GET /graphs/{name}/graph/vertices?limit=N）或项目 kg_stats，勿用裸 gremlin。

per-dataset 隔离

standalone rocksdb 只单图；要每文档独立 KG 须用 PD 模式（hg-pd / hg-store / hg-server），按 PD→Store→Server 顺序启动；drop/clear 图后须 restart hg-server 刷新内存 schema 缓存。

LLM 模型选择

百炼走 qwen-turbo（支持 json_schema，快 + 非思考）；thinking 模型（qwen3.7-max / glm-5.2）抽取极慢；KG 抽取与 QA LLM 可拆分（he_extract_llm / he_qa_llm）。

CLI 盲区

kg build CLI 无 --doc-type，须摄入期设置；Gremlin 写操作（addV/addE）被 REST 端点拦截，仅 Python SDK 直调 kg_query() 执行。
