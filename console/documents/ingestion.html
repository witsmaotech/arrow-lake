第 02 章 · 摄取

数据摄取指南

本地文件、HTTP / SQL / Kafka、图像 / 视频 / PDF 文档与 PyArrow Table——统一 Lake 接口写入 Lance，覆盖分块、嵌入、去重与死信队列。

难度 · 初级耗时 · 15 分钟依赖 · 可选 sqlalchemy / kafka / s3

摄取是数据进入湖仓的唯一入口。多源统一接口把不同来源数据收敛到一致的 IngestionReport（含 total_rows / total_files / sources），下游检索、分析、RAG 全部基于此。

1核心概念

能力说明
多源统一接口ingest / ingest_http / ingest_sql / ingest_kafka / ingest_iceberg / ingest_deltalake，统一返回 IngestionReport
结构化格式CSV / JSON / JSONL / Parquet；CSV/Parquet 由 Daft 解析，首文件决定 schema
多模态摄取ingest_images（缩略图+EXIF）/ ingest_videos（关键帧）/ ingest_mixed（统一表）

分块策略page / paragraph / recursive / semchunk / chonkie_token / chonkie_semantic / chonkie_sdpm

死信队列 DLQIngestDeadLetterQueue 记录失败文件，状态 pending → retrying → resolved | permanent

SDK ≠ REST 建索引

SDK lake.ingest_documents() 只分块 + 存储，不建检索索引；REST POST /ingest/documents 走 ingest_documents_and_index（parse → store → embed → FTS → vector 一条龙），行数 ≥256 自动建 IVF_PQ，<256 跳过并告警（vector 仍可暴力搜索）。SDK 用户若要检索，摄入后需手动 lake.create_vector_index() + lake.create_fts_index()。

以图搜图（v1.9.2）

图像摄入后，用 POST /embed/image 把查询图编码为 CLIP/SigLIP 向量，再 POST /datasets/{name}/search/vector 检索相似图像；文搜图用 SDK lake.encode_text_clip()。图像列写入 image_data/image_thumbnail/image_preview 及 EXIF 元数据。

5踩坑提示

Schema 锁定

多文件 / 追加摄取时，第一个文件决定 dataset schema，后续文件列须为子集或类型兼容，否则抛 StorageError。

非线程安全

Ingestor 非线程安全；并发写不同 dataset 要建独立实例，并发写同一 dataset 需外部同步。

依赖按需装

SQL 需 sqlalchemy + 驱动（psycopg2 / pymysql / pyodbc）；Kafka 需 confluent-kafka；Iceberg 需 pyiceberg[pyarrow,s3fs]；Delta 需 deltalake；S3 URI 须经 StorageConfig 或环境变量配凭证。ocr_endpoint 默认 http://localhost:8002，切 turbo_ocr 须保证服务可达。

安全默认

ingest_http 内置 SSRF 防护（阻止私有 IP）、仅 http/https、对 429/5xx 指数退避；dataset 名须匹配 ^[a-zA-Z_][a-zA-Z0-9_-]*$。
